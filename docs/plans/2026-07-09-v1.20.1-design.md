# v1.20.1 Design: set_access_vlan + port_binding 写命令

**Date**: 2026-07-09
**Author**: Claude (minimax-m3) with user input
**Status**: Design Draft (pending user sign-off)
**Parent Milestone**: v1.19 follow-up (corresponds to FUTURE-01 + FUTURE-03 partial)

---

## 1. Background & Motivation

v1.19 落地了 3 厂商 × 5 操作的端口写命令 MVP（shutdown / undo_shutdown / description / dot1x enable / dot1x disable）。`v1.19-REQUIREMENTS.md` 的 Future Items 中列出了：

- **FUTURE-01**: 端口绑定（port-security / sticky MAC / 最大 MAC 数）多厂商命令
- **FUTURE-03**: VLAN 切换（access / trunk / hybrid）

本期 **v1.20.1** 选择 2 个最小可用功能组合：

1. **`set_access_vlan`** — 修改端口的 access VLAN（VLAN ID 1-4094）
2. **`port_binding`** — IP+MAC+Port 静态绑定（基于 `user-bind` / `port-security binding`）

### 1.1 关键修正（v1.19 FUTURE-01 的语义纠错）

原 FUTURE-01 描述把"端口绑定"和"port-security MAC 数量限制"混为一谈。**经过用户实际设备输出验证**（Huawei S8700 + Ruijie RS8607E），这两者是**不同的功能**：

| 实际功能 | Huawei S8700 | Ruijie RS8607E |
|----------|--------------|----------------|
| **MAC 数量限制 (max-mac)** | `dis port-security` 的 `MaxSecureAddr` 列 | `switchport port-security maximum N` |
| **IP+MAC+Port 静态绑定** | `dis user-bind static all` 的 IP+Interface 表 | `sh port-security binding` 的 IP+Port 表 |
| **绑定命令** | `user-bind static ip-address <IP> [mac-address <MAC>] interface <iface>` | `switchport port-security binding <IP>` |

**v1.20.1 仅做"IP+MAC+Port 静态绑定"**；max-mac / sticky / enable 留到 v1.20.x+ 单独迭代。

## 2. Scope

### 2.1 In Scope (v1.20.1)

| Action | 输入字段 | 输出命令（3 厂商） |
|--------|----------|---------------------|
| `ActionSetAccessVLAN` | `vlanId: int (1-4094)` | 见 §3 |
| `ActionPortBinding` | `op: "add"\|"remove"`, `ipAddress: string`, `macAddress: string?` | 见 §3 |

### 2.2 Out of Scope (deferred to v1.20.x+)

- **FUTURE-01 剩余部分**: port-security enable / disable / max-mac-num / sticky MAC
- **FUTURE-03 剩余部分**: trunk VLAN / hybrid VLAN / 多 VLAN list
- **FUTURE-04**: dry-run 模式
- **FUTURE-05**: 操作历史查看 UI
- **FUTURE-06~14**: 见 v1.19-REQUIREMENTS.md

### 2.3 不含 Cisco

与 v1.19 一致，本期 3 厂商：**Huawei / H3C / Ruijie**。FUTURE-08 (Cisco) 仍独立。

## 3. Vendor Command Matrix (基于实际设备输出)

### 3.1 set_access_vlan

| 厂商 | 完整命令序列 | 来源 |
|------|-------------|------|
| **Huawei VRP** | `interface <iface>`<br>`port link-type access` (V200R008+ 可省)<br>`port default vlan <vlanId>`<br>`quit` | 调研 (S5700/S5735 官方 KB) |
| **H3C Comware V7** | `interface <iface>`<br>`port link-type access` (必须)<br>`port access vlan <vlanId>`<br>`quit` | 调研 (H3C 官方命令手册) |
| **Ruijie RGOS 11.4** | `interface <iface>`<br>`switchport mode access` (必须)<br>`switchport access vlan <vlanId>`<br>`quit` | 调研 (Ruijie RG-S8607 命令参考 PDF) |

⚠ **H3C 与 Huawei 关键字不同**：
- Huawei: `port default vlan <id>`
- H3C: `port access vlan <id>`

⚠ **Ruijie Cisco 风格**：先 `switchport mode access` 再 `switchport access vlan`。

### 3.2 port_binding (add)

| 厂商 | 完整命令序列 | 来源 |
|------|-------------|------|
| **Huawei VRP** | `interface <iface>`<br>`user-bind static ip-address <ip> [mac-address <mac>] interface <iface>`<br>`quit` | 用户实采 `dis user-bind static all` 输出格式 |
| **H3C Comware V7** | (类 Huawei，`user-bind` 同样存在，H3C V7 命令集) | 调研（待现场 UAT 验证关键字） |
| **Ruijie RGOS 11.4** | `interface <iface>`<br>`switchport port-security binding <ip>` (一行一 IP，不支持 MAC 参数化 — 待 verify)<br>`quit` | 用户实采 `sh run int gigabitEthernet 1/1` 输出 |

### 3.3 port_binding (remove)

| 厂商 | 完整命令序列 |
|------|-------------|
| **Huawei** | `interface <iface>`<br>`undo user-bind static ip-address <ip> [mac-address <mac>] interface <iface>`<br>`quit` |
| **H3C** | (类 Huawei，undo 形式) |
| **Ruijie** | `interface <iface>`<br>`no switchport port-security binding <ip>`<br>`quit` |

### 3.4 MAC 地址格式归一化

| 厂商 | 命令中 MAC 格式 |
|------|----------------|
| Huawei | `AABB-CCDD-EEFF` (无冒号，带连字符) |
| H3C | `AABB-CCDD-EEFF` (同 Huawei) |
| Ruijie | `aaaa.bbbb.cccc` (Cisco 风格点分十六进制) |

需要在 `vendor_port_template.go` 渲染前归一化 MAC 格式（参考项目已有 `NormalizeMACAddress` helper 库 `[memory: mac-address-normalize-returns-colon-format]`）。

## 4. Pre-State Check 策略

沿用 v1.19 模式：每个 action 下发前用 vendor-specific read 命令读当前状态，对比目标值，若一致则 NoOp 短路。

### 4.1 set_access_vlan Pre-State

| 厂商 | Read 命令 | 解析目标 |
|------|----------|---------|
| Huawei | `display port vlan <iface>` | 提取 `PVID` 列 |
| H3C | `display vlan` 或 `display this interface <iface>` | 提取端口的 PVID / access VLAN |
| Ruijie | `show interfaces status` (或 `sh int status`) | 提取 `Vlan` 列 |

实际设备样例（用户提供）：
```
<HUAWEI> display port vlan ge 1/0/0
Port                    Link Type    PVID  Trunk VLAN List
GE1/0/0                 access         25  --

<Ruijie> sh int status
Interface                                Status    Vlan
GigabitEthernet 1/1                      up        318
```

### 4.2 port_binding Pre-State

| 厂商 | Read 命令 | 解析目标 |
|------|----------|---------|
| Huawei | `display user-bind static all` | 找 (ip, interface) 匹配行 |
| H3C | `display user-bind` (Comware V7 关键字) | 找 (ip, interface) 匹配行 |
| Ruijie | `show port-security binding` | 找 (ip, port) 匹配行 |

实际设备样例（用户提供）：
```
<HUAWEI> dis user-bind static all
IP Address         MAC Address     VSI/VLAN(O/I)   Interface
10.62.25.1         --              --/--           GE1/0/0

<Ruijie> sh port-security binding
NO.  VLAN MacAddress     PORT       IpAddress         FilterType
1     --        --       Gi2/29     10.62.2.111       ipv4-only
```

### 4.3 NoOp 判定

- **set_access_vlan**: 当前 PVID == 目标 vlanId → `result.Status = "skipped"`, 不下发
- **port_binding add**: (ip, [mac], interface) 已存在 → skipped
- **port_binding remove**: (ip, [mac], interface) 不存在 → skipped

## 5. Permission 模型

**沿用 v1.19 单一权限**：`network:port:write`（不分 vlan / port-security / port_binding 多个 perm）。

菜单 seed 同样：单一"端口配置" F 型按钮，覆盖所有 7 个 actions（5 已有 + 2 新增）。

## 6. operlog OperType 映射

| Action | OperType | 语义 |
|--------|----------|------|
| `ActionSetAccessVLAN` | `OperTypeUpdate=2` | 修改现有端口配置（与 description 同类） |
| `ActionPortBinding` (op=add) | `OperTypeCreate=1` | 新增静态绑定记录 |
| `ActionPortBinding` (op=remove) | `OperTypeDelete=3` | 删除静态绑定记录 |

## 7. Audit Row Schema

**复用 v1.19 `sys_port_write_audit` 表**，**无需 schema 变更**。

`before_value` / `after_value` 字段已是 `json.RawMessage` (JSONB)，直接序列化：

```json
// set_access_vlan
before: {"vlanId": 25, "linkType": "access"}
after:  {"vlanId": 100, "linkType": "access"}

// port_binding add
before: null
after:  {"ipAddress": "10.62.25.5", "macAddress": "AA:BB:CC:DD:EE:FF"}

// port_binding remove
before: {"ipAddress": "10.62.25.5", "macAddress": "AA:BB:CC:DD:EE:FF"}
after:  null
```

`operlog.oper_param` 字段携带 operator + audit_id（Path C 模式不变）。

## 8. UI 设计

### 8.1 复用 v1.19 模式

- 端口列表"操作"列下拉：**5 项 → 7 项**
  - 启停端口（shutdown / undo_shutdown）
  - 修改描述
  - dot1x 启停
  - **修改 access VLAN**（新增）
  - **端口绑定**（新增）

- 复用 `PortWriteModal`（单 Modal 5-action 模式 → 7-action）
- 复用 `BulkWriteDrawer`（批量三态机）
- 复用 `ActionButtons` 组件

### 8.2 新 Modal 表单字段

| Modal | 字段 |
|-------|------|
| `SetAccessVlanModal` | `vlanId: InputNumber (1-4094)` + reason (复用 v1.19 5-200 字符) |
| `PortBindingModal` | `op: Radio.Group (add / remove)` + `ipAddress: Input (IPv4 regex)` + `macAddress: Input (MAC regex, optional)` + reason |

### 8.3 审计跳转

复用 v1.19 `showAuditLinkToast` helper。OperType 区分（Create / Update / Delete）后，前端根据 OperType 文案变化（"新增/修改/删除"）。

## 9. API 端点

沿用 v1.19 模式，**新增 3 个端点**（2 单端口 + 1 batch 共用）：

```
POST /network/ports/write/set-access-vlan
POST /network/ports/write/port-binding
POST /network/ports/write/batch        (复用 v1.19，已支持任意 action)
```

`networkApi.ts` 新增 2 个 wrapper：
```typescript
export const writeSetAccessVlan = async (req: SetAccessVlanRequest) => post<PortResult>(...)
export const writePortBinding = async (req: PortBindingRequest) => post<PortResult>(...)
```

## 13. Known Risks & Decisions

| ID | 风险 | 缓解 |
|----|------|------|
| RISK-01 | H3C user-bind 关键字未在 v1.19 出现过；用户说"复用华为命令"语义不明 | 模板按 Huawei 模板结构写，H3C 关键字待现场 UAT 阶段确认；写 fallback（关键字与 Huawei 不同的 vendor 走 H3C 独立模板） |
| RISK-02 | Ruijie `switchport port-security binding` 是否支持 MAC 参数未确认（用户实采输出无 MAC 列） | MVP 仅做 IP binding；MAC optional 字段若 Ruijie 拒绝，记录到 H3C/Huawei 路径，Ruijie 仅 IP |
| RISK-03 | Huawei 老固件 V200R003 需 `port link-type access` 前置 | 模板在 Huawei 入口加 `port link-type access`（与 description v1.19 模式一致，宽容老固件） |
| RISK-04 | 用户输入 VLAN 越界（<1 或 >4094） | service 层加 validator（与 description 长度校验同模式） |
| RISK-05 | 用户输入 IP 格式错误 / MAC 格式错误 | service 层加 IP regex + MAC regex（与 description 字符校验同模式） |
| DECISION-01 | 不重命名现有 5 action（与 v1.19 audit log 兼容） | 2 个新 action 走新名 ActionSetAccessVLAN / ActionPortBinding |
| DECISION-02 | port_binding 1 个 action 覆盖 add/remove | 通过 `op` 字段区分，operlog OperType 分流（Create / Delete） |
| DECISION-03 | 暂不实装"binding 列表查看"功能（只写不读） | 复用 `dis user-bind static all` 在 pre-state 阶段读到完整列表；前端列表查看留 FUTURE-05 |
