# 缓存异步写入失败重试机制

## 概述

本功能为XingRan-Next项目的多级缓存（L1内存 + L2 Redis）提供了L2缓存异步写入失败的自动重试机制，解决了之前L2缓存写入失败只记录警告、数据可能丢失的问题。

## 核心特性

### 1. 自动重试机制

- **指数退避重试**：每次重试延迟按指数增长，避免雪崩
- **智能错误判断**：只对网络相关错误进行重试
- **随机抖动**：添加10%随机延迟，避免惊群效应
- **异步处理**：重试在后台协程中执行，不影响主线程

### 2. 工作队列模式

- **队列缓冲**：1000个任务缓冲队列
- **多协程处理**：默认3个工作协程并发处理重试任务
- **统计监控**：实时记录重试成功率、失败次数等

### 3. 可配置化

所有重试参数均可在配置文件中调整：

```yaml
cache:
  retry_enabled: true           # 是否启用重试
  retry_max_retries: 3          # 最大重试次数
  retry_initial_delay: 50       # 初始延迟（毫秒）
  retry_max_delay: 2000         # 最大延迟（毫秒）
  retry_backoff_factor: 2.0     # 退避因子
  retry_worker_count: 3         # 工作协程数
```

## 使用方式

### 1. 配置启用

在 `configs/config.yaml` 中设置：

```yaml
cache:
  type: "redis"
  # ... 其他缓存配置 ...

  # 启用L2缓存写入重试
  retry_enabled: true
  retry_max_retries: 3
  retry_initial_delay: 50
  retry_max_delay: 2000
  retry_backoff_factor: 2.0
  retry_worker_count: 3
```

### 2. 代码方式创建

```go
import "github.com/xingran-next/xingran-go-backend/pkg/cache"

// 创建默认重试配置
retryConfig := cache.DefaultRetryConfig()

// 创建带重试的多级缓存
multiLevelCache := cache.NewMultiLevelCacheWithRetry(
    memoryCache,
    redisCache,
    retryConfig,
    3, // 工作协程数
)
```

### 3. 查看重试统计

## 可重试的错误类型

以下网络相关错误会自动重试：

- `connection refused` - 连接被拒绝
- `connection reset` - 连接重置
- `broken pipe` - 管道破裂
- `timeout` / `i/o timeout` - 超时
- `network is unreachable` - 网络不可达
- `no route to host` - 无路由到主机
- `connection timed out` - 连接超时
- `EOF` - 连接意外关闭
- `use of closed network connection` - 使用已关闭的连接

以下错误**不会**重试：

- 认证错误（密码错误）
- 数据格式错误
- 权限错误
- 键不存在等业务逻辑错误

## 性能影响

### 正常情况（Redis正常）

- **L1缓存写入**：同步，约0.1ms
- **L2缓存写入**：异步，不阻塞主线程
- **总延迟**：约0.1ms

### L2写入失败

- **第1次写入失败**：记录失败，加入队列
- **重试延迟**：50ms → 100ms → 200ms
- **3次重试总耗时**：约350ms（异步，不影响主线程）

### 资源占用

- **每个工作协程**：约2MB内存
- **3个工作协程**：约6MB内存
- **队列缓冲**：1000个任务 × 约200字节 = 约200KB

## 监控和告警

### 关键指标

1. **成功率**：`total_success / total_attempts`
   - 正常值：> 95%
   - 告警阈值：< 90%

2. **连续失败次数**：`consecutive_fails`
   - 正常值：0-5
   - 告警阈值：> 10

3. **队列大小**：`queue_size`
   - 正常值：< 100
   - 告警阈值：> 500

## 故障排查

### 问题1：重试不生效

检查配置：
```bash
# 查看配置
grep -A 10 "cache:" configs/config.yaml

# 确认 retry_enabled: true
```

### 问题2：队列积压

可能原因：
- Redis连接完全断开
- 网络长时间不可用
- Redis负载过高

解决方案：
- 检查Redis连接状态
- 增加工作协程数
- 检查网络连接

### 问题3：重试成功率低

可能原因：
- Redis配置不当
- 网络不稳定
- Redis服务器过载

解决方案：
- 检查Redis服务器状态
- 优化Redis配置
- 考虑使用Redis哨兵或集群模式

### RetryConfig配置

```go
type RetryConfig struct {
    MaxRetries      int           // 最大重试次数
    InitialDelay    time.Duration // 初始延迟
    MaxDelay        time.Duration // 最大延迟
    BackoffFactor   float64       // 退避因子
    RetryableCheck  func(error) bool // 判断错误是否可重试
}

// 获取默认配置
func DefaultRetryConfig() *RetryConfig
```
