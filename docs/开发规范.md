# 开发规范文档

## 1. 概述

本文档定义了RuoYi Modern项目的开发规范，包括编码规范、状态值规范、数据库设计规范等，确保项目的一致性和可维护性。

## 2. 状态值统一规范

### 2.1 通用规则

为保持系统一致性，所有模块的状态字段必须遵循以下统一规则：

- **0 = 启用/正常/显示/有效**：表示该数据处于活跃可用状态
- **1 = 禁用/停用/隐藏/无效**：表示该数据处于不可用状态

### 2.2 各模块状态定义

| 模块 | 状态类型 | 0值含义 | 1值含义 | 默认值 | 显示颜色 |
|------|---------|--------|--------|--------|----------|
| **用户模块** | UserStatus | 启用 | 禁用 | 0 | 绿/红 |
| **角色模块** | RoleStatus | 正常 | 停用 | 0 | 绿/红 |
| **菜单模块** | MenuStatus | 显示 | 隐藏 | 0 | 绿/红 |
| **部门模块** | DeptStatus | 正常 | 停用 | 0 | 绿/红 |
| **岗位模块** | PostStatus | 正常 | 停用 | 0 | 绿/红 |

### 2.3 后端实现规范

```go
// 状态常量定义
const (
    UserStatusEnabled  UserStatus = 0 // 启用
    UserStatusDisabled UserStatus = 1 // 禁用
)

// 数据库模型
type User struct {
    // ...其他字段
    Status UserStatus `gorm:"default:0" json:"status"`
    // ...其他字段
}
```

### 2.4 前端实现规范

```typescript
// 类型定义
export type UserStatus = 0 | 1;  // 0:启用 1:禁用

// 状态显示组件
const getStatusTag = (status: number) => {
  return (
    <Tag color={status === 0 ? 'success' : 'error'}>
      {status === 0 ? '启用' : '禁用'}
    </Tag>
  );
};

// 表单默认值
<Form.Item name="status" label="状态" initialValue={0}>
  <Select>
    <Select.Option value={0}>启用</Select.Option>
    <Select.Option value={1}>禁用</Select.Option>
  </Select>
</Form.Item>
```

## 3. 数据库设计规范

### 3.1 表设计规范

1. **表命名**：使用 `sys_` 前缀，采用小写字母和下划线
2. **字段命名**：使用小写字母和下划线，见名知意
3. **主键**：统一使用 UUID 类型，默认值为 `gen_random_uuid()`
4. **时间字段**：必须包含 `created_at`、`updated_at`，软删除表包含 `deleted_at`
5. **状态字段**：统一使用整数类型，0表示启用/正常，1表示禁用/停用

### 3.2 字段设计规范

| 字段类型 | 说明 | 示例 |
|---------|------|------|
| **主键** | UUID类型 | `id UUID DEFAULT gen_random_uuid()` |
| **状态** | 整数类型 | `status INTEGER DEFAULT 0` |
| **排序** | 整数类型 | `order_num INTEGER DEFAULT 0` |
| **备注** | 文本类型 | `remark TEXT` |
| **创建时间** | 时间戳 | `created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP` |
| **更新时间** | 时间戳 | `updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP` |

### 3.3 索引设计规范

1. **主键索引**：自动创建
2. **外键索引**：所有外键字段必须创建索引
3. **唯一索引**：业务唯一字段必须创建唯一索引
4. **查询索引**：经常用于查询条件的字段创建索引

## 4. API设计规范

### 4.1 RESTful API规范

1. **请求方法**：统一使用 POST 方法，通过路径区分操作类型
2. **路径规范**：使用小写字母和下划线，资源名称使用复数形式
3. **响应格式**：统一使用 JSON 格式，包含固定字段

```go
// 路径设计示例
POST /api/v1/users              // 创建用户
POST /api/v1/users/list         // 查询用户列表
POST /api/v1/users/{id}         // 获取用户详情
POST /api/v1/users/{id}/update  // 更新用户
POST /api/v1/users/{id}/delete  // 删除用户
```

### 4.2 响应格式规范

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    // 具体数据
  },
  "timestamp": 1234567890,
  "requestId": "uuid-string"
}
```

### 4.3 状态码规范

| 状态码 | 说明 | 使用场景 |
|--------|------|----------|
| 200 | 成功 | 操作成功 |
| 400 | 请求错误 | 参数错误、格式错误 |
| 401 | 未授权 | 未登录、token无效 |
| 403 | 禁止访问 | 权限不足 |
| 404 | 资源不存在 | 资源未找到 |
| 500 | 服务器错误 | 系统内部错误 |

## 5. 代码规范

### 5.1 Go代码规范

1. **包命名**：使用小写字母，简短且有意义
2. **函数命名**：使用驼峰命名，首字母大写表示公开，小写表示私有
3. **变量命名**：使用驼峰命名，见名知意
4. **常量命名**：使用全大写字母和下划线
5. **注释规范**：公开函数必须包含注释

```go
// UserService 用户服务接口
type UserService interface {
    // CreateUser 创建用户
    CreateUser(ctx context.Context, user *User) error
}

// userService 用户服务实现
type userService struct {
    db *gorm.DB
}

// NewUserService 创建用户服务实例
func NewUserService(db *gorm.DB) UserService {
    return &userService{db: db}
}
```

### 5.2 TypeScript代码规范

1. **文件命名**：使用小写字母和短横线或下划线
2. **组件命名**：使用 PascalCase
3. **函数命名**：使用 camelCase
4. **变量命名**：使用 camelCase
5. **常量命名**：使用 UPPER_SNAKE_CASE

## 6. 安全规范

### 6.1 认证授权

1. **JWT Token**：使用双Token机制（访问Token + 刷新Token）
2. **密码加密**：使用SM3国密算法加密
3. **权限控制**：基于RBAC模型的权限控制
4. **API鉴权**：所有API接口必须进行权限验证

### 6.2 数据安全

1. **SQL注入防护**：使用参数化查询
2. **XSS防护**：前端输出内容必须进行转义
3. **CSRF防护**：使用CSRF Token防护
4. **敏感数据**：敏感信息不得在前端存储

## 7. 测试规范

### 7.1 单元测试

1. **覆盖率**：核心逻辑覆盖率不低于80%
2. **测试命名**：使用 `Test_功能名_场景` 格式
3. **断言规范**：使用清晰的断言消息

```go
func TestUser_CreateUser(t *testing.T) {
    tests := []struct {
        name    string
        user    *User
        wantErr bool
    }{
        {
            name:    "成功创建用户",
            user:    &User{Username: "test", Status: 0},
            wantErr: false,
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            err := userService.CreateUser(context.Background(), tt.user)
            if (err != nil) != tt.wantErr {
                t.Errorf("CreateUser() error = %v, wantErr %v", err, tt.wantErr)
            }
        })
    }
}
```

### 7.2 集成测试

1. **API测试**：测试所有API接口的功能
2. **数据库测试**：测试数据库操作的正确性
3. **权限测试**：测试权限控制的有效性

## 9. 文档规范

### 9.1 代码注释

1. **文件注释**：每个文件必须包含文件说明
2. **函数注释**：公开函数必须包含完整注释
3. **复杂逻辑**：复杂业务逻辑必须添加注释

### 9.2 API文档

1. **接口说明**：每个API接口必须包含详细说明
2. **参数说明**：请求参数和响应参数必须说明
3. **示例代码**：提供完整的调用示例

## 10. 版本管理

### 10.1 Git规范

1. **分支命名**：使用 `feature/功能名` 格式
2. **提交信息**：使用约定式提交格式
3. **代码审查**：所有代码必须经过代码审查

### 10.2 版本发布

1. **版本号**：使用语义化版本号（semver）
2. **发布说明**：每次发布必须包含详细的发布说明
3. **标签管理**：使用Git标签标记版本

## 11. 总结

本规范文档定义了项目开发的基本规范，所有开发人员必须严格遵循。如有需要修改规范，必须通过团队讨论和架构评审。

规范的目的是：
- 提高代码质量和可维护性
- 降低团队协作成本
- 确保系统的一致性和稳定性
- 提升开发效率和用户体验

定期审查和更新规范，确保规范的适用性和完整性。
