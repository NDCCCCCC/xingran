## 1. 系统概述

### 1.1 平台定位

数智化平台是基于若依（XingRan）框架深度重构的 **Go + React 前后端分离企业级权限管理系统**，集成国密 SM2/SM3/SM4 算法满足等保合规要求，面向企业内部运维、业务、数据可视化的统一管理平台。

核心能力一览：

| 能力域 | 内容 |
|--------|------|
| 权限管理 | 完整 RBAC：用户/角色/菜单/部门/岗位 + 数据权限 + 细粒度按钮权限 |
| 运维资产 | 楼宇/楼层/工位/机房/专线/信息点全生命周期，Excel 批量导入导出，3D 可视化 |
| 网络设备 | Scrapli (SSH/Telnet) + SNMP 纳管，端口采集、MAC 历史、LLDP 拓扑、远程端口写命令 + 审计 |
| 资产对账 | 账务/资产/网络三源对账，异常分类 A-F，修复建议，自动转工单 |
| AD 域集成 | LDAP 多账号故障切换池、定时同步、OU 管理、部门-OU 映射 |
| RPA 自动化 | Docker Worker 自动扩缩容、AI 生成脚本 + 视觉 Agent 降级 |
| VDI 桌面云 | 深信服接口对接、虚拟机生命周期、VM Agent 远程运维 |
| 协同办公 | 工单（轮转分配/周期工单）、值班排班、知识库、定向通知 |

### 1.2 技术架构

- **后端**：Go 1.24 + Gin + GORM + PostgreSQL 18（备选 SQLite）/ Redis 7.4
- **前端**：React 19 + TypeScript + Ant Design + Three.js + ECharts
- **安全**：SM2/SM3/SM4 国密体系、JWT 双 Token、请求体加密
- **请求链路**：`请求 → Router → 中间件（RequestID → 加解密 → JWT 认证 → 操作日志 → 权限 → 数据权限）→ Handler → Service → DB/Cache`
- **统一响应**：`{code, message, data, timestamp, request_id}`，成功码 `0`
- **状态值约定**：全平台 `0 = 正常/启用`，`1 = 停用/禁用`（菜单 `visible` 字段例外：`1 = 可见`）

### 1.3 组件构成

| 组件 | 说明 |
|------|------|
| 后端单体（`xingran-backend`） | API 服务 + 调度器 + WebSocket，前端静态资源与 TextFSM 模板已 embed 进二进制 |
| 前端 SPA（React） | 动态菜单驱动路由，菜单+权限 sessionStorage 30 分钟缓存 |
| PostgreSQL 18 | 主库，分区表 + 物化视图（对账/MAC 统计） |
| Redis 7.4 | L2 缓存、Token 黑名单、RPA 任务队列（Redis Streams） |
| VM Agent（可选） | 部署在 VDI 虚拟机内的常驻代理（Windows/Linux） |
| RPA Worker（可选） | Chromium 浏览器自动化执行器，Docker 容器池 |

## 2. 快速入门

### 2.1 登录

- 访问 `http://<服务器地址>/`（生产建议 HTTPS）。
- **统一登录入口**：本地账号与 AD 域账号使用同一表单，后端按账号来源自动路由认证方式。
- **验证码**：登录前前端自动预检（preflight）验证码配置，三种形态动态切换：
  - `disabled` — 无验证码直接登录；
  - `normal` — 页内图形/文字验证码，随表单提交；
  - `slider` — 弹出滑块验证码模态，拖拽通过后再登录。
  - 服务端验证码类型变更时前端自动刷新配置重新验证，无需手动刷新页面。
- **密码安全**：系统支持 SM2 密码字段加密 + SM2/SM4 请求体加密（开关由后端参数动态下发，见 §17）。
- 登录成功后自动拉取菜单与权限并跳转仪表盘；平台记忆上次访问路径。
- 连续失败触发锁定（默认策略见 §17.5），管理员可在「系统监控 → 登录日志」解锁，或 `POST /api/v1/system/user/unlock`。

### 2.2 界面布局与个性化

| 项 | 说明 |
|----|------|
| 布局模式 | `classic` 经典（左导航+顶栏）、`hybrid` 混合（可折叠侧栏+多标签页）、`innovative` 创新（图标化"空间"导航，9 大空间：仪表盘/系统管理/系统监控/网络设备/值班管理/工单管理/消息通知/个人中心/系统设置） |
| 主题风格 | 5 套预设 × 明/暗双模式：minimal 极简、glassmorphism 玻璃拟态、neumorphism 新拟物、flat2.0 扁平 2.0、luxury-quiet 轻奢静谧 |
| 颜色定制 | 主色取色器 + 侧栏背景色 + 预设色板 |
| 密度 | 紧凑 / 舒适 / 宽松 |
| 个人偏好 | 「个人中心 → 设置」中保存（明暗模式、布局、默认分页大小），跟随账号漫游 |

### 2.3 全局功能

- **全局搜索**（顶栏）：跨菜单快速定位页面。
- **通知铃**：未读通知计数、实时 WebSocket 推送。
- **面包屑 / 快速导航**：层级路径与常用页快捷入口。
- **个人中心**：资料维护、修改密码、头像上传、我的通知、我的值班。

### 2.4 权限与菜单可见性

> 所有页面均由后端菜单表按角色下发。若某功能在本手册中有述但界面不可见，请检查：① 角色是否勾选该菜单（注意父子联动，勾父不等于勾子）；② 该菜单状态是否启用；③ 重新登录刷新菜单缓存。

## 3. 系统管理

路由前缀：`/api/v1/system`

### 3.1 用户管理（`system:user:*`）

| 操作 | 说明 |
|------|------|
| 查询/统计 | 列表支持部门树侧栏联动筛选、关键字、状态过滤；`POST /users/statistics` 提供统计卡片数据 |
| 新增/编辑 | 用户名、昵称、部门、岗位、角色、手机、邮箱、状态；密码符合策略（§17.5） |
| 启停/删除 | 单个 + 批量；停用用户立即失效（Token 黑名单） |
| 重置密码 | 管理员强制重置，用户下次登录使用新密码 |
| Excel 导入 | `POST /users/import`，导入过程联动 AD 域同步；提供模板下载 |
| 解锁 | 「登录日志 → 解锁」或专用端点，针对连续失败被锁账号 |
| 数据权限 | 用户列表受数据权限（DataScope）过滤：全部/本部门/本部门及以下/仅本人 |

### 3.2 角色管理（`system:role:*`）

- 角色 CRUD、启停、批量删除；统计卡片。
- **菜单权限分配**：树形勾选（目录/菜单/按钮三级）；注意 antd 树父子联动语义——子菜单未显式勾选时路由不生成。
- **数据权限分配**：全部/自定义/本部门/本部门及以下/仅本人。

### 3.3 菜单管理（`system:menu:*`）

- 树表管理三类节点：目录（M）/ 菜单（C）/ 按钮（F）。
- 菜单节点维护：路由地址、组件路径、权限标识（perms）、图标、排序、可见性。
- **新增页面上线流程**：菜单管理建节点 → 角色管理授权 → 用户重新登录。
- 按钮级权限标识即后端 `RequirePermissions` 校验的字符串（附录 A 有权限族清单）。

### 3.4 部门管理（`system:dept:*`）

- 树形 CRUD、启停、批量；支持 Excel 导入/导出/模板下载。
- 导出含「上级部门链路」列，用于区分同名部门。
- 部门树同时服务：用户归属、数据权限、工位导入部门匹配、AD OU 映射目标。

### 3.5 岗位管理（`system:post:*`）

- 岗位 CRUD、启停、批量删除、下拉选项（`/posts/enabled`）。

### 3.6 字典管理（`system:dict:*`）

- 字典类型 + 字典数据两级；前端页面通过 `useDict` 消费（如节假日类型 `duty_holiday_type`、资产状态等）。
- 字典缓存 24 小时（Lazy-Loading），修改后自动失效相关缓存。

### 3.7 参数管理（`system:config:*`）

系统级动态参数（sys_config），典型键：

| 键 | 作用 |
|----|------|
| `sys.request.encryption.enabled` | 响应体加密运行时开关（热生效） |
| `sys.auth.ad.default_dept_id` | AD 同步用户默认部门 |
| `sys.ad.group.sync.*` | AD 组同步开关/cron/目标 OU 等（§5.6） |
| `vdi.server.{index}.{field}` | VDI 服务器连接信息（已从配置文件迁移至此） |
| `network.connection_pool.*` | 网络设备 SSH 连接池容量/空闲超时（改后需重启） |

- 修改后可 `/configs/refresh-cache` 手动刷新参数缓存。

### 3.8 通知公告（`system:notice:*`）

- 公告 CRUD、批量删除；**发布/撤回**支持定时（为每条定时公告自动生成 cron 任务，到点经 WebSocket + 多渠道推送，到期自动撤回）。
- **定向发布**：可指定接收范围；用户端「我的通知」提供未读计数、单条/全部已读、忽略。
- **推送渠道**：可为公告配置邮件/API(Webhook) 渠道（需先在设置中心配置，§4.1/4.2）。

### 3.9 API 密钥（`system:apikey:*`）

- 为第三方/脚本签发 API Key，支持 scopes、过期时间、启停。
- 调用日志与用量汇总（`/apikeys/:id/logs`、`/summary`）；支持 X-API-Key 认证链与限流。

### 3.10 操作日志 / 登录日志

- 操作日志 `sys_oper_log`：记录所有业务写操作（模块、类型、操作人、请求参数——敏感字段自动脱敏 `******`）。
- 登录日志 `sys_logininfor`：登录成功/失败记录，支持解锁入口。
- 高频路径可经 `operlog.exclude_paths` 配置排除（默认排除 RPA Worker 心跳，§21.5）。
- 支持单条/批量删除、清空（请先归档，日志为分区表、GB 级/天增长，见 §20.5）。

### 3.11 个人文件与偏好

- 文件上传/列表/详情/删除/批量删除（`sys_files`，含访问日志）。
- 表格列配置：每个列表页的列显隐/顺序可按 `page_key` 保存/重置。

## 5. AD 域管理

路由前缀：`/api/v1/ad-domain`，权限族 `ops:ad:*`

### 5.1 域配置

- 多域配置 CRUD：域控地址、端口、TLS、基础 DN；**连接测试**；手动触发全量同步。
- 凭据字段（管理员密码）SM4 加密存储，日志与导出自动脱敏。

### 5.2 服务账号池（关键可靠性设计）

> 解决"单管理员账号被锁导致所有用户无法登录"问题（多账号故障切换池）。

- 多账号管理：创建/更新/启停/删除/解锁/统计。
- **状态机**：`0=可用 / 1=停用 / 2=熔断`；连续 3 次失败自动熔断 30 分钟，cron 每 5 分钟恢复过期熔断。
- **故障切换**：登录/同步时按可用账号顺序遍历，任一成功即返回（最多 10 跳）。
- **手动解锁**：必须填写 ≥10 字符原因 + 操作人（审计要求）。
- 排查入口：`sys_ad_service_accounts` 的 `last_failure_reason` / `status` / `failure_count`。

### 5.3 组织单位（OU）与用户/组/计算机

| 功能 | 说明 |
|------|------|
| OU 树 | 拉取 AD 组织架构树（`ops:ad:ou:view`） |
| AD 用户 | 列表/详情/编辑/移动 OU/启用/禁用；批量从 AD 同步用户入库 |
| AD 组 | 列表、同步状态、成员查看、编辑 |
| AD 计算机 | 列表/详情（域内设备台账） |

### 5.4 映射管理

- **OU ↔ 部门映射**（`sys_dept_ou_mapping`）：AD 同步用户的部门落位依据。
- **OU ↔ 用户组映射**（`sys_ou_group_mapping` + 同步日志）：OU 下用户自动加入指定 AD 组。

### 5.5 同步机制

- 独立调度器每 5 分钟检查启用的域配置并执行全量同步（`ad_data_sync`）；同步日志可查（`ops:ad:log:view`）。
- 部门结构→AD OU、部门成员→AD 组两个任务类型可在「定时任务」中按需配置 cron。

### 5.6 AD 组同步配置

> 注意：组同步**不读配置文件**，读 sys_config 表。推荐经 API `POST /api/v1/system/ad-domain/group-config/update` 配置。

| 键 | 默认 |
|----|------|
| `sys.ad.group.sync.enabled` | false |
| `sys.ad.group.sync.cron` | `0 */15 * * * *`（每 15 分钟） |
| `sys.ad.group.member_ou` | —（目标 OU） |
| `sys.ad.group.auto_create` | false |
| `sys.ad.group.max_concurrent` / `batch_size` | — |

### 5.7 已知行为约束

- AD 用户在 AD 端被删后，本地残留 `ad_dn` 的属性修改会报 `No Such Object`（code 32）；同步逻辑已内置 DNExists 预检短路，不再放大账号池熔断。
- AD 端账号锁定（LDAP data 775）是临时状态，会自动解锁；先查子码再判断是否代码问题（§21.1）。

## 6. 运维资产管理

路由前缀：`/api/v1/ops`，权限族 `ops:building/floor/workstation/serverroom/dedicatedline/infopoint/asset/location/workstation-device/floor-plan:*`

### 6.1 物理资源台账

| 资源 | 要点 |
|------|------|
| 楼宇 | CRUD + 批量 + 统计 + 下拉；**地理编码**（`/building/geocode`，百度地图，30 分钟缓存）；`org_id` 必须是有效部门 UUID |
| 楼层 | CRUD + 楼层树；关联楼宇 |
| 工位 | CRUD + 部门下拉 + 平面图坐标批量更新 + 楼层工位全集（3D/平面图用）；导入支持部门代码、用户名、主设备 SN 跨表关联 |
| 机房 | CRUD + 照片管理（上传/主图/排序/描述/批量删除） |
| 机房设备 | CRUD + Excel |
| 专线 | CRUD + Excel |
| 信息点 | CRUD + Excel；与端口/工位/设备关联 |

### 6.2 Excel 批量导入导出

- 全资源支持三件套：`/import`、`/export`、`/template`（模板下载）。
- **列顺序即模板列顺序**（按位置匹配，非表头名），模板勿自行调序。
- 工位导入附赠**部门映射表下载**（`/workstation/dept-mapping-template`），便于按部门代码批量对应。
- 导入链路：名称/编码→ID 批量解析 → 按 UpsertKey 批量插入或更新 → 自动失效相关缓存 → 返回成功/失败明细。

### 6.3 工位设备关联

工位可挂接三类设备视图，管理员按需维护：

| 视图 | 数据来源 | 用途 |
|------|----------|------|
| AD 设备 | AD 计算机同步 | 使用者-设备对应 |
| 资产设备 | `ops_asset` 台账 | 财务/台账对应 |
| 物理链路 | MAC→交换机端口→信息点反推 | 接入位置核实（用 port_id 锚定，跨设备同名接口属正常现象） |

- 支持手动添加、AD/资产同步、设主设备（`set-primary`）。

### 6.4 CAD 平面图

- 楼层平面图要素：墙体、门、文本标注——均 CRUD + 批量；配合工位坐标构成 CAD 风格平面编辑器。

### 6.5 资产台账与组件

- `ops_asset`：设备资产主档（类型/类别/状态基础数据由端点提供）；按序列号查询、组件清单（板卡/电源/风扇/光模块，来自 v1.18 SNMP ENTITY-MIB 采集，一机多序列号 + 父子从属）。
- 组件行 UPDATE-only：板卡要出现在组件 Tab，须先作为资产行导入；采集 MISS 只发对账异常。

### 6.6 楼宇空间可视化

| 页面 | 能力 |
|------|------|
| 楼宇空间 | 楼宇卡片 + 3D 楼层堆叠 + 工位平面图；统计走专用 COUNT 端点 |
| 湖北省 3D | 省级楼宇分布地图（百度地图普通版 / WebGL 版可切换），聚合标记、下钻楼宇 |

## 7. 网络设备管理

路由前缀：`/api/v1/network`

### 7.1 设备台账与凭据

- **设备**（`network:device:*`）：CRUD、批量删除、在线探测、导出、快捷创建；统计卡片。
- **凭据**（`network:credential:*`）：SSH/Telnet/SNMP 凭据池（密码 SM4 加密存储），设默认、查看引用设备、导出。

### 7.2 命令模板与分发

- **模板**（`network:template:*`）：变量化命令模板，渲染预览、克隆、变量管理。
- **命令分发**（`network:command:execute/view`）：批量 CLI 下发、快捷命令、执行明细（按设备）、导出。
- **配置执行**：按模板批量下发配置、取消、明细。

### 7.3 配置备份与恢复（`network:backup:*`）

- 手动/批量备份；备份内容查看；**diff 差异对比**；版本与历史。
- **恢复**：独立强权限 `network:backup:restore`，恢复任务可追踪。

### 7.4 设备发现（`network:discovery:*`）

- 创建发现任务（网段扫描）→ 执行 → 查看结果 → **一键导入为设备台账**。

### 7.5 端口采集与管理

- 端口状态采集（单台/全部）、列表、统计、导出；查询接受运维读权限（供信息点等选择器）。
- **端口写命令**（`network:port:write`，v1.19/v1.20）：经 SSH 直连下发，全量写入审计表 `sys_port_write_audit`：

| 命令 | 端点 |
|------|------|
| 端口关停/启用 | `/ports/write/shutdown`、`/undo-shutdown` |
| 端口描述 | `/ports/write/description` |
| 802.1X 启用/停用 | `/ports/write/dot1x-enable`、`/dot1x-disable` |
| 设置 Access VLAN | `/ports/write/set-access-vlan` |
| 端口绑定（MAC/IP 绑定） | `/ports/write/port-binding` |
| 批量执行 | `/ports/write/batch`（串行 fail-fast，上限 50 端口） |

- 厂商适配：华为/H3C/锐捷（`no shutdown` vs `undo shutdown` 等差异已在矩阵内处理）。
- 每条写命令经 sentinel 校验器防误操作；操作人、原始命令全量入审计表。
- 排查：`undo`/`exit`/嵌套视图等厂商差异见内存矩阵；批量操作当前为不确定进度（SSE 实时进度在规划中，§22）。

### 7.6 MAC 地址管理

- MAC 表查询/采集（单台/全部）/统计/清理/导出；**MAC 归一化为冒号格式**（`AA:BB:CC:DD:EE:FF`）。
- **MAC 历史**：端口级/设备级变迁、接入统计、厂商识别（OUI 库）、**接入热力图**；月度分区自动清理与保留期配置。
- 端口管理页展开行可直接查看当前 MAC + 历史 MAC（懒加载）。
- **拓扑 MAC 过滤规则**：排除无需上图的 MAC（如网关虚 MAC），支持生效规则预览。

### 7.7 LLDP 拓扑

- LLDP 邻居信息采集入 `sys_device_lldp_info`，拓扑视图呈现设备互联；采集经 MAC 过滤规则降噪。

### 7.8 采集类定时任务（默认暂停，需手动启用）

| 任务 | 默认 cron |
|------|-----------|
| `device_status_check`（SNMP 在线状态） | 每 5 分钟 |
| `device_info_update`（型号/序列号/版本） | 每小时 |
| `port_collection`（端口状态） | 每小时 |
| `mac_collection`（MAC 表） | 每小时 |
| `config_backup`（配置自动备份） | 每天 02:00 |

> 启用入口：「系统监控 → 定时任务」。修改连接池容量（`network.connection_pool.*`）后需重启生效（默认 50 连接 / 300s 空闲回收，池满 LRU 淘汰最老空闲连接）。

## 17. 安全管理

### 17.1 国密体系总览

| 机制 | 说明 | 配置点 |
|------|------|--------|
| SM3 密码哈希 | PBKDF2-SM3（10000 次迭代+盐），不可逆 | 内置 |
| SM2 密码传输加密 | 前端取 `GET /auth/public-key` 公钥加密密码后提交 | 公钥端点须保留在加密排除路径 |
| SM4 字段级存储加密 | 设备密码/AD 管理员密码/RPA 凭证等入库加密 | `security.sm4_key`（env `SM4_KEY`，`openssl rand -base64 16`） |
| SM2+SM4 请求体加密 | 每请求随机 SM4 密钥加密 body，SM2 封装密钥；防重放（时间窗+nonce） | `security.request_encryption.*` |
| 响应体加密 | 默认关；**运行时开关=参数管理 `sys.request.encryption.enabled`** | 参数管理 |
| 双 Token | Access 7200s + Refresh 7 天，前端自动刷新；JWT SM2 签名 | `jwt.*` |

### 17.2 请求加密管理

- `enabled`：解密中间件总开关。
- `exclude_paths`：免加密路径（必须保留 `public-key`、`/captcha/*`、`/upload/*`、Worker register/heartbeat）。
- `require_encryption`：强制全部客户端加密（生产建议灰度开启）。
- **前后端配置同步**：前端经公共端点 `/auth/encryption-config` 动态协商（后端 30s / 前端 5 分钟缓存），管理员改参数即可热生效，不会造成登录态丢失。

### 17.3 验证码

- 图形/文字/滑块三种；背景图库管理（§4.3）；配置查询与 reload 端点。
- **注意**：验证码类型配置仅接受 `disabled/normal/slider`，其他值会导致登录页既不弹模态也无输入框（§21.3）。

### 17.4 Token 与在线用户

- 登出即入 Token 黑名单；缓存监控可查看登录相关键。
- 双 Token 自动刷新；Refresh Token 7 天。

### 17.5 密码策略

- 设计基线：8-128 位、大小写/数字/特殊字符、历史 5 次、90 天有效期、连续失败 5 次锁 30 分钟（以系统实际实现为准）。
- 管理员解锁：登录日志页或 `POST /system/user/unlock`。

### 17.6 审计

| 审计表 | 内容 |
|--------|------|
| `sys_oper_log` | 全业务写操作（25 种操作类型），敏感值脱敏 |
| `sys_logininfor` | 登录成功/失败 |
| `sys_port_write_audit` | 网络端口写命令全量（操作人/原始命令/结果） |
| `sys_rpa_audit_logs` | RPA 关键动作 |
| `sys_api_key_usage_logs` | API Key 调用 |

### 17.7 密钥管理红线

1. 仓库默认 SM2/JWT/SM4 均为**公开示例值，生产必须全部替换**。
2. `jwt.sm2_private_key` 留空 = 每次重启重新生成 = **全员强制登出**。
3. 生产 JWT 必须 `use_sm2: true`。
4. 生成工具：`go run scripts/crypto/gen_sm2_keys/main.go`；SM4：`openssl rand -base64 16`。
5. 启动前后检查清单见 `docs/deployment/secret-management.md`。

### 20.1 部署方式选型

硬件基线：最低 4 核 16GB；启用真实 RPA Docker 模式需 64GB+（每 Worker 容器 1-2GB）。端口：9000 后端仅内网、80/443 对外、5432/6379 **严禁公网**。

### 20.2 构建与启动

```bash
# 前端（产物经 go:embed 进入二进制）
cd xingran-react-frontend && npm install && npm run build

# 后端（Windows / Linux）
go build -o xingran-backend.exe ./cmd/main.go
set GOOS=linux && set CGO_ENABLED=0 && go build -ldflags="-s -w" -o xingran-backend-linux ./cmd/main.go
```

启动 7 阶段：进程 init → 配置/日志 → core（SM4/JWT，SM4 缺失直接终止）→ core.Init（PG 连接 → AutoMigrate + 56 个显式 migration → seed → 缓存 → cron → 验证码 → 账号池 → RPA）→ cmd 级 seed → Gin 路由 → HTTP + SIGTERM 优雅关闭。
`SERVER_SKIP_SETUP=true` 跳过 seed（生产首次部署必须 false，后续 true）。

### 20.3 数据库迁移

- `internal/core/db/migrations/`，启动时自动按版本执行（GORM AutoMigrate + 显式 migration 函数 + PG advisory lock 防并发）。
- 物化视图先 DROP 后重建（对账 MV），启动即 RefreshView。

### 20.4 备份与恢复

- PG 定期备份（pg_dump）+ 设备配置备份（§7.3）双轨。
- CI/CD 部署失败 60s 内自动回滚（保留 5 份 `.bak-*`）。

### 20.5 容量规划要点

- 三档：<100 单机 / 100-1000 单机调优 / 1000+ 拆 PG 主从 + Redis 集群 + 多实例 + LB。
- 操作日志 GB 级/天，需归档策略；3D 可视化吃前端内存；RPA 极耗资源。
- 拆库触发线：CPU>70%、内存>80%、磁盘 IO>50ms。

### 20.6 Swagger

`http://localhost:9000/swagger/index.html`（server.mode=debug）。重新生成：`./scripts/generate_swagger.bat`。

## 21. 常见问题与故障排查

> 以下均来自生产实际案例。排查顺序：先看现象 → 查对应表/日志 → 按处方处理。

### 21.1 用户报"登录失败"，提示 admin_bind / LDAP data 775

- **根因优先级**：① AD 端账号锁定（data 775，临时，自动解锁）；② 服务账号池熔断；③ SM4 cipher 偶发解密失败导致错密码 bind。
- **排查**：域控 `Get-ADUser` 查 `badPwdCount`；查 `sys_ad_service_accounts.last_failure_reason / status / failure_count`（`operation:` 前缀 = 业务失败，`dial:` = 连接失败）。
- **处理**：等待自动解锁（约 30 分钟）或管理员手动解锁（「AD 域 → 服务账号池 → 解锁」，原因须 ≥10 字符）。

### 21.2 登录后 idle 一段时间报加密错误/强制登出

- 前后端加密开关不一致。系统已内置 preflight + `encryption-config` 动态同步（后端 30s 缓存）；若仍复现，检查参数管理 `sys.request.encryption.enabled` 与 `security.request_encryption.*` 是否一致。

### 21.3 登录页既不弹验证码也没有输入框（死状态）

- 验证码类型配置了非法值（仅接受 `disabled/normal/slider`）。查 `sys_config` 验证码相关键并修正。

### 21.4 网络设备采集间歇性失败（设备较多时）

- SSH 连接池打满。默认 50 连接/300s 空闲回收，可经参数 `network.connection_pool.*` 调整，**改后需重启**。池满自动 LRU 淘汰最老空闲连接，不要"用完即关"。

### 21.5 RPA 心跳刷屏操作日志

- 已支持 `operlog.exclude_paths` 配置排除（默认已排除 `/api/v1/rpa/workers/*/heartbeat`）；如仍有高频路径污染，按 filepath.Match 通配追加。

### 21.6 设备序列号/信息不更新

- `device_info_update` 任务默认**暂停**，需在定时任务中手动启用。
- 若任务表无新行且 `net_device_enrichment_task` 存在长期 `running` 记录：worker 异常留下的僵尸任务会永久阻塞入队（去重查 pending/running）。处理：`UPDATE net_device_enrichment_task SET status='failed' WHERE status='running' AND updated_at < now()-interval '1 day'`。

### 21.7 启动卡在"PostgreSQL 连接成功"无 migration 日志

- 僵尸 MV 刷新（REFRESH CONCURRENTLY 堆叠锁死）。`pg_stat_activity` 找到 REFRESH 会话 `pg_terminate_backend`（CONCURRENTLY 中途杀是安全的），重启。

### 21.8 MAC 地址格式不一致

- 全链路已归一化为冒号格式 `AA:BB:CC:DD:EE:FF`（模型 hook 兜底 + 历史清洗迁移）。如发现其他格式，先确认部署二进制版本一致（部署漂移是历史根因），再排查。

### 21.9 统计卡片数字偏小（如恰好 100）

- 该卡片误用了列表接口（被 MaxPageSize=100 钳制）。正确实现应走专用 COUNT/statistics 端点；如遇到请反馈修复。

### 21.10 缓存监控里键名带 `xingran:` 前缀

- Redis 实际键带 `xingran:` 前缀；监控操作时直接粘贴即可（系统自动剥离前缀），无需手动处理。

### 21.11 VDI 虚拟机按钮置灰

- `power_state` 合法值仅 `pending/stopped/suspended/in_use`（没有 `running`）；按状态表判断可执行操作。

### 21.12 端口列表看到"跨设备同名接口"

- 正常现象（每台同型号交换机都有 GE1/1…）。物理链路查询以 port_id（UUID）锚定，勿按 interface_name 全局唯一理解。
