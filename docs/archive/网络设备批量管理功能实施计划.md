### 推荐方案：scrapligo + gorm + 自研调度层

基于您的项目特点（若依Go框架、已有完善的用户/权限/定时任务系统），**推荐使用方案二**：

**理由：**
1. scrapligo已成熟稳定，专注设备通信，无需重复造轮子
2. 与现有GORM数据库无缝集成
3. 可复用工位管理、定时任务等现有模块
4. 保持代码风格一致性
5. 便于后续维护和扩展

**技术栈组合：**
```
设备连接层: scrapligo
数据持久层: GORM (现有)
任务调度层: robfig/cron (现有) + errgroup (新增)
业务逻辑层: 自研 (遵循现有架构)
前端展示层: React + Ant Design (现有)
```

## 项目概述

为若依Go后端项目集成网络设备批量管理功能，支持国内主流厂商设备（Huawei、H3C、Ruijie、Maipu），实现设备管理、配置批量执行、配置模板、定期备份、差异对比、设备自动发现等功能。

---

## 用户确认的方案

| 选择项 | 方案 |
|--------|------|
| 设备厂商 | 国内厂商（Huawei、H3C、Ruijie、Maipu） |
| 配置存储 | 文件系统 + 数据库（文件存配置，数据库存元数据） |
| 实时监控 | 不需要（仅在执行任务时检查设备状态） |
| 前端实现 | 前后端完整实现 |
| 设备分组 | 使用现有部门表（sys_department） |
| 授权管理 | 独立授权凭证表，设备关联授权 |

### 定制化需求

1. **MAC地址表采集**：定期收集所有设备的MAC地址表信息
2. **802.1X状态监控**：收集所有端口的dot1x认证状态
3. **端口安全配置**：收集所有端口的安全配置信息
4. **命令分发**：支持对单个或多个设备进行命令分发

## 一、技术栈（基于scrapligo方案）

| 功能层 | 选用技术 | 说明 |
|--------|----------|------|
| **设备连接** | `github.com/scrapli/scrapligo` | 核心库，支持SSH/NETCONF，多厂商平台 |
| **数据库ORM** | `gorm.io/gorm` (现有) | 数据持久化 |
| **定时任务** | `github.com/robfig/cron/v3` (现有) | 配置备份定时任务 |
| **并发控制** | `golang.org/x/sync/errgroup` | 批量任务并发执行 |
| **SNMP协议** | `github.com/gosnmp/gosnmp` | 设备自动发现 |
| **模板引擎** | Go标准库 `text/template` | 配置模板变量替换 |
| **差异对比** | `github.com/andreyvit/diff` | 配置变更可视化 |
| **密码加密** | 项目现有 `internal/core/security/` | 凭证安全存储 |
