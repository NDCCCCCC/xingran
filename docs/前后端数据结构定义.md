# 前后端数据结构定义

## 概述

本文档定义了前后端交互的统一数据结构，确保API接口与前端类型定义的一致性。

## 状态值统一规范

### 通用规则

为保持系统一致性，所有模块的状态字段必须遵循以下统一规则：

- **0 = 启用/正常/显示/有效**：表示该数据处于活跃可用状态
- **1 = 禁用/停用/隐藏/无效**：表示该数据处于不可用状态

### 各模块状态定义

| 模块 | 字段名 | 类型 | 0值含义 | 1值含义 | TypeScript类型 |
|------|--------|------|--------|--------|----------------|
| **用户** | status | UserStatus | 启用 | 禁用 | `0 | 1` |
| **角色** | status | RoleStatus | 正常 | 停用 | `0 | 1` |
| **菜单** | status | MenuStatus | 显示 | 隐藏 | `0 | 1` |
| **部门** | status | DeptStatus | 正常 | 停用 | `0 | 1` |
| **岗位** | status | PostStatus | 正常 | 停用 | `0 | 1` |

### TypeScript类型定义示例

```typescript
// 用户状态
export type UserStatus = 0 | 1;  // 0:启用 1:禁用

// 角色状态
export type RoleStatus = 0 | 1;  // 0:正常 1:停用

// 菜单状态
export type MenuStatus = 0 | 1;  // 0:显示 1:隐藏

// 部门状态
export type DeptStatus = 0 | 1;  // 0:正常 1:停用

// 岗位状态
export type PostStatus = 0 | 1;  // 0:正常 1:停用
```

### 重要说明

1. **默认值**：所有状态字段的数据库默认值必须为 `0`
2. **前端表单**：新增时默认选中状态为 `0`（启用状态）
3. **状态显示**：前端显示时，`0` 显示为正面状态（绿色），`1` 显示为负面状态（红色）
4. **API传参**：状态字段使用数字类型 `0` 和 `1`，不使用布尔值
5. **扩展性**：如需新增状态值，必须通过架构评审，保持向后兼容

// 前端类型定义
interface BaseResponse<T = any> {
  code: number;         // 业务状态码
  message: string;      // 消息提示

### 分页参数

**重要：所有列表查询API必须使用统一的分页参数名称和计算逻辑**

```typescript
// 前端：统一参数名称（从1开始）
interface PageParams {
  current: number;    // 当前页码，从1开始
  pageSize: number;   // 每页条数
}
```

```go
// 后端：统一请求结构（必须使用以下字段名）
type ListRequest struct {
    Current  int `json:"current"`   // 当前页码，从1开始
    PageSize int `json:"pageSize"`  // 每页条数
}

// 统一计算逻辑
offset := (req.Current - 1) * req.PageSize  // PostgreSQL OFFSET
limit := req.PageSize                       // PostgreSQL LIMIT

// 统一响应结构
type PageResponse struct {
    List     []interface{} `json:"list"`
    Total    int64         `json:"total"`
    Current  int           `json:"current"`
    PageSize int           `json:"pageSize"`
}
```

**分页参数处理规范：**

1. **参数名称统一**：所有API必须使用 `current` 和 `pageSize`，不得使用 `pageNum`、`pageNo`、`limit` 等其他名称
2. **默认值处理**：`current` 默认为 1，`pageSize` 默认为 10
3. **参数验证**：`current` 必须 ≥ 1，`pageSize` 建议 1-100 之间
4. **计算逻辑**：`offset = (current - 1) * pageSize`，这是固定的计算方式
5. **响应格式**：必须返回 `current` 和 `pageSize` 字段，与请求参数保持一致

**错误示例（禁止使用）：**
```go
// ❌ 错误：使用了不一致的参数名
type BadRequest struct {
    pageNum  int  // 应该使用 current
    pageSize int
}
offset := (req.pageNum - 1) * req.pageSize  // 计算逻辑错误
```
