# 数据库迁移目录

此目录包含 XingRan-Next 项目的数据库迁移文件。

## 迁移策略

项目采用 **GORM AutoMigrate + SQL 初始数据** 的混合策略：

### 1. 表结构创建 (GORM AutoMigrate)
项目启动时自动执行，根据 Go models 创建表结构：
```go
// internal/core/core.go:132
if err := c.DB.AutoMigrate(); err != nil {
    log.Fatalf("数据库迁移失败: %v", err)
}
```

### 2. 初始数据导入 (SQL 文件)
手动执行 SQL 文件导入菜单、字典等初始数据。

## 目录结构

```
migrations/
├── README.md                    # 本文件
├── init/                        # 初始数据（新环境必需）
│   └── README.md                # 初始数据导入指南
├── archive/                     # 历史迁移归档（新环境不需要）
│   ├── README.md                # 归档说明
│   └── *.sql                    # 修复类迁移文件
└── *.sql                        # 功能迁移文件（按需执行）
```

## 新环境部署步骤

### 1. 创建数据库
```bash
createdb -U postgres xingran_next
```

### 2. 启动应用（自动创建表结构）
```bash
./xingran-backend
```

### 3. 导入初始数据
详见 `init/README.md`。

## 文件分类

| 类别 | 位置 | 说明 |
|------|------|------|
| 初始数据 | `init/` | 新环境必需的菜单、字典等数据 |
| 功能迁移 | `*.sql` | 新功能的数据结构变更（100+编号） |
| 历史修复 | `archive/` | 修复历史问题，新环境不需要 |

## 迁移文件规范

### 编号规则
- `000-099`: 核心功能和初始数据
- `100-199`: 高级功能（RPA、API密钥等）
- `fix_*.sql`: 已移至 archive/

### 命名约定
- `add_*`: 添加新功能
- `create_*`: 创建新表
- `init_*`: 初始化数据
- `drop_*`: 删除旧结构（已归档）
