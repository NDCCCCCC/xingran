# Phase quick-260814-164 Plan 01: 修复 RPA Worker 主键 NULL + 菜单祖先补全 N+1 Summary

修复两个独立后端缺陷：RPA Worker 自动注册 SQLSTATE 23502 (id NOT NULL) 与 my-menus 系列接口 N+1 累计超时 (500 / context canceled)。

## What Built

### Task 1 — RPA Worker 注册主键 NULL 修复 (commit f0d0a1f)

**根因：** `worker_service.Register` 用原生 SQL INSERT + ON CONFLICT DO UPDATE，绕过 GORM Create 钩子链（`Worker.BeforeCreate` / `BaseModel.BeforeCreate` 显式赋 UUID 均不触发），且 INSERT 列清单未带 `id`，而 `sys_rpa_workers.id` 当初由 legacy SQL 建表无 DEFAULT → PG 收到 NULL → 23502。

**修复（A1 代码层 + A2 列 DEFAULT 根治层）：**
- **A1** `worker_service.go`: INSERT 列清单首位加 `id`，VALUES 首位加 `gen_random_uuid()`；占位实参顺序数量不变（gen_random_uuid 是 SQL 内嵌函数）。注释说明为何必须显式写入。
- **A2** `migration_205_rpa_worker_id_default.go` (新建): 仿 Migrate204 模式，`isPostgreSQL` 守卫 + 幂等 `ALTER TABLE sys_rpa_workers ALTER COLUMN id SET DEFAULT gen_random_uuid()`（SET DEFAULT 本身幂等）。
- **A2 注册** `database.go`: AutoMigrate postgres post-block 内、Migrate204 调用之后追加 Migrate205 调用，错误非阻断（与 175/176/202/203/204 一致）。

### Task 2 — 菜单祖先补全 N+1 消除 (commit 4c2a900)

**根因：** `appendAncestorMenuIDs` 经 `collectAncestors` 对每个 menuID 逐层 `SELECT id, parent_id FROM sys_menu WHERE id=?` —— N 起点 × 每链 K 层 = O(N·K) 次主键查询，叠加 dev DB 单查询慢，累计超请求超时 → my-menus 系列接口 500 / context canceled。

**修复：** 改为一次 `Model(&models.Menu{}).Select("id, parent_id").Find(&rows)` 全量载入（菜单表通常几十~几百行），归一为 `map[string]*string`，纯内存上溯。总查询数从 O(N·K) 降为 1。

- 每链独立 `visited` map 防御环路（菜单树理论无环，防御无害）。
- 终止条件与原 `collectAncestors` 一致：parent_id 为 nil / 空串 / key 不存在（已被软删）则停止该链。
- GORM Find 自动带 `deleted_at IS NULL` 软删除过滤，与原 `.First()` 软删除语义一致。
- 查询失败降级返回原始 menuIDs（与原容错语义一致，不阻断主流程）。
- 删除 `collectAncestors`（grep 确认唯一调用方为本函数 + 自递归）。
