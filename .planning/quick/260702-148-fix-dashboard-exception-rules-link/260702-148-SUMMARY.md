### 第 3 轮 — DB 实查揭真相: 把 component 当成了路由路径 (a63e1fdf, 真正修复)
写只读诊断工具直查 sys_menu (cmd/check_exception_menu, 已删), 发现菜单**已在库**
(migration_195 跑过了), 但揭露了被忽视的关键事实:

```
父 "资产管理" path=assets (顶级)        ← menu.path, 不是 component
  ├─ 对账看板     path=dashboard        → 路由 /assets/dashboard
  ├─ 异常列表     path=exceptions       → 路由 /assets/exceptions
  └─ 例外规则管理 path=exception-rules  → 路由 /assets/exception-rules  ← 真实路由!
```

**路由路径 = sys_menu.path 层级拼接 (routeGenerator.resolvePath), 与 component 字段无关。**
`asset/reconciliation/exception-rules/index` 是 **component 模块路径**(懒加载哪个 tsx),
不是路由! 第 1 轮我把 href 改成的 `/asset/reconciliation/exception-rules` 是**错的**——
把 component 路径当路由用了。而**最初的 `/assets/exception-rules` 其实是对的**,
只是当时菜单未 seed 所以不工作。

第 3 轮修复: href 改回真实路由 `/assets/exception-rules` (保留 `<Link>`)。
