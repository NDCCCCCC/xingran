# Quick 261102-m94: 用户偏好「省略即不修改」修复与主题风格 CHECK 约束冲突

**修复 PostgreSQL 上「保存暗色模式失败」（`new row for relation "sys_user_preference" violates check constraint "chk_theme_style"`，SQLSTATE 23514）：服务层把「请求未携带」误当「显式置空」，写出空字符串撞上 CHECK 约束。**

## 根因

前端自 Phase 65 移除多主题后不再发送 `themeStyle`；后端 DTO 用普通 `string` 接收该字段，`omitempty` 让省略字段跳过校验并留下空字符串；`UpdateUserPreferences` 的 UPDATE 分支用 `map[string]interface{}` 显式写出 `"theme_style": ""`，把「请求未携带该字段」误当成「显式置空」写库。PG 上该列带 `chk_theme_style` 约束且不允许空串，于是 500。

本地 SQLite 不复现有两个叠加原因：SQLite 分支走 GORM AutoMigrate 建表（不生成 CHECK 约束），失败表现为「静默写空串」而非报错；Create 分支因模型 `default:minimal` tag 让 GORM 省略零值字段、侥幸由数据库填默认值。**只有 PG + UPDATE 路径会炸。**

## Accomplishments

- **服务层「省略即不修改」**：请求字段为零值表示「本次未携带」。Update 分支（已有行）兜底取该行当前值并原样写回（幂等 no-op，不丢用户已有偏好）；Create 分支（无历史行）兜底取规范默认值。落库前统一走「合并 + 允许集合自检」，越界值一律替换为规范默认值 —— 服务层在任何输入下都不写出越界值。
- **绑定标签与数据库约束逐字对齐**：`themeStyle` 的 oneof 列表移除数据库 CHECK 从未允许过的历史遗留值；`pageSize` 由 `required,min=5,max=100` 收紧为 `required,oneof=5 10 20 50 100`。两处原本能过绑定却必然 500 的请求，现在确定返回 400。
- **GET 侧自检**：`GetUserPreferences` 对历史行里残留的越界值（如 SQLite 上被本 bug 写入的空串）替换为规范默认值返回，API 响应永不返回越界值。
- **迁移 233**：双方言通用语法、幂等、表不存在时 no-op 的数据归一化迁移，PG 与 sqlite 分支各注册一处。
- **三层回归测试**：服务层 5 条（省略保留 / Create 默认值 / 显式生效 / 越界不落库 / 反射锁定允许集）、HTTP 层 3 条（前端真实形态 200、越界主题风格 400、pageSize=30 400）、迁移层 3 条（归一化 / 幂等 / 无表 no-op）。
