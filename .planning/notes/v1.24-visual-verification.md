## 1. 验证方法与口径

### 1.1 为什么必须上真实浏览器（Phase 76 静态断言的盲区）

Phase 76 的断言跑在 **file:// 静态 harness** 上，fixture 是手写的 class 组合，**没有 antd 组件参与**，因此漏掉了 3 件真事：

1. **antd 6 的 affix wrapper 真实 class 组合** = `ant-input-affix-wrapper` **+** `ant-input-textarea-affix-wrapper`（TextArea 同时带两者，源 `@rc-component/input/es/BaseInput.js:79` `affixWrapperCls = clsx('${prefixCls}-affix-wrapper', …, classNames.affixWrapper)`）；
2. **antd 6 的 status class 落点是 `ant-input-status-error`**（落在 wrapper 上），**不是** `ant-input-affix-wrapper-status-error`；
3. **antd 6 的暗色算法不覆盖显式 token**（F3），以及 **`--input-bg` 被就地重定义 3 次**（VIS-04 已登记）导致暗色输入框仍是浅底。

### 1.2 真实浏览器环境事实（本次实测踩到的坑，供后续复用）

| 事实 | 说明 |
|---|---|
| **headless Chrome 默认 `document.hasFocus() === false`** | ⇒ `:focus` 伪类**不生效**、`:focus-within` 生效 ⇒ 直接测焦点环会得到「无环」的假阴性。**必须**用 CDP `Emulation.setFocusEmulationEnabled` 开焦点模拟（`document.hasFocus()` → true，`:focus` 生效）。 |
| **focus emulation 不跨 CDP session** | 用 `agent-browser eval` 会另开 session ⇒ 模拟失效。**必须在同一个 CDP 连接里「开模拟 → 立刻求值/截图」**（本 phase 的 `cdp-page.js` / `cdp-run.js` 即为此）。 |
| **焦点环有 0.15s 过渡动画** | 聚焦后立即读 `getComputedStyle` 会读到插值中间态（如 `rgba(233,239,235,0.176) 0 0 0 0.352px`）⇒ **必须等 ≥450ms 再取样**。 |
| **antd 6 仍会加 `ant-input-affix-wrapper-focused` class** | `@rc-component/input` 注释写「Not used, but keep it」，但 **antd 自身在聚焦时会加上** ⇒ 项目 `index.css:920` 的 `.ant-input-affix-wrapper-focused` 规则**确实生效**（它是焦点环的真实来源）。 |

### 🟡 P2-1 —— `index.css:2084-2108` 的 `.dept-tree-search` 规则是**死规则**

### 🟡 P2-2 —— antd 6 中 `<Form.Item status="error">` **不是有效 API**

antd 6.6.4 的 `Form.Item` 类型定义只有 `validateStatus?: ValidateStatus`（`node_modules/antd/es/form/FormItem/index.d.ts:30`），`status` prop 未被 `StatusProvider` 消费 ⇒ `<Form.Item status="error">` **完全无效**（静默忽略）。
**实测**：harness 的 4 个 `<Form.Item status="error">` 控件的 class 里 **没有** `ant-input-status-error`；改用真实校验错误（`rules:[{required:true}]`）或 `validateStatus="error"` 后 class 正常出现。
**建议**：本仓若有代码用 `<Form.Item status=...>`，应改 `validateStatus`（本次全仓检索未在业务页发现该用法，仅测试夹具用到）。

### 🟡 P2-3 —— InputNumber 错误态边框不变红（登记册 #16 已知欠账）

实测 `input-number-err` 边框仍 `rgb(219,215,206)`；`.ant-input-number` 被 `index.css:872-875` 的 `border: ... !important` 简写锁死。
**建议**：v1.25 方案 C 一并收敛（登记册已列 #16）。

### 🟡 P2-4 —— 既有 antd 6 API 弃用警告（与本 phase 无关，但会污染 console 巡检基线）

`onSearch` → `showSearch`（Select/TreeSelect/Cascader）、`Modal maskClosable` → `mask.closable`。
**建议**：单独开小 phase 清理，否则后续「无新增 console error」无法自动化判定。
