# UAT 执行排期计划（v1.56 候选）

> **本环境无生产 PG 写授权、无真机，只能排期不能执行。**
> 本文件只做分类、排优先级、给解锁路径；**不执行任何验证、不预填判定、不勾选任何条目**。
> 79 条跟踪表（`.planning/notes/261108-human-verification-tracker.md`）逐条已补
> `owner（角色） / 计划窗口（W1~W4 相对周次） / 前置授权 / 证据落盘格式`，
> 状态统一为 **「已排期·待执行」**，**0 勾选 / 0 已完成**（见 §五 自检口径）。
> 状态定义与收档门槛见 `.planning/notes/SHIPPED-DEFINITION.md`。

## 一、三桶分类（按「能否在本环境执行」划分）

> **逐条实测分布（以 tracker 为准）**：A 可自动化 **16** 条（W1 11 / W2 5）｜B 可现场执行 **56** 条（W1 真机 29 / W2 27）｜C 需生产授权 **7** 条（W3）；合计 **79**。
> 分类依据是**解锁条件**，不是「技术难度」：A 桶里凡需连生产 PG 只读的项，授权未下来前同样只能排期。

## 四、执行与回写纪律（沿用最高纪律）

1. **只能排期不能执行**：本环境无生产 PG 写授权、无真机；本文件与 tracker 的「已排期·待执行」**不是执行结果**。
2. **0 勾选 / 0 已完成**：79 条一律 `- [ ]`（tracker 内为表格状态列，非 checkbox 列亦不得出现「已完成 / 已勾选」）；史实 RESOLVED / 独立证据可核销仅作备注。
3. **AI 边界**：只做文档组织（分类、排期、解锁路径、证据格式），不写生产数据、不切生产认证模式、不代跑 `--apply`、不伪造截图 / 日志 / 勾选、不代 QA 裁定。
4. **证据落盘格式**：统一 `evidence/<条目ID>-<YYYYMMDD>.md`，字段见 `.planning/notes/261108-uat-writeback-policy.md §3.2`（来源 REQ / 执行日期 / 执行人 / 前置授权凭证 / 环境 / 步骤与结果 / 判定 / 证据位 / 回写动作 / 副作用核对）；敏感输出脱敏、凭据不入库。
5. **回写**：人工执行完后在 GSD 产物 / 未来里程碑 UAT 清单把 `- [ ]` 改 `- [x]`，**同处记录** `清偿日期 + 执行人 + 证据位 + 判定`；只有勾选无证据 = 伪造闭环；`blocked` 项保持 `- [ ]` 并登记阻断原因与解锁条件。
6. **收档门槛**：按 `.planning/notes/SHIPPED-DEFINITION.md`，关键 UAT 未通过 + 证据未落盘前，v1.56 候选保持 `code-complete·verification-pending`，不得标 SHIPPED。

## 五、覆盖与自检口径

- **覆盖**：79 条 = VAL-01(2) + VAL-02(7) + VAL-03(3) + VAL-04(29) + VAL-05(37) + VAL-06(1)，逐条在 tracker 中带 `owner / 计划窗口 / 前置授权 / 证据落盘格式` 四字段，状态「已排期·待执行」。
- **合计行**：tracker §二 合计仍为 **79 / 0 已勾选 / 0 已完成**，不变。
- **自检**：`grep -nE '\[x\]|已勾选|已完成' .planning/notes/261108-human-verification-tracker.md` 中，除「0 已勾选 / 0 已完成」合计行与「严禁伪造已完成 / 已勾选」纪律说明外，**不得出现任何条目级勾选 / 完成标记**。
- 本计划与 tracker 的差异：tracker 是**逐条台账**（谁、哪周、要什么授权、证据怎么存），本文件是**全局调度**（三桶优先级、解锁链、窗口分配）。两者都不产生执行结果。
