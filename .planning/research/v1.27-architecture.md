# v1.27 集成测试基建接入架构研究

**模式:** Project Research — ARCHITECTURE(基建接入既有测试体系)
**研究日期:** 2026-08-23
**总体置信度:** HIGH(仓库内模式全部实证;外部库版本 MEDIUM)

## 结论摘要

五个测试替身(miniredis / 嵌入式 LDAP / HTTP mock / SSH fake / 子进程 stub)**全部可做成进程内(in-process)实现,零 Docker 依赖**——因此 ci.yml 单一 `go test` job 无需任何改动即可保持绿,Windows 本地开发同样可跑。核心建议:**沿用 e2e_helpers.go A1 先例(ForTesting 命名后缀 + 无 build tag)不变**,规模增长用"AST 守护测试"治理而非引入 tag;QUIRK 修复采用"翻转断言 + 回归用例 + 原子 commit"五步法,且 **MemoryCache.IncrementBy 必须最先修**(它连锁解锁 core 包 captcha GenerateCaptcha 真实链路)。

## Q1 测试文件组织

| 方案 | CI 影响 | 结论 |
|------|---------|------|
| 同包 `_test.go` 共置 | `go test ./internal/...` 自动执行,覆盖率自动计入 coverage.out → 直接喂 4 层 gate | **采用** |
| `tests/` 独立树 | ci.yml 显式排除 `tests/`(见 ci.yml:52 注释),进了也不被跑、不计覆盖率 | 仅保留既有 login_encryption 遗留,不新增 |
| `//go:build integration` tag | 默认 `go test` 跳过 → 覆盖率损失 + 需第二个 CI job | **不采用**(违背 A1 "每次 go test 全跑"的锁定理由) |

**约定 1:** 集成测试与单测同包共置,文件名沿用 phase-plan 后缀惯例 `<topic>_<phase>_<plan>_test.go`(如 `ldap_client_75_xx_test.go`),与 v1.26 的 `_74_08_test.go` 体系连续。

**约定 2:** 共享测试 helper 放同包 `_test.go` 文件(如 `ldapserver_helper_test.go`)。`_test.go` 内符号生产代码物理不可 import——比 ForTesting 后缀**更强的隔离**,是首选;ForTesting 后缀仅在"跨包需要触达私有字段"时使用(portwrite e2e 先例:需从另一个包构造 device.PooledConnection)。

**约定 3:** 仅当需要黑盒视角(防止测试偷用私有函数)才用 `package xxx_test` 外部测试包;现状仓库全部同包,维持不变。

## Q2 Fixture 生命周期

**现状实证:** TestMain 仅 2 处(`tests/integration` 遗留 + `vdi_server_service_test.go:22` 设 SM4_KEY 环境变量);单测惯用 **per-test helper + t.Cleanup**(如 `newMem(t, 100)`、`newVDITestDB(t)`)。t.Parallel 仅 7 处且全是纯函数测试(operlog regression / models 常量)。

**约定 4:** 替身默认 per-test 实例 + `t.Cleanup`:
- miniredis:`mr := miniredis.RunT(t)`(官方 API,自动清理),构造 `redis.NewClient(&redis.Options{Addr: mr.Addr()})` 接 core 现有 Cache 接口。启动为 µs~ms 级,per-test 成本可忽略。
- 嵌入式 LDAP:`srv := ldapserver.NewServer()` + Bind/Search 路由 handler + `net.Listen("tcp", "127.0.0.1:0")` 随机端口,`t.Cleanup(srv.Close)`。LDAPClient.dialConnection 走真实 wire(ldap.DialURL 到 127.0.0.1)。
- **不用 TestMain 持有共享实例**:共享 server 与 t.Parallel 冲突(包内测试并行时共享状态互踩),且 core.Core 这类重依赖图每次干净构造比共享+重置更可靠(v1.26 教训:coverage 噪声已让 ratchet floor 需 0.4pp 裕量,勿再引入状态噪声源)。
- TestMain 职责保持单一:仅设环境变量(vdi 先例),不管理 fixture。

**约定 5:** t.Parallel 政策维持现状——纯函数测试可加;持有替身/DB 的测试不加(miniredis per-test 实例本身 parallel-safe,但 sqlite :memory: + core 初始化路径未验证并行安全,本期不冒险)。

## Q3 ForTesting 先例 vs build tag(规模化)

**建议:继续 A1(命名后缀,无 tag)。** 论据:

1. A1 的原始理由(54-01-PLAN)是"e2e 每次 `go test ./...` 都跑"——v1.27 的覆盖率目标(≥70% 计入 itest)恰恰**依赖**这一点,tag 会直接拆台。
2. tag 的隔离收益(防生产误用)在 `_test.go` helper 方案下由编译器免费获得;ForTesting 生产符号只剩 2 个真实需求场景(device 包跨包注入)。
3. 治理规模化用仓库既有范式:**AST 守护测试**(仿 `status_constants_test.go`)——扫描生产 .go 文件(非 _test)禁止引用 `*ForTesting` 符号,零依赖纯 Go,bash+awk 同哲学(D-01 精神:用自实现而非引工具)。

**何时才引入 tag:** 出现必须 Docker 的测试(真 PG 方言行為、真 Redis Cluster)。本期没有。

## Q4 QUIRK 修复工作流(D-03)

**五步法(每个 QUIRK 一个原子 commit):**
1. `grep -rn "QUIRK" --glob *_test.go` 定位锁定该行为的测试(当前 43 处注释命中);
2. 翻转断言:删 QUIRK 注释、旧期望改新期望(如 `"" → "S5735-L48T4X-A"`);
3. 补回归用例(同文件,用例名标注重语义,如"行首锚定命中");
4. 跑本包 + 受联动包(`go test ./pkg/cache/... ./internal/core/...`);
5. commit 格式 `fix(quirk-N): <语义> + 回归测试`,SUMMARY 记录生产影响面。

**已知受影响测试清单(实证坐标):**

## Q5 go.mod 布局

**单一主 module,测试依赖直接进主 go.mod。** 理由:
- Go 没有原生 "test-only dependency" 隔离;分 module(如 `internal/agent/go.mod`)会制造 import 边界地狱(rpa-worker 先例是**可部署物**才分,module)。
- v1.27 D-02 已解锁"测试专用 devDependencies"——在 require 行加注释 `// test-only (v1.27 D-02)` 标记即可,grep 可审计。
- **tools directive 不需要**:不引入 CLI 工具链(golangci-lint 走 action 版本锁定)。

新增依赖预估:`github.com/alicebob/miniredis/v2`(v2.3x,go-redis v9 官方兼容,MEDIUM 版本号置信)+ `github.com/vjeantet/ldapserver`(近期仍有 pseudo-version 提交,libraries.io 显示 v1.0.2-0.2026x;备选 cloudogu 维护的 fork)。两者均纯 Go、无 CGO、跨平台。

## Q6 CI 策略

**约定 6:全部替身进程内化,CI 零改动。** 各包注入点(实证):

| 阻塞包 | 替身 | 注入点(已验证) | 新文件 |
|--------|------|----------------|--------|
| core(754)+ pkg/cache Redis 路径 | miniredis | Cache 接口实现换 Addr | `internal/core/redis_itest_<plan>_test.go` |
| addomain(2415) | 嵌入式 LDAP server(127.0.0.1:0) | `ADConfig` host/port 指向随机端口,LDAPClient.dialConnection 真实 wire | `internal/services/addomain/ldapserver_helper_test.go` |
| operations(3714) | httptest + RoundTripper | **geocoding_service.go:88 已有可注入 httpClient 构造器**——注入自定义 RoundTripper 拦截 `api.map.baidu.com` 请求返回罐头 JSON,**零业务改动** | `internal/services/operations/geocoding_itest_<plan>_test.go` |
| device(1249) | scrapligo FileTransport(已验证于 portwrite e2e,10+11 个 TestE2E_*) | 扩展 ForTesting 工厂家族(`NewPooledConnectionForTesting` 先例) | 复用 `internal/device/e2e_helpers.go` 模式 |
| agent-server(616) | TestHelperProcess 再执行模式(`os.Args[0] -test.run=TestHelperProcess`) | subprocess.go 的 cmd 构造点 | `internal/agent/server/subprocess_stub_test.go` |

**子进程 stub 跨平台警告(实证):** 现有 `subprocess_pgroup_test.go` 直接 `exec.Command("echo")`——Windows 上 echo 是 shell 内建无独立 exe,这正是 P2_RATCHET 注释记录的 agent-server "env-branch divergence"(本地 22.08% vs CI 19.48%)来源之一。新 stub 一律用 TestHelperProcess 再执行模式(可移植,Go 官方惯用法),不依赖平台二进制。

**若未来引入 Docker 级测试:** 单独 CI job(仿 coverage-diff 的 PR-only 模式)+ env guard `XINGRAN_ITEST=1` + 测试开头 `if os.Getenv("XINGRAN_ITEST") == "" { t.Skip }`,主 backend job 永不接触 Docker。`-short` flag 方案不推荐(语义被"快速单测"占用,易误触发)。

**覆盖率联动:** itest 自动计入 coverage.out → 4 层 gate(check-coverage.sh 的加权 + P1/P2 floor)与 diff-coverage ≥80% 无需改脚本;5 包过 70% 后按既有"删除 P2_RATCHET 条目"流程收口 floor。
