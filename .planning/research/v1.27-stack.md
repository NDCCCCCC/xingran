## 1. Redis test double → miniredis/v2

### 代码库事实（本地实证）
- `pkg/cache/redis.go` 全文使用**具体类型 `*redis.Client`**（go-redis `v9.7.0`）：字段(:25)、`scanKeys`(:219)、`getClient() *redis.Client`(:1010)、`GetRedisClient()`(:1072) —— mock-接口方案需大改生产代码，直接排除。
- 实际用到的命令（grep 全量核对）：`PING / DEL / MGET / MSET / INCR / INCRBY / EXPIRE / TTL / HGET / HSET / HGETALL / FLUSHDB / SCAN(游标循环 COUNT=500)`（`Keys` 经 SCAN 实现, :223）+ `IncrementWithExpire` 的 Incr+Expire 组合；`internal/core/core.go:798` `cache.NewRedisCache(cacheConfig, "xingran")` 在 Init 链路内构造。
- 多级缓存 `MultiLevelCache` L1=memory + L2=redis，`MGetJSON/MSetJSON` 走 MGet/MSet。

### 决策矩阵
| 方案 | 结论 | 依据 |
|------|------|------|
| **miniredis/v2** ✅ | 上述**全部命令均在 README 实现清单内**（SCAN/KEYS/EXPIRE/TTL/INCR/HSET/HGETALL/MGET/MSET/FLUSHDB/MULTI-EXEC-WATCH 均 support） | 官方 README 全文核对（HIGH）。真 TCP 端口，`redis.NewClient(&Options{Addr: mr.Addr()})` 直连，**不改任何生产代码**。纯 Go、无 Docker、Windows/CI 同构。`RunT(t)` 自动清理；`FastForward(d)` 推进 TTL；`mr.Set/HSet/Exists` 可直接断言。维护活跃（v2.36.0 release 2026-01，pkg.go.dev 已收录 v2.38.0），与 go-redis v9 官方组合是社区事实标准。集成测试对标 Redis 8.4 + RESP3。 |
| go-redis/redismock ❌ | **硬淘汰**：依赖 go-redis **v8**、未跟进 v9 —— 本库 v9.7.0 无法使用 | web 验证（MEDIUM-HIGH） |
| elliotchance/redismock | 依赖 testify mock + 需接口化改造；本库具体类型使然不适用 | web 验证（MEDIUM） |
| testcontainers-redis | 真 Redis 保真度最高，但强制 Docker → Windows 开发机 `go test ./...` 断裂，违背 A1「所有测试随处可跑」纪律 | 官方模块存在（HIGH），不采纳 |

### 已知限制（README 明示，均不影响本库）
- TTL **不会自动递减**，过期类测试需 `mr.FastForward(d)`（写 TTL 断言时必记）。
- 不支持 `CLIENT * / CONFIG * / MONITOR / CLUSTER 管理` 等 —— 本库未使用。
- Lua EVAL 需内建支持（已含）；无影响。

**用法骨架：** `mr := miniredis.RunT(t)` → config 指向 `mr.Addr()` → 走真实 `NewRedisCache`/`Core.Init` 链路。

## 2. LDAP test double → 扩展既有接口 stub（嵌入式 server 仅作补充线）

### 代码库事实（本地实证）
- `internal/services/addomain/ldap_iface.go` **已有** `LDAPClientIface`（18 方法：Connect/Close + 4 搜索 + 组成员/组 CRUD + 用户属性/Move/Enable/Disable）+ 编译期断言 `var _ LDAPClientIface = (*LDAPClient)(nil)` + 既有 `ldap_client_mock_test.go`。
- 体量：`ldap_client.go` 527 行 / `account_pool.go` 582 行 / `failover_client.go` 119 行；`FailoverClient` 消费 `AccountPool`+LDAPClient，`AccountPool` 走 DB 行锁（glebarez sqlite 已可测）。
- go-ldap 版本 `v3.4.12`。

### 关键验证结论（本地 module-cache 实证，HIGH）
- **go-ldap v3.4.12 不自带任何 test server / ldaptest 包**（模块目录逐文件核对：仅 client 侧 add/bind/conn/search/...）。训练数据中的"ldaptest 包"假设**证伪**。
- Go 生态**无维护活跃的纯 Go 嵌入式 LDAP server 库**：`vjeantet/ldapserver`（nmcclain/ldap 的 fork）数年未更新、pkg.go.dev 标注 "work in progress"，lldap/glauth 均维护私有 fork（web 验证，MEDIUM）。`scribd/go-testslapd` 是 Docker 封装 → 同 Windows 约束。

### 决策矩阵
| 方案 | 结论 |
|------|------|
| **扩展 LDAPClientIface mock（主推）** ✅ | 零新依赖、模式已在库内验证（P2-A6 已把 group_sync/user_ou 关键路径打到 ≥70%）。补齐方向：补全 mock 缺失方法（walk/paging 语义）+ 覆盖 `FailoverClient` 顺序遍历/`maxHops`、`AccountPool` 熔断状态机（DB+iface 即可）、`LDAPClient` 参数组装/错误分支中不触网的部分。 |
| vjeantet/ldapserver 嵌入式 wire server（补充线，MEDIUM） | 若要覆盖 `*LDAPClient` 具体实现的 Bind/Search-with-Paging（PagedResultsControl）真实报文路径：唯一纯 Go 进程内选项。协议本身（LDAPv3）冻结，库虽停更但风险可控；需自写 Bind/Search handler（约 100-200 行）。**建议先做 stub 线，wire 线按 70% 缺口决定是否引入**。 |
| testcontainers-openldap / go-testslapd ❌ | Docker 强依赖，Windows 断裂，不采纳 |

**注意：** milestone 目标特性里写的"嵌入式 LDAP server"按上述证据修正为「优先接口 stub；嵌入式 server 为 vjeantet/ldapserver 备选」， REQUIREMENTS 落 INFRA 条目时按此措辞。

## 4. HTTP mock（operations）→ httpmock（geocoding）+ httptest.Server（其余）

### 代码库事实（本地实证）
- `geocoding_service.go`：URL 是 **`const baiduGeocodingAPIURL = "https://api.map.baidu.com/geocoding/v3/"`**(:24)，两个构造器均硬编码 `&http.Client{Timeout:...}`，**无注入点**（:76-90）；请求 `http.NewRequestWithContext` GET(:311)。
- 关键推理：`&http.Client{}` 的 `Transport==nil` → 默认走 `http.DefaultTransport` → **httpmock 拦截 DefaultTransport 即可命中，无需任何生产代码改动**（不改 const、不加注入点）。
- handlers 侧（Excel 上传等）repo 已广泛使用 httptest。

### 决策矩阵
| 方案 | 结论 |
|------|------|
| **httpmock（外部 API 路径）** ✅ | `jarcoal/httpmock`：**官方声明支持 Go 1.16–1.27**（1.24 在列，HIGH），维护中（v1.4.x；Debian 2025-12 仍在跟进打包）。`httpmock.Activate()` 全局换 DefaultTransport + 按 URL/METHOD 注册 Responder，完美匹配 const-URL 现状；`ResponderFromMultipleResponses` 可测限流重试序列。 |
| **httptest.Server（可注入场景）** ✅ 并用 | stdlib 零依赖；凡 httpClient/baseURL 可注入（新代码或轻量测试缝）一律优先 httptest。operations handler 层继续沿用。 |
| h2non/gock ❌ | 社区证据为休眠/停滞（多年无 release、issue 悬置，MEDIUM），同能力下选 httpmock。 |

### httpmock 使用纪律（写进 INFRA 要求）
- 全局 DefaultTransport 拦截 ⇒ 每个测试必须 `defer httpmock.DeactivateAndRestore()`（或 `httpmock.NewMockTransport` 挂到独立 client 上实现并行测试隔离，二者择一成文）。
- 需要直连真实网络/httptest 的用例不得与 Activate 状态交叠。

## 5. 子进程 stub（agent/server & Core.Init reaper）→ stdlib re-exec 模式，零新依赖

### 代码库事实
- `internal/agent/server/subprocess.go`：`exec.CommandContext`(:14/:21/:29) + `SysProcAttr` 平台分支（`sysproc_linux.go` Pdeathsig/Setpgid vs `sysproc_windows.go`）；已有 `subprocess_pgroup_test.go` 先例。
- `core.go` Init 链(:196-) 含 scheduler 注册、RPA、子进程 reaper(:233)。

### 推荐（HIGH，官方文档模式）
- **`os.Args[0]` 自身 re-exec 模式**（Go 官方 `os/exec` 包文档原生的 TestHelperProcess 模式）：测试内 `exec.Command(os.Args[0], "-test.run=TestHelperProcess", "--", args...)` + `cmd.Env = append(os.Environ(), "GO_WANT_HELPER_PROCESS=1")`，helper 函数内按 env 分支模拟 常驻/秒退/忽略 SIGTERM/输出大量 stdout 等进程形态。
- Windows 兼容：`os.Args[0]` 即测试二进制 .exe，re-exec 天然跨平台；仅 pgroup/SysProcAttr 断言按平台分支（沿用现有 sysproc_*.go 拆分）。
- Core.Init 的测试策略 = miniredis(#1) + glebarez sqlite + re-exec stub（reaper）+ scheduler 以极短 interval 配置驱动，不需要任何新库。

## 6. testcontainers-go → 不作为本 milestone 依赖

| 判据 | 结论 |
|------|------|
| 能力 | 官方 Redis 模块齐备（golang.testcontainers.org/modules/redis），真保真度最高（HIGH） |
| Windows 开发机 | 需 Docker Desktop/WSL2 —— **不可假设每台开发机具备**；一旦引入，本地 `go test ./...` 出现环境性 FAIL，破坏 v1.26 D-04「0 FAIL」与 74-07 A1「随处可跑」纪律 |
| CI | ubuntu-latest 有 Docker，可用 —— 但**双环境不同构**会让「CI 绿 ≠ 本地绿」 |
| 替代组合覆盖度 | miniredis + iface-stub + FileTransport + httpmock + re-exec 已覆盖 5 个阻塞包全部声明的命令面 → **收益不足以抵环境成本** |
| 何时重开 | 未来若需「真 Redis 连接池行为 / 真 OpenLDAP 报文」的 smoke 层，以 **CI-only job + build tag（如 `//go:build smoke`）+ 本地自动 skip** 引入，不进默认测试面 |
