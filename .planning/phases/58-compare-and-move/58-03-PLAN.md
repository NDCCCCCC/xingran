# F-11 dead 判定的具体方向（planner 决策，锁定）

禁令原文：**排水器禁止裸 `attempts` 判 dead**（合并子句 `ad_push_queue_service.go:161-169` 每次编辑清零 `attempts`）。

落地口径（planner 在 RESEARCH Q1 的 (c) 方向上收紧）：
1. `attempts` 语义即"自上次编辑以来的连续失败次数" —— 合并清零让它天然只计连续失败，因此它**是**正确的连续失败计数器，不需要新列（避免与"最小动作行"精神冲突）
2. 但判定**只能**发生在本轮实际失败的分支内：`attempts+1 >= maxDrainAttempts` 才转 dead。禁止在拾取阶段、成功分支、或任何非失败路径上读 `attempts` 判死
3. 由此 `attempts=5` 的行若本轮成功必须转 `pushed`（不是 dead）
4. 已知并接受的后果：用户持续编辑某个持续失败的属性时，每次编辑清零 attempts，该行永不终态 —— 这是"编辑即续命"的有意设计（用户还在管这件事），必须写进函数注释并在 SUMMARY 记录
5. 不可恢复错误（code 32 / 配置无匹配 / 用户已不存在）**直接** dead 且不烧 attempts，与上述路径分离

## 4) `DrainOnce(ctx context.Context) error`

```
// DrainOnce 执行一轮排水（D-05）。cron 与手动触发共用本入口，互斥在内部统一处理。
// 返回 error 只表示"本轮基础设施层失败"（如查库失败），行级失败一律写回队列状态、不上抛。
func (d *ADPushDrainer) DrainOnce(ctx context.Context) error {
	if !d.mu.TryLock() { // 上一轮未结束，本轮跳过（30s 间隔下单轮可能超 30s）
		applogger.Debugf("[ad_push_queue] 上一轮排水未结束，本轮跳过")
		return nil
	}
	defer d.mu.Unlock()
	now := d.now() // 一轮一次，全轮透传（P8）

	rows, err := d.pickRows(ctx, now)
	if err != nil {
		return fmt.Errorf("拾取待排水行失败: %w", err)
	}
	if len(rows) == 0 {
		return nil
	}

	// 按解析出的 AD 配置分组（P12：每组一次 ExecuteWithFailover，而不是每行一次 bind）
	groups, deadRows, err := d.groupByResolvedConfig(ctx, rows)
	if err != nil {
		return fmt.Errorf("解析 AD 配置分组失败: %w", err)
	}
	// deadRows 只含"单用户匹配不到配置 / 无 ad_dn / 用户已不存在"三类；
	// "全局零启用配置"在 groupByResolvedConfig 内部已 defer 成空结果，不会走到这里。
	for _, row := range deadRows {
		// 不可恢复分支**不烧 attempts**：传 row.Attempts 原值写回（不 +1）
		d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:no-ad-config")
	}
	for cfgID, group := range groups {
		if err := d.executeGroup(ctx, cfgID, group, now); err != nil {
			applogger.Warnf("[ad_push_queue] 配置组 %s 本轮执行异常: %v", cfgID, err)
		}
	}
	return nil
}
```

- `markPushed(ctx, id string, now time.Time) error`：`Updates({status: pushed, pushed_at: now, next_retry_at: nil, last_error: "", failed_at: nil})`。⚠ `next_retry_at`/`failed_at` 要显式写 `nil`（清空）——用 `map` 形式而非 `struct` 形式，否则零值语义混乱
- `markFailed(ctx, row models.ADPushQueue, now time.Time, poolExhausted bool, msg string) error`：
  `newAttempts := row.Attempts + 1`；若 `!poolExhausted && newAttempts >= maxDrainAttempts` → 转 `markDead(ctx, row.ID, now, newAttempts, "dead:max-attempts")` 并返回（⚠ **传 newAttempts**：本次失败已计入连续失败计数，DB 必须落到 5，否则 `TestPhase58_Drain_MaxAttemptsGoesDead` 的 `attempts == 5` 不可达）；否则 `Updates({status: failed, attempts: newAttempts, next_retry_at: now.Add(backoffDuration(newAttempts)), failed_at: now, last_error: msg})`

  ⚠ 每次更新显式带 `"updated_at": now`
- `markDead(ctx, id string, now time.Time, attempts int, reason string) error`：`Updates({status: dead, attempts: attempts, next_retry_at: nil, failed_at: now, last_error: reason})`。

  ⚠ **`attempts` 必须显式入参**（否则达上限用例断言 `attempts == 5` 不可达）：本轮失败的第 5 次在 `markFailed` 里算出的 `newAttempts = row.Attempts + 1` 必须落到 DB；不写 attempts 时 DB 仍是 4，`TestPhase58_Drain_MaxAttemptsGoesDead` 的 `attempts == 5` 断言必红。
  两条调用口径：
  - **不可恢复分支**（code 32 / 配置无匹配 / 无 ad_dn / 用户不存在 / 未知 action / OU 映射缺失）传 `row.Attempts`（**不 +1**，D-05「不可恢复不烧 attempts」）；
  - **达上限分支**（`markFailed` 内 `newAttempts >= maxDrainAttempts`）传 `newAttempts`。

  语义等价性说明：不可恢复分支传原值写回 = "本轮没有为该行贡献一次新的连续失败计数"，与 `updates` 显式写原值同义；达上限分支传新值 = "本次失败已计入计数"。两者的差别只在**计数语义**，终态一律 dead。
  注释写清 reason 的可 grep 前缀约定：`unrecoverable:*` / `dead:*` / `retry:*` / `pool:*`

## 1) `drainRow(ctx, c LDAPClientIface, row models.ADPushQueue, cfgID string, now time.Time)` —— 行的处理

⚠ 本 Task 只做 `disable` 与 `update_user` 的**属性**部分；**OU 移动是 Plan 04 的内容**，本处留一个明确标记：`// Phase 58 Plan 04: 此处补 compare-and-move OU 移动分支`（不是 TODO 猜测，是给后续 plan 的接口位）。⚠ 标记行的**上方**是完整可用的属性路径（含 reload 判空 → dead），下方才是 Plan 04 的插入位 —— 骨架两侧都必须能独立通过本 task 的用例。

```
// drainRow 处理单行。⚠ 行级错误一律写回队列状态、绝不上抛（P1：上抛会触发
// FailoverClient 换账号重跑整组 + MarkFailure 累加熔断）。
// ⚠ Phase 58 revision：签名已含 cfgID，与 Plan 04 T2 终稿**同一形态** —— Plan 04 只把
//   标记行替换为真实 compareAndMoveOU 调用，不再动签名与调用点。
func (d *ADPushDrainer) drainRow(ctx context.Context, c LDAPClientIface, row models.ADPushQueue, cfgID string, now time.Time) {
	user, err := d.loadUserUnscoped(ctx, row.EntityID)
	if err != nil {
		if errors.Is(err, gorm.ErrRecordNotFound) {
			d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:user-not-found") // F-07 孤儿，与 code 32 同一条分支；不可恢复 → 不烧 attempts（传原值）
			return
		}
		d.markFailed(ctx, row, now, false, "retry:读取用户失败 "+err.Error())
		return
	}
	if user.AdDn == nil || *user.AdDn == "" {
		// 不可恢复：⚠ 不可当成成功（否则 Phase 59 守卫误判"无待推送 → 一致"）
		d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:no-ad-dn")
		return
	}

	switch row.ActionType {
	case models.ADPushActionDisable:
		// UAC 514 Replace，幂等可重放；禁 delete AD 账号（Phase 57 D-04 红线）
		if err := c.DisableUser(*user.AdDn); err != nil {
			d.handlePushError(ctx, row, now, err, "disable")
			return
		}
		d.markPushed(ctx, row.ID, now)

	case models.ADPushActionUpdateUser:
		updateReq := buildDrainUpdateReq(user) // 见下
		// 属性推送（复用 syncUserAttributes：DNExists 预检 + code 32 清 ad_dn 已封装）
		if err := d.adSync.syncUserAttributes(ctx, c, user, updateReq); err != nil {
			d.handlePushError(ctx, row, now, err, "update_user")
			return
		}
		// ⚠ syncUserAttributes 在 DNExists=false 时清空 ad_dn 后 **return nil**（不报错）。
		//   故必须重新 loadUserUnscoped 判空：目标在 AD 端不存在时终态是 dead 而不是
		//   pushed（QUEUE-05）。缺这一步 → TestPhase58_Drain_DNExistsFalseIsDeadNotPushed 必红。
		if refreshed, err := d.loadUserUnscoped(ctx, row.EntityID); err == nil {
			if refreshed.AdDn == nil || *refreshed.AdDn == "" {
				d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:target-not-found") // 不烧 attempts
				return
			}
			user = refreshed
		}
		// Phase 58 Plan 04: 此处补 compare-and-move OU 移动分支
		d.markPushed(ctx, row.ID, now)

	default:
		d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:unknown-action")
	}
}
```

⚠ `syncUserAttributes` 有两条不同的失败路径，必须区分：
- `DNExists` 返回 false → 它**清空 ad_dn/ad_ou_dn/ad_synced_at 后 return nil**（不报错）→ 若直接 markPushed 会把"目标在 AD 端不存在"误报成功。**已在上方骨架内实现**：`syncUserAttributes` 返回 nil 后重新 `loadUserUnscoped` 一次，若 `user.AdDn` 已变空 → 说明是 not-found 路径 → 转 `markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:target-not-found")`（⚠ 四参 + `row.Attempts` 原值，不烧 attempts；省略 attempts 会违反本 plan 的 markDead 契约断言）。代码注释须写清它为什么必要（DN 已被清空 = 目标在 AD 端不存在，终态不是成功）
- 返回 `ErrADTargetNotFound`（modify 阶段 code 32）→ 直接 dead（走 `handlePushError` 的第 1 分支）

⚠ **骨架一致性（Phase 58 revision 澄清）**：上方 `drainRow` 骨架的 update_user 分支已是 **reload → 判空 → dead → compareAndMoveOU 接口位注释 → markPushed** 的形态，与 `58-04` Task 2 的终稿骨架**逐行同构**。Plan 04 只需把 `// Phase 58 Plan 04: 此处补 compare-and-move OU 移动分支` 替换为真实的 `compareAndMoveOU` 调用 + `if terminal { return }` 守卫。⚠ 若本 plan 的骨架停在 "syncUserAttributes 成功后直接 markPushed"，则同批的 `TestPhase58_Drain_DNExistsFalseIsDeadNotPushed`（断言 dead）在 wave 2 必然红 —— 骨架必须自带 reload 判空分支。

## 3) `handlePushError(ctx, row, now, err, action string)` —— 错误分流

```
// 错误分流（QUEUE-05 核心）：不可恢复 → dead 且不烧 attempts；其余 → 退避重试。
func (d *ADPushDrainer) handlePushError(ctx context.Context, row models.ADPushQueue, now time.Time, err error, action string) {
	// 1) 属性路径的哨兵错误（syncUserAttributes 已清空 ad_dn/ad_ou_dn/ad_synced_at）
	if errors.Is(err, ErrADTargetNotFound) {
		d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:target-not-found")
		return
	}
	// 2) LDAP code 32（errors.As 穿透 %w 包装，OU 路径的 code 32 在 Plan 04 复用此分支）
	if ldap.IsErrorWithCode(err, ldap.LDAPResultNoSuchObject) {
		d.clearUserADRefs(ctx, row.EntityID) // 清 ad_dn/ad_ou_dn/ad_synced_at
		d.markDead(ctx, row.ID, now, row.Attempts, "unrecoverable:target-not-found")
		return
	}
	// 3) 账号池熔断（同步面可能直接冒泡到此处）
	if errors.Is(err, ErrAllAccountsUnavailable) {
		d.markFailed(ctx, row, now, true, "pool:"+err.Error())
		return
	}
	// 4) 其余可恢复错误 → 退避重试（死判定只在这里、且只按 attempts+1，F-11）
	d.markFailed(ctx, row, now, false, "retry:"+action+":"+err.Error())
}
```
