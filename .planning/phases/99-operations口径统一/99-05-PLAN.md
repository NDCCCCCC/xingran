# Plan 99-05: V130R-09 CAD 全集专用端点 + 前端消费者迁移

## Context

99-04（wave 1）已将 workstation List 上限收敛为 200（D-03-8）。本计划消除反模式的另一半（D-03-5）：新增楼层全集专用端点（D-03-6/D-03-7），并把全部 CAD/3D/平面图前端消费者从 `workstationApi.list({ pageSize: 1000/10000/500 })` 迁到该端点，前后端测试同步（D-03-9）。

### 路径与注册位置（所有四处表面对齐）

**最终路径：`GET /ops/workstation/:floorId/workstations-all`（workstation 组、单数、:floorId 参数名）。**

依据：
- CONTEXT.md「Specific Ideas」明确路径「按现有路由风格选择」。ops 组现有资源组全部单数（`ops.Group("/floor")` router.go:565、`ops.Group("/workstation")` router.go:605、`ops.Group("/location-alias")` router.go:643），`floorApi` 基路径 `/ops/floor` 同为单数
- **注册在 workstation 组而非 floor 组**：① `workstationHandler` 在 workstations 块内构造（router.go:620），floor 块作用域没有该变量，跨块注册无法编译；② 权限 profile——workstation 组中间件为 `ops:workstation:* OR ops:building:spaces:list`（router.go:607-612），与现行 CAD/3D 消费者通过 workstation List 持有的权限完全一致，floor 组方案会让仅持 workstation 权限的用户 403
- gin 同组「静态 + 参数」混排有既有先例（`workstations.POST("/list")` 与 `POST("/:id")` 共存；GET `/dept-mapping-template` router.go:639），无路由冲突；全量装配由 `internal/api/router_80_04_test.go` 的 SetupRouter 探针兜底（路由冲突 panic 即测试失败）

**四处对齐清单：** router.go 注册 / workstation_handler.go swagger 注解（`@Router /ops/workstation/{floorId}/workstations-all [get]`）/ opsApi.ts 前端 URL / must_haves key_links——全部使用上述同一路径。
