# Plan 99-04: V130R-09 分页 clamp 单一权威收敛（Go 口径核心）

## Context

V130R-09 将 operations/system/vdi 域三条并存的分页 clamp 口径收敛为单一权威出口 `pkg/query`（D-03-1 方案 B）。本计划只做 **Go 侧口径核心**：query 变体 + 弃用注释 + 全部生产调用方迁移 + 内联限制清理 + 回归测试。CAD 专用端点与前端消费者迁移在 99-05（wave 2，同 phase 内紧随执行）。

**Decisions honored:**
- D-03-1: `pkg/query.NormalizePagination` 为唯一分页归一化权威出口
- D-03-2: 新增 `NormalizePaginationWithMax(current, pageSize, maxPageSize int)` 3 参数版；`NormalizePagination` 委托它（cap=`pkg/constants.MaxPageSize`=200）
- D-03-3: `pagination_helper.go` 的 `clampPageSize`/`extractPagination` 标注 `@deprecated` 保留不删；ops 生产调用方全部迁到 `query.NormalizePaginationWithMax`（cap=`internal/constants.MaxOptionsPageSize`=10000，ops 表格 list 口径不变）
- D-03-4: 内联硬编码 `100` 清理。**重定靶说明**：discuss 时点名的 dict/post 老 service 经核实**无内联 clamp**（仅 `dict_service.go:45/200/222`、`post_service.go:26/59` 的过时注释，实际 100 上限已由 system 模块 `requests.PaginationParams.GetPagination` → `MaxListPageSize` 统一承接）；真实内联 clamp 位于 `internal/services/vdi/vdi_server_service_impl.go:70`，本计划以该处为 D-03-4 的实际落点
- D-03-8: `workstation_service.go` List 删除 `GetPaginationWithMax(constants.MaxOptionsPageSize)`，改用 `query.NormalizePagination`（cap=200）。**无迁移窗口**——CAD/3D 全集消费者在 99-05（同一 phase 内）迁到专用端点，List 上限直接落 200

### 口径语义差异（迁移伴随的行为变化，均为 bugfix caliber，逐条记录）

| 维度 | 旧路径行为 | 新路径行为 | 定性 |
|------|-----------|-----------|------|
| pageSize 1-9（workstation List / ops 三调用方） | `GetPaginationWithMax`/`clampPageSize` 以 `MinPageSize=10` 放大下限（5→10） | `NormalizePaginationWithMax` 仅修 `<=0`，1-9 原样透传 | bugfix：把 <10 的 pageSize 放大到 10 无语义收益；D-03-2 锁定实现无下限放大 |
| current < 1（building/asset/location_alias） | `extractPagination` 透传负值（如 -5 → offset 为负隐患） | 修正为 `DefaultCurrent=1` | bugfix：消除负 offset 隐患 |
| pageSize > 100（vdi ListServers） | 重置为默认 10（`if pageSize <= 0 \|\| pageSize > 100 { pageSize = 10 }`） | 钳到 `MaxListPageSize=100` | 口径收敛：超限应钳制而非静默重置 |
| cap（workstation List） | `MaxOptionsPageSize=10000` | `MaxPageSize=200` | D-03-8 锁定；全集场景由 99-05 专用端点承接 |

**执行顺序约束：** 本计划（wave 1）落地后、99-05（wave 2）完成前，CAD/3D 消费者的 `pageSize:1000` 请求会被暂时钳到 200。两个计划在同一 phase 内连续执行，该中间态不会跨越 phase 边界暴露。
