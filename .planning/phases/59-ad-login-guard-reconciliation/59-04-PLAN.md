## Decision Reconciliation

- **D-17 权限门**：Tab 始终可见；无权限时在 Tab 内渲染 403 且不发请求（不隐藏 Tab）。前端权限只是 UX 门，后端 `RequirePermissions` 才是鉴权边界（59-03）。
- **后端路径对齐**：D-14 字面 `/system/ad-config/...` 按实际挂载对齐为 `/ad-domain/reconciliation/mismatch`；前端沿用模块内既有 `/ad-domain/...` 前缀，不加别名。
- **共享组件字重（机制已按真实 API 收敛）**：`EmptyStateWithAction` 的 props 只有 `title/description/actionLabel/actionPath/onAction/icon`——**没有 `styles`、没有 `className`**，且标题在组件内部以 **inline style** 渲染（`<div style={{ fontSize: 16, fontWeight: 500 }}>`，`EmptyStateWithAction.tsx:48`）。inline 声明胜过任何普通类选择器，因此「父级加 class 覆盖」不可行。
  本计划选定并只使用一种可行机制：**新增与本 Tab 同目录的 `ReconciliationTab.css`，用本 Tab 专属包裹类下的 `!important` 规则覆盖该标题 div 的 `font-weight` 为 600**（CSS 层叠中作者样式表的 `!important` 声明确实压过非 `!important` 的 inline 声明）。仓库既有先例：`src/components/shared/ActionButtons.css` 用同法在 `!important` 下覆盖 antd 内部元素。不修改共享组件本身。
  代价与验证边界：jsdom 不计算层叠样式，该字重**无法在 vitest 中做计算样式断言**——组件测试只锁定空态文案与组件选型，字重由视觉/UAT 复核（记入 Manual-Only）。UI-SPEC §规划期注意 2 给出的另一条路（接受共享组件现状 16px/500 并修订契约）被显式否决，因为该处默认取「以契约为准」。
