## 1. DEBT-01 — hex→token 映射契约

### 1.1 收敛规则（判定三问）

对每一处硬编码 hex，按顺序问：

1. **它进不进 DOM？** 出现在 JSX `style`、CSS 文件、antd `color` prop、className 关联样式 → 必须收敛：随主题的（背景/文字/描边/表面）→ `var(--theme-*)`；品牌定值 → `ruoyiBrand` 常量。
2. **它是不是数据而非样式？** 色值作为业务数据被选择/传输/存储（如 `IconSelect` 色板、用户可选标签色）→ 不属样式收敛，改从 `ruoyiBrand` 派生数据源即可（可选），不强制。
3. **它是不是非 DOM 渲染管线输入？** → 进入 1.2 豁免判定。

### 1.2 豁免判定标准与豁免清单机制

**豁免判定标准（全部满足才可豁免）**：该 hex 是 (a) WebGL/Three.js 材质/灯光、Canvas 2D 绘制、echarts option（主题注入或图表配色数组）、地图区域着色等 **非 DOM 渲染输入**，且 (b) 不随 light/dark 主题切换语义（或由渲染层自行处理主题），且 (c) 收敛到 token 反而破坏视觉效果或引入主题耦合。

**豁免清单机制**：本 SPEC 不内嵌长清单（文件会随 67 迁移动）。executor 在收敛时维护
`.planning/phases/68-p2/hex-exemptions.md`，每行一条：

```
| 文件路径:行号 | hex | 场景 | 豁免理由（对应 1.2 判定 a/b/c） |
```

SC1 验收即「豁免清单之外的 hex 命中 = 0」。

**按目录聚类（亲测）默认豁免/收敛分类**：

### 1.3 lint 增量方案

**现状（亲测 `ruoyi-react-frontend/eslint.config.js`）**：已有三类拦截（内网 IP `no-restricted-syntax`、Phase 65 契约组件强制块、no-restricted-imports 块），**尚无裸 hex 禁令**。Phase 63 UI-SPEC 口径是「禁止新增裸 hex / 双写兜底」，仅靠 review 纪律无机器守卫。

**增量方案**：在 `eslint.config.js` 新增独立 config 块（勿与既有块合并——flat config 同名 rules 键互相覆盖，既有注释已明示）：

```js
// ===== Phase 68 DEBT-01 裸 hex 拦截 =====
{
  files: ["src/**/*.{ts,tsx}"],
  rules: {
    "no-restricted-syntax": [
      "error",
      {
        selector:
          "Literal[value=/#[0-9a-fA-F]{3,8}\\b/]",
        message:
          "禁止裸 hex 颜色字面量，请使用 var(--theme-*) 或 @/design-system/tokens/colors 的 ruoyiBrand；豁免须 eslint-disable-next-line 并注明原因（Phase 68 DEBT-01）",
      },
    ],
  },
},
```

豁免三层面（与 Phase 65 机制同构）：
1. **目录 override**：`design-system/**`、`**/__tests__/**`、`**/*.test.*` 块内关掉本条；
2. **逐行豁免**：真实非 DOM 场景用 `// eslint-disable-next-line no-restricted-syntax -- <1.2 判定理由>`，且同步登记进 `hex-exemptions.md`；
3. **存量文件豁免 override**：若收敛完成后仍有整文件级合理场景（如 cad-editor），以文件列表 override 收口。

**拦截面说明**：selector 命中字符串字面量含 3-8 位 hex（含 3 位简写、8 位带 alpha）。正则宽度宁可宽后靠豁免收窄，不遗漏。CSS 文件不在 eslint 面内，CSS 的裸 hex 以 `hex-exemptions.md` + review 收口（如需机器守卫可后续加 stylelint，本 phase 不立项）。

## 2. DEBT-02a — 状态展示 helper 契约

### 2.1 API 契约（新建 `src/components/shared/statusHelpers.tsx`）

> **落点裁定（checker 修订）**：唯一落点为 `src/components/shared/`。若放 `src/utils/`，`StatusTag` 内部的裸 `<Tag>` 会命中 Phase 65 裸组件拦截（`eslint.config.js` 的 shared/ui 豁免块仅覆盖 `src/components/ui/**`、`src/components/shared/**`，utils 不在内）。

```ts
// 输入：status 数值 + 语义域；输出：统一文案 + antd Tag color（语义 token，非裸 hex）
export type StatusDomain =
  | "enable"      // 0=启用/正常, 1=停用 （通用 sys_status）
  | "online"      // 0=在线, 1=离线 （ad-domain computers）
  | "result"      // 0=成功, 1=失败 （job 日志/执行结果）
  | "health"      // 0=正常, 1=异常 （monitor server）
  | "workstation" // 0=空, 1=占, 2=维 （工位三态，唯一多值域）
  | "visible";    // 1=显示, 0=隐藏 （menu visible，注意反转例外）

export function statusLabel(status: number, domain: StatusDomain): string;
export function statusColor(status: number, domain: StatusDomain): "success" | "error" | "default" | "processing";
export function StatusTag({ status, domain }: { status: number; domain: StatusDomain }): JSX.Element;
// StatusTag 内部 = <Tag color={statusColor(...)}>{statusLabel(...)}</Tag>，未知 status 值 → "未知" + "default"
```

硬规则：
- **文案唯一口径**：enable 域统一「启用 / 停用」（不带「已」前缀）；result 域「成功 / 失败」；health 域「正常 / 异常」；online 域「在线 / 离线」。
- **色 token 唯一口径**：正向一律 `color="success"`，负向一律 `color="error"`；禁止 `color="green"/"red"` 预设色名与 hex。
- **「停用」的 Tag 色**：统一 `"error"`（现状混用 `"default"` 的实例一并收敛，见 2.2）。
- 未知 status 值不得 crash 也不得静默显示错误文案。
- 操作语境（下拉菜单里的「停用/启用」动作项）**不属**展示 helper 范畴，保持现状文案即可，但动词与域文案保持一致（「停用」非「禁用」）。

## 3. DEBT-02b — 日期展示 helper 契约

### 3.1 真相源：既有 `src/utils/datetime.ts`（亲核）

已有三档 helper，**本 phase 不新建，只收敛调用**：

```ts
export function formatDateTime(date: string|Date|null|undefined, format = "YYYY-MM-DD HH:mm:ss"): string; // 空值 "-"
export function formatDate(date): string;   // "YYYY-MM-DD"
export function formatTime(date): string;   // "HH:mm:ss"
```

时区口径（已实现，保持）：入参字符串尾缀 `Z/z` 被**剥离后按本地时区格式化**（`date.replace(/[Zz]$/, "")`），即后端返回的 UTC 无时区标记时间按本地展示；空值统一显示 `-`。本 phase 不改此口径，只要求所有调用走 helper（杜绝散落 dayjs 直调绕过空值/剥 Z 逻辑）。

### 3.2 现有手写格式清单与目标映射（亲测 dayjs `.format("...")` 分布，全 src 非 test）

| 现有 format 字符串 | 命中 | 目标 |
|-------------------|------|------|
| `"YYYY-MM-DD"` | 24 | ✅ 基准 → `formatDate()`（checker 复核 2026-10-25） |
| `"YYYY-MM-DD HH:mm:ss"` | 9 | ✅ 基准 → `formatDateTime()` |
| `"YYYY年MM月DD日"` | 4 | 收敛 → `formatDate()`（列表/详情一律 ISO 风格；如确为展示性场景保留须登记豁免+理由） |
| `"YYYY-MM-DD HH:mm"` | 3 | 分档收敛：精度到分的场景统一 `formatDateTime(x, "YYYY-MM-DD HH:mm")`（helper 的 format 参数允许，但字符串字面量集中为常量 `FORMAT_DATETIME_MINUTE` 导出） |
| `"YYYY-MM-DDTHH:mm:ss"` | 2 | **bug 级**：T 分隔符会原样渲染给用户 → `formatDateTime()` |
| `"MM-DD"` | 2 | 周视图等紧凑场景 → `formatDate(x, "MM-DD")`? 归入常量 `FORMAT_DATE_SHORT`，禁止散落 |
| `"HH:mm"` | 2 | → `formatTime` 或常量 `FORMAT_TIME_MINUTE` |

命中文件 TOP（收敛顺序参考）：`pages/operations/assets/index.tsx`(7)、`pages/duty/management/components/WeeklyView.tsx`(4)、`pages/duty/schedules/**`(7)、`pages/asset/reconciliation/exceptions/index.tsx`(3)。日期字符串收敛**不依赖 67 迁移**，可独立做（若触碰文件恰在 67 迁移列，随迁移顺带，以 67 收口实测为准避免冲突）。
