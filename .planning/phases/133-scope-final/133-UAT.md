## A. 四实体读写 403 矩阵（人工复核）

> 自动验收：service 层 ScopeResult 注入 + 403 矩阵单测（SQLite）。
> 人工项在真实 PG + 真实浏览器跨角色复核「越界不可见 / 越界写 403 / 超管零回归」。

- [ ] **A1 asset（dept_id 直挂）**：用 Dept 档用户分别访问
  `/ops/asset/list`、`/statistics`、`/dropdown-options`（若适用）、`/:id`，
  断言只返回 `dept_id ∈ 可见集` 的资产；越界 ID 的 GetByID 返回空/404。
- [ ] **A2 serverRoom（楼宇链）**：Dept 档用户 List / Statistics / GetByID / dropdown-options
  只返回 `building.org_id ∈ 可见集` 的机房；跨机构楼宇下的机房不可见。
- [ ] **A3 dedicatedLine（source/dest 双链 OR 命中）**：
  - 构造「源机房在本机构、目的机房在跨机构」的专线 → 本机构用户应可见（任一端命中）；
  - 构造「两端机房都在其它机构」的专线 → 本机构用户不可见（两端都不命中 → fail-closed 空集）；
  - Create/Update 提交两端都越界的 `source_room_id`/`dest_room_id` → 403。
- [ ] **A4 roomDevice（两级 JOIN）**：Dept 档用户只返回
  `room → building.org_id ∈ 可见集` 的机房设备；任一级断链的设备不可见。
- [ ] **A5 单条写越界 403**：四实体 Create / Update / Delete 各挑一条越界目标，
  浏览器 Network 断言 HTTP 403（统一错误文案，见 DS-04 / 132）。
- [ ] **A6 批量按可见集裁剪**：Batch 请求混入越界 ID，断言只处理可见集内行、
  越界计数入 operlog、不整批 403（批量裁定 §2）。
- [ ] **A7 超管零回归**：admin（All 档）对四实体读全量 / 写任意目标放行，行为与 130 前一致。
- [ ] **A8 Self 档空集**：Self 档用户对四实体（无用户归属列）读返回空集、写 403（裁定 §2）。
- [ ] **A9 异常枚举 fail-closed**：构造非 0 且 ∉ 1..5 的 data_scope 角色，读返回空 / 写 403。
- [ ] **A10 归属链断链脏数据抽查**（ds05 残余风险，见下 C 段）：
  在测试库造「building 已软删但 dedicatedLine / roomDevice 仍引用」的脏数据，
  断言非超管看不到这些行（fail-closed），且**系统不为脏数据开旁路**；
  记录抽查行数与结论。
- [ ] **A11 两级 JOIN `EXPLAIN` 观察项**（非阻断）：对 roomDevice 两级 JOIN 与
  dedicatedLine 两端 OR 子查询在真实 PG 跑一次 `EXPLAIN`，记录是否出现全表扫描 / 计划退化。
