Add `React.memo` wrapping to four identified hot components (D-14):

1. **AssetRow** — If the asset list page uses a custom `render` row function, extract it into `src/components/table/AssetRow.tsx`:
   ```
   import { memo } from 'react';
   import type { AssetRecord } from '@/types/asset';

   interface AssetRowProps {
     record: AssetRecord;
     // other props like handlers
   }

   function AssetRowImpl({ record, ...rest }: AssetRowProps) {
     // ... existing row render logic
   }

   export const AssetRow = memo(AssetRowImpl);
   ```
   Then in the page's `columns` array, change the column `render` functions to use the new `AssetRow` component, OR keep the existing inline `render` and wrap the entire `Table` cell-render closure. The simpler route: just memoize the `render` output via `useCallback` in the columns array. If extraction is too invasive, document the alternative in a JSDoc and skip.
   - Pragmatic path: if the page renders rows inline, leave the page's row code alone and add a `React.memo` wrapper around a top-level sub-component that takes `{ record, columns }` if such a wrapper exists or can be added with minimal disruption. If the row is purely inline in the page, skip this component and document the limitation in the SUMMARY.

2. **VDIRow** — Same pattern. Extract from `VirtualMachineList/index.tsx` if possible, otherwise memoize the row callbacks via `useCallback` and pass them as stable props to AntD Table's `onRow`.

3. **Dashboard Widget** — In `src/components/dashboard/Widget.tsx` (or wherever Widget is defined — confirm location; if `pages/dashboard-system/components/`, create or use the existing module). Wrap the default export in `memo`:
   ```
   import { memo } from 'react';
   function WidgetImpl(props) { ... }
   export const Widget = memo(WidgetImpl);
   export default Widget;
   ```
   - Verify that the widget receives stable props (id, config, data) from its parent — if parents pass new object literals on every render, memo won't help. Add a JSDoc note suggesting the parent use `useMemo` for the props object.

4. **EditModal** — `src/components/modal/BaseEditModal.tsx` (create this file as a generic wrapper if it does not exist; or apply `memo` to the existing modal component). The goal: when a parent re-renders (e.g. table pagination), the modal (if open) should not re-render. Wrap in `memo`. If the modal takes inline `onOk` / `onCancel` callbacks from the parent, document that parents should `useCallback` them.

5. After all memo wrappers, run `cd ruoyi-react-frontend && npm run lint` to ensure the new `error: react/jsx-no-unstable-nested-components` rule does not fire on the new components. If it does, refactor any inline component definitions out of render functions.
