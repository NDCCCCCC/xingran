### 1.2 允许的变化（仅实现层替换 + 显式裁决项）

**A 类：用户不可感知（默认允许，无需逐条验收）**
- 内部 hook 替换：usePagination / useServerSort / useTableManager 三 hook 手工接线 → PageTable 内部 useTableManager 统一承接；setTotal effect 删除（INV-1 等价）。
- 手写 Table/分页/搜索卡 JSX → PageTable/SearchForm 渲染；DOM 结构微调（Card 包裹层级、flex 容器）但视觉布局不变。
- 裸 `<Input>/<Select>` → AppInput/AppSelect（allowClear/showSearch 默认与现状一致——现状这些字段已手写 allowClear）。
- 手写 Modal → FormModal（BaseEditModal 底座 + INV-10 脏检查红利）。

**B 类：文案对齐（用户可感知，65 契约既定升级，裁决：随迁移对齐，记 PR 描述）**

现状部分删除/确认入口是早期裸 `Modal.confirm`，文案与 65 §4 模板不一致。迁移到唯一入口时**文案按 65 模板对齐**（这是 65 SC3「无绕过入口」的既定要求，但属用户可感知变化，逐条列出）：

| 页面 | 现状文案（亲测） | 迁移后（65 模板） | 裁决 |
|------|----------------|------------------|------|
| devices 单删（`devices/index.tsx:238-257` 裸 Modal.confirm：`确认删除?` / `确定` / `取消`） | `确认删除?`，内容为空，无对象无警示 | `确认删除` / `将删除{target}，删除后不可恢复，是否继续？` / `删除` / `取消`（target=设备名，经 createDeleteAction→ConfirmDelete） | **对齐**（65 §4 既定） |
| backups 还原确认（`backups/index.tsx:206-214`：`确认恢复配置` + 覆盖警示；`backups/index.tsx:527-533`：`确认恢复到此版本?` / `确定`） | 两处还原确认文案不一 | **保持各自现状原文不动**——还原是危险恢复操作而非删除，不在 65 ConfirmDelete 强制面；零 UI 变化优先。lint 若拦（Popconfirm/Modal.confirm selector）按 65 §3 存量豁免清单处理，不加 eslint-disable 散点 | **保持现状**（豁免清单承接） |
| cache 清空全部（`cache/index.tsx:311-330`：`确认清空` / `确定要清空所有缓存吗？此操作不可恢复！`） | 含警示但非删除模板 | **保持现状原文**（同上：清空≠删除，且文案已含不可恢复警示；豁免清单承接） | **保持现状** |
| discoveries 删除任务（`discoveries/index.tsx:146-154` onOk 直连 post；确认弹窗实际存在于 `discoveries/columns.tsx:114-121` Modal.confirm「确认删除?/确定/取消/danger」——**planner 亲测修正：现状已有确认，非 STOP 级缺口**） | 有确认（文案过时） | 迁移经 createDeleteAction→ConfirmDelete，文案对齐 65 模板（「确认删除?」→ 模板句式） | **B 类文案对齐**（原「STOP 级缺口」表述系 UI-SPEC 误判，2026-10-25 planner PLAN 期间修正，裁决结果不变） |

**C 类：结构缺陷裁决（如实记录，执行时需 checker/用户确认）**
1. **discoveries 状态筛选未接线**（`discoveries/index.tsx:292-310`：Form.Item 无 name，Select 无受控值——用户选了状态，请求并不携带该参数）。迁移到 searchFields schema 会**顺带接线使筛选生效** = 行为变化（缺陷修复）。裁决建议：**接线生效并显式标注**（与 B 类 discoveries 删除同性质：修复假交互）；若 checker 裁决零变化优先，则用 `searchChildren` 逃生口复刻现状不接线形态。默认按「接线生效」执行。
2. **搜索按钮文案**：discoveries/backups 现状「查询」（无重置按钮）、devices「查询/重置/刷新」、cache「搜索/重置/刷新」。SearchForm 内建为「搜索/重置/刷新」。裁决：**统一到 SearchForm 内建文案**（65→66 已验收惯例；「查询→搜索」为 B 类可感知微变，逐 PR 记录）；backups/discoveries 迁移后**新增「重置」按钮**（新增能力，B 类）。
3. **cache 搜索区非 Form 形态**（`cache/index.tsx:568-638`：受控 state `setSearchForm`，非 antd Form）——迁移到 useTableManager searchForm 需接线改造；行为等价（输入/下拉值进查询参数），视觉不变。
4. **devices 批删取消按钮防抖放弃**：`devices/index.tsx:243-257` 单删 confirmInstance.update 防抖与 `:518` 注释——批删已声明「随迁移放弃」（helper 契约外增强）；单删迁移到 ConfirmDelete 后其 onOk Promise 语义天然覆盖防重，等效。

## 4. 回滚契约

**选择：git revert 即回滚（不采用迁移 commit 内文件级并存）。**

| 项 | 契约 |
|----|------|
| PR 粒度 | 每页一个独立 PR（discoveries → backups → devices → cache 顺序，前页验收通过再开下页） |
| 并存策略 | **不做** `index-v2.tsx` 文件级并存。理由：① 路由（App.tsx）import 固定路径，并存需切 import，产生额外 diff 噪音；② 双实现并存一个迭代必然漂移（修 bug 只修一边），比 revert 更危险；③ git 历史即旧实现存档，revert 语义完整 |
| 「旧实现保留一个迭代」的确切含义 | 迁移 commit 本身不删除尚未迁移的子文件（columns/hooks/modals 子目录原样保留）；**迁移后一个迭代内不做删除性清理**（不删旧 hook 引用、不收缩豁免清单之外的内容）；期间发现回归 → `git revert <迁移 commit>` 单步回滚，零残留。迭代结束无回归 → 清理 PR 收缩豁免清单（gen-p66-exemptions.mjs 复跑） |
| 回滚演练 | 每页 PR 合并前在本地分支验证 `git revert --no-commit` 干净（无后续 commit 依赖迁移产物） |
| revert 粒度 | PR 合并采用 **squash merge（单 commit）**，`git revert <commit>` 单步即回滚整页；若个别 PR 因 review 需保留多 commit 合并（merge commit），回滚改用 `git revert -m 1 <merge-commit>`，效果等价——执行时在 PR 描述注明合并方式 |
