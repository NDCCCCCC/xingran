# Phase 55 Plan 02: 后端 batch_orchestrator.go fallback 路径 port 归属跨层防御

## Objective

清理 Phase 53 code review `53-REVIEW.md` §CR-02 记录的 **后端 fallback 路径跨设备写入风险**: 当 `preStateMap` 查不到 port(`!exists`)走 fallback 分支 `executeWrite(ctx, portID, req.DeviceID, ...)` 时,后端完全信任前端传入的 `req.DeviceID`,如果前端 deviceId 错位(CR-01 根因 — Phase 53 已修)但漏网,后端会用错误 deviceId SSH 下发命令到非 port 所属设备。修复: 在 fallback 分支前置一次 `db.First(&port, "id = ?", portID)` 查 port 真实 deviceID,与 `req.DeviceID` 不一致则归入 `result.Failed` 并标 `error: "port does not belong to device"`,**不调 SSH**(纵深防御双保险)。

修复范围仅限 fallback 分支(`!exists` 路径),不动主路径(主路径 `preStateMap` 查询用 `WHERE device_id = ? AND id IN ?` 隔离,正常路径零开销)。

## Tasks

### Task 1: CR-02 — fallback 分支前置 port 归属校验

**read_first:**
- `internal/services/portwrite/batch_orchestrator.go` (line 50-87: 批量 pre-state 查询 + fallback 分支)
- `.planning/phases/53-w4-frontend-drawer-progress-dialog-api-wrappers/53-REVIEW.md` (line 91-115: CR-02 原始描述与修复示意)
- `.planning/phases/55-phase-53-leftover-sweep/55-CONTEXT.md` (D-04 决策: 仅 fallback 分支加校验,不做全路径;error message 文案固定 `"port does not belong to device"`)

**action:**

修改 `batch_orchestrator.go` line 72-87 的 fallback 分支(`if !exists` 块),在调用 `s.executeWrite(...)` 之前增加一次 DB 查询校验:

```go
if !exists {
    // CR-02 跨层防御: fallback 路径下前端 deviceId 可能错位(CR-01 根因已修但兜底双保险),
    // 先查 port 真实 deviceID,与 req.DeviceID 不一致则归 Failed 不调 SSH
    var actualPort models.DevicePortStatus
    if err := s.db.WithContext(ctx).
        Where("id = ?", portID).
        First(&actualPort).Error; err != nil {
        // DB 查不到该 port(可能已被软删/物理删) — 归 Failed
        result.Failed = append(result.Failed, PortResult{
            PortID: portID,
            Error:  fmt.Sprintf("port not found: %v", err),
        })
        continue
    }
    if actualPort.DeviceID != req.DeviceID {
        // port 真实 deviceID 与请求 deviceID 不一致 — 拒绝 SSH 下发
        result.Failed = append(result.Failed, PortResult{
            PortID:   portID,
            Error:    "port does not belong to device",
            PortName: actualPort.InterfaceName, // 可选,便于审计追踪
        })
        continue
    }

    // 校验通过 — 端口"消失"(D-13 fallback)但归属正确,直接下发
    writeResult, werr := s.executeWrite(ctx, portID, req.DeviceID, req.Action, req.Description, operator, "")
    if werr != nil {
        if writeResult != nil {
            result.Failed = append(result.Failed, *writeResult)
        }
        break // fail-fast
    }
    if writeResult.NoOp {
        result.Skipped = append(result.Skipped, *writeResult)
        continue
    }
    result.Succeeded = append(result.Succeeded, *writeResult)
    continue
}
```

关键改动:

1. **新增 `actualPort` 查询**: 用 `s.db.WithContext(ctx).Where("id = ?", portID).First(&actualPort)` 查 port 真实信息(line 75-79)。
2. **DB 错误处理**: 如果 First() 返回 err(端口已删/软删/不存在),归 `result.Failed` + `continue`(不 break,因为是数据校验失败而非 SSH 失败,后续端口可继续校验)。
3. **归属校验**: 比较 `actualPort.DeviceID != req.DeviceID`,不一致则归 `result.Failed`,`Error: "port does not belong to device"`(文案严格按 53-REVIEW §113 固定),并填 `PortName: actualPort.InterfaceName` 便于审计追踪(可选,但符合 audit 表既有规范)。
4. **continue vs break 语义**: 校验失败时 `continue`(继续校验下一个 portID),不 `break`。`break` 是 SSH 失败时的 fail-fast 语义,数据校验失败不应阻断整个 batch(其他 port 可能 OK)。原 fallback 分支(line 79)的 `break // fail-fast` 仅在 SSH `werr != nil` 时触发,语义保留。
5. **通过则继续原逻辑**: 校验通过后执行原 `s.executeWrite(...)` 调用,逻辑保持不变。

**acceptance_criteria:**

- `batch_orchestrator.go` line 72-87 的 `if !exists` 块新增 `actualPort` 查询 + 归属校验逻辑
- `actualPort.DeviceID != req.DeviceID` 时归 `result.Failed` + `Error: "port does not belong to device"`,**不调 SSH**(`s.executeWrite` 调用只在归属校验通过后执行)
- DB 查询失败(端口已删)归 `result.Failed` + `continue`(不 break)
- 归属校验失败用 `continue`(不 break),让 batch 中其他 port 继续校验
- error message 字符串严格为 `"port does not belong to device"`(53-REVIEW §113 固定文案,前端 `ResultView` 失败明细表 `dataIndex: "error"` 会渲染此值)
