### 豁免清单定稿规则（防止「白名单无限扩张让脚本变绿」）

86-00 落的是**骨架 51 条**。W5 定稿时按下列规则核对，**任何增删都必须落理由**：

| 规则 | 判据 |
|---|---|
| R1 悬空 | 豁免条目指向的页面必须存在于 76 页清单 → 否则删条目（页面没了，豁免也没了） |
| R2 重叠 | 同一页面不得同时出现在「已门控」与「豁免」两侧 → 已门控的必须从豁免里删掉 |
| R3 无写入口 | `category: read-only` 的页面必须**确实没有「业务写」入口特征命中** → 有命中则必须改判为 `no-permission-code` 并补证据。**⚠️ 人工判定口子（防止 R3 推翻前两波结论）**：`<Switch` 命中若经核实为**非业务写**（纯视图切换 —— 只改本地渲染状态、不落库），**允许保留 `read-only` 豁免**，但必须在 `reason` 中注明「**视图切换 Switch，非业务写**」并给出证据（`onChange` 绑定的 handler 名 + 该 handler 不触发后端写请求）。实例：`operations/building-spaces-3d/index.tsx:116` 的 `<Switch checked={useWebGL} onChange={setUseWebGL}>`（只切 WebGL/普通渲染）—— 86-00 归 `read-only`、86-02 边界写明「不动 building-spaces-3d」，两者一致；**缺此标注**的 `<Switch` 命中条目才强制改判 `no-permission-code` |
| R4 无码可证 | `category: no-permission-code` 的页面，其码必须确实不在 `src/constants/permissionCodes.ts` 的任何区块中（grep 逐条核）→ 若在，则该页必须改为实际门控（**这是发现漏铺的信号**） |
| **R4′ 码键存在性（引用前 grep —— TS2339 防线）** | **任何新写的 `PERMISSION_CODES.<组>.<键>` 引用，必须先 grep 确认该键在 `src/constants/permissionCodes.ts` 的该组区块中确有定义**（命令示例：`grep -A 12 "opsBuilding:" src/constants/permissionCodes.ts`），**不允许凭「别的组有同名键」推断本组也有**。⚠️ 反例（MEDIUM-5）：`opsBuilding:73` / `opsFloor:83` / `opsWorkstation:91` / `opsAsset:99` / `opsInfoPoint:107` / `opsServerRoom:115` / `opsDedicatedLine:123` / `opsRoomDevice:131` 八组**只有 `delete` 没有 `remove`**（`remove` 只存在于 `systemUser:27` / `systemRole:41` / `systemMenu:48` / `systemDept:56` / `systemPost:63`）→ 照抄 `PERMISSION_CODES.opsBuilding.remove` 会 **TS2339，8 页同时返工**。本条须在**各波实现前**（86-01~86-04）逐键 grep 执行，不只在 W5 补 |
| R5 理由非空 | 每条 `reason` + `evidence` 非空；理由须能回答「为什么现在不能门控 + 何时回补」 |
| R6 总量 | 豁免数 + 已门控数 = **76**（脚本硬断言）；豁免数若变化，须同步脚本常量并在 `86-VERIFICATION.md` 说明 |
