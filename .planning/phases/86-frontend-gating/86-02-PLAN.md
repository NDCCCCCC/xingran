### 铺开模式（与 W1 完全一致，不引入新形态）

```tsx
const permGate = useActionPermission();
```

⚠️ **三种「无 permission 位」的页面形态**：
- `PageTable` 的 `batchDelete={{ onDelete, target }}`（契约无 permission 位，`PageTable.tsx:60`）→ 条件传参 `batchDelete={permRemove.visible ? { onDelete: handleBatchDelete, target: "楼宇" } : undefined}`；
- `floors` 页的自研 `FloorSearchForm` 的 `onBatchDelete` prop（`FloorSearchForm.tsx:43,169`）→ **采纳 Lead 裁定方案 ①：给 `FloorSearchForm` 再加一个可选 `showBatchDelete?: boolean` 通道**（`onBatchDelete` 保持**必填**，页面层传 noop 包装兜底；`showBatchDelete` 决定按钮**渲不渲染**，`batchDeleteDisabled` 决定按钮**禁不禁用**）。页面层写法：`onBatchDelete={() => { if (!permRemove.visible) return; handleBatchDelete(); }}` + `batchDeleteDisabled={permRemove.disabled}` + `showBatchDelete={permRemove.visible}`。
  > **为什么是「加 `showBatchDelete`」而不是「只靠 noop + disabled 位」**：只给 `batchDeleteDisabled` 时，ready 无权限态下 `permRemove.visible===false` ⇒ `disabled===false` ⇒ **「批量删除 (N)」按钮仍在 DOM 且可点**（点了被 noop 吞掉，无动作）。虽然**不越权**（noop 兜住），但达不到本 plan acceptance_criteria「批删……**均不在 DOM**」的口径；若实施者自行加「不渲染」通道，又会与「本波组件契约加法合计**三处通道**」的登记口径冲突（**契约登记失真**）。加 `showBatchDelete?: boolean` 后：ready 无权限 → `visible===false` → `showBatchDelete===false` → **按钮不渲染**；未就绪 → `visible===true` + `disabled===true` → **渲染但 disabled**（**符合裁定 #3 三态语义**，`useActionPermission.ts:104` 未就绪返回 `visible:true, disabled:true`）。
- `floors` 页的自研 `FloorSearchForm` 的 **导入/导出触发按钮**（`:160` / `:163`，回调由 `index.tsx:541` / `:542` 传入）→ 触发按钮在**子组件内部**，页面层**无处可插**条件渲染 → **必须**给 `FloorSearchForm` 增补两个通道：① `onImport` / `onExport` 由**必填改为可选**（接口**放宽** —— 既有调用方传了回调时行为零变更；**不传 ⇒ 该按钮不渲染**）；② 增补**可选** `importDisabled?: boolean` / `exportDisabled?: boolean`（按钮 `disabled` 位）。页面层写法：`onImport={permImport.visible ? () => setImportVisible(true) : undefined}` + `importDisabled={permImport.disabled}`（导出同理）→ ready 无权限时**按钮不渲染**，未就绪时**渲染且 disabled**。

> ⚠️ **floors 的导入/导出若不加这两个可选位就必然失败**：触发按钮在子组件内，页面层只有「回调不传 ⇒ 不渲染」+「disabled 位」两条通道能把门控结果送进去。**本波组件契约加法合计三处通道**（**均须在 plan 报告中逐条登记**），全部落在**同一个**页面内组件 `FloorSearchForm` 上：
> - **通道 ①（导入 / 导出）**：`onImport` / `onExport` 由**必填改为可选**（接口**放宽** —— 既有调用方传了回调时行为零变更；**不传 ⇒ 该按钮不渲染**）+ 新增可选 `importDisabled?: boolean` / `exportDisabled?: boolean`（按钮 `disabled` 位）；
> - **通道 ②（批量删除）**：`batchDeleteDisabled?: boolean`（**新增位** —— 实测 `grep -rn batchDeleteDisabled src/` = **0**，本 phase 之前**不存在**）+ **新增 `showBatchDelete?: boolean`**（`showBatchDelete` 决定**渲不渲染**，`batchDeleteDisabled` 决定**禁不禁用**；两者组合出完整三态）；
> - **通道 ③（边界说明）**：上述加法**全部落在 `src/pages/operations/floors/components/FloorSearchForm.tsx`** —— `src/components/shared/**` 仍**零 diff**（`FloorSearchForm` 属 `src/pages/operations/floors/components/`，**不是** shared 目录）。
>
> **三通道合成的最终 props 形态（TS 声明）**：
> ```ts
> export interface FloorSearchFormProps {

>   onImport?: () => void;          // 通道①：必填 → 可选（放宽）
