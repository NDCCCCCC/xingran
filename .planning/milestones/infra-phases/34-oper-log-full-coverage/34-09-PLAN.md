<objective>
End-to-end verification of the operlog full-coverage phase: a shell script that, against a running backend + database, triggers 30 sampled write endpoints (selected deterministically by hashing the endpoint path) and verifies each one inserts a row in `sys_oper_log` with the expected title, businessType, and (where applicable) masked sensitive param. A Go test wraps the shell script for CI integration. Final counts and observed pass rate are appended to the audit note.

**WARNING 2 addressed:** The script MUST source admin credentials from environment variables (ADMIN_USER, ADMIN_PASSWORD). It defaults to `admin/admin123` ONLY when (a) the env vars are unset AND (b) the script is running in dev mode (checked via `APP_ENV` or `DEV_MODE` env var being `dev`/`development`/`1`/`true`). In any other environment, missing env vars cause the script to exit 1 with a clear error message. This prevents accidental hardcoded credential leaks in CI logs or production.

Purpose: The wave plans add 300+ handler-level Record calls. Without a runtime check, the build's success is not sufficient evidence — a handler could compile with a misnamed module, an off-by-one OperType, or a Record call placed AFTER the early-return error path. Plan 34-09 is the safety net that confirms the production code path actually writes the right row.

Output: `scripts/operlog_e2e_verify.sh` (the test driver) + `scripts/operlog_e2e_verify_test.go` (the CI wrapper) + an update to the audit note with observed coverage %.
</objective>
