<objective>
Build the foundation for the operlog full-coverage phase: a shared `recordOperLog` helper that any module can call, extended `OperType` constants, an enhanced sensitive-parameter filter, AND a body-aware `RecordWithBody` helper that reads/restores `c.Request.Body` for sensitive endpoints. Plan 34-01 ships the full API surface (Record variadic options + RecordWithBody helper) so Plan 34-02 (Wave 2) and later waves can use either pattern WITHOUT modifying this file's signatures. AD domain handler keeps compiling via a thin shim.

Purpose: Decouple operlog recording from `internal/api/v1/system` so waves 2-8 (covering system core, system peripheral, operations, network, vdi/workorder/duty/knowledge/scheduler, monitor/rpa/agent, and remaining system submodules) can add the same one-line call without circular import or handler-constructor changes. Extend the constant set to cover state-change verbs (enable/disable/reset/sync/move/...) and audit-related verbs (login/logout/approve/reject/...) so handlers don't have to misuse `OperTypeOther` (0) for legitimate semantic types. Ship two Record variants up front to avoid cross-wave signature changes: (a) variadic `Record(... opts ...RecordOption)` with `WithOperParam(string)` for inline override; (b) `RecordWithBody(c, svc, db, module, operType)` that reads+restores `c.Request.Body` internally so handlers do not have to manage the io.NopCloser dance.

Output: New `internal/utils/operlog` package with `Record`, `RecordWithBody`, `OperType` constants, `RecordOption`/`WithOperParam`, and `FilterSensitiveParams` helper; existing `internal/api/v1/system/helper.go` `recordOperLog` becomes a shim; AD domain handler unchanged; `internal/services/oper_log_service.go` `FilterSensitiveParams` is replaced/enhanced with the extended keyword set; new `operlog_test.go` covers the filter and the body-restore behavior.
</objective>

    Define the `RecordOption` type and option helpers (functional options pattern):
    ```go
    type RecordOption func(*recordConfig)

    // WithOperParam overrides the recorded oper_param with the given (already filtered) string.
    func WithOperParam(s string) RecordOption {
        return func(c *recordConfig) { c.operParam = &s }
    }
    // WithStatus sets the recorded status (1 = success, 0 = failure) — used for error-path logging.
    func WithStatus(status int) RecordOption {
        return func(c *recordConfig) { c.status = status }
    }
    // WithErrorMsg records an error message in the row.
    func WithErrorMsg(msg string) RecordOption {
        return func(c *recordConfig) { c.errorMsg = msg }
    }
    ```

    Define the `RecordWithBody` helper (used by handlers that need to capture the request body, e.g., user ResetPassword):
    - Signature: `func RecordWithBody(c *gin.Context, operLogSvc services.OperLogService, db *gorm.DB, module string, operType int)`
    - Behavior:
      1. Read `c.Request.Body` via `c.GetRawData()`. If error, fall back to plain `Record(c, operLogSvc, db, module, operType)`.
      2. Restore `c.Request.Body = io.NopCloser(bytes.NewBuffer(raw))` so downstream handlers (e.g., the actual handler logic, or SM2+SM4 middleware) can still bind the body.
      3. Pass `operlog.FilterSensitiveParams(string(raw))` via `WithOperParam` to `Record`.
    - This means handlers do NOT need to manage the io.NopCloser dance themselves — they just call `RecordWithBody` at the end of the success path.
    - Document in a comment: "Prefer RecordWithBody for sensitive endpoints (password reset, password change, API key creation, agent registration). For non-sensitive write endpoints, prefer plain Record to avoid reading the body unnecessarily."

    - Algorithm: for each keyword, find every occurrence of `"<keyword>":"<value>"` and replace the value substring with `******`. The current implementation only finds the first occurrence per keyword and assumes plain JSON; do a loop with `strings.Index` from the previous end position until no more matches. Cap input length at 8192 bytes before processing to bound CPU.

Document this caveat at top of file: "Bodies > 8192 bytes are not audited for sensitive-field masking. Endpoints that may receive such large payloads (file uploads, bulk imports) should use explicit WithOperParam(...) rather than relying on auto-masking."
