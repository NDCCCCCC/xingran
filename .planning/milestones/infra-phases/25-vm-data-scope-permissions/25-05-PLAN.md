<objective>
Fix Gin Context vs standard Context value passing incompatibility that prevents data scope filtering from working.

Purpose: The DataScopePermission middleware stores values via c.Set() into Gin's internal map, but the VM Service reads them via ctx.Value() from standard Go context chain. These two mechanisms are incompatible -- the service always gets nil, so no filtering occurs.

Output: Modified handler and service layers where userID and dataScope are passed as explicit parameters.
</objective>
