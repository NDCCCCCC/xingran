    1. `toFullPathTree<T extends DeptLikeNode & { deptName?: string }>(nodes, opts?: { startFromLevel?: 1 | 2 })`:产生 `{ title: string; value: string; key: string; children?: ...; isExternalOrg?: number }` 数组。语义为**全路径拼接**:
       - 顶级节点(ancestorNames 长度 0):title = node.deptName(直接显示)
       - 其余节点:title = [...ancestorNames, node.deptName].join(' / ')
       - `opts.startFromLevel` 默认 1 = 不裁剪祖先路径;若调用方需要"从二级开始"(如 DepartmentTreeSelect 旧行为的 `currentPath.slice(1)`),由调用方在 opts 传入或在调用前用 `nodes` 切片——**不在本函数硬编码 slice(1)**,以保持函数纯语义。复用 `getDeptNodeId` 取 value/key。
       - **必须透传 `isExternalOrg`**(workstations 高风险依赖此字段,否则 filterExternalOrgDepts 会把树过滤为空)。

    2. `toShortNameDataNode<T extends DeptLikeNode & { deptName?: string }>(nodes)`:产生 `{ title: string; key: string; value?: string; children?: unknown[]; isLeaf?: boolean }` 数组。语义为**短名**(只显示 deptName,不拼路径):
       - title = node.deptName;key = getDeptNodeId(node);value = getDeptNodeId(node)
       - children 递归;叶子节点 isLeaf = true

    两个函数都要 JSDoc 注释说明语义差异(对应 PATTERNS.md 给出的语义归类表),并标注它们替代了哪些原函数:

    - toShortNameDataNode ← DeptTree.transformToTreeData + notice/useTargetSelector.convertTree + **user/utils.tsx convertDeptTreeData(实测为短名,见 37-PATTERNS.md 修正条目)**

    不修改任何调用方(后续 task / 后续批次处理)。函数纯新增。
