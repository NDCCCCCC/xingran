**Step 0 (CRITICAL — preserves lazy chunk):** Modify
`src/components/dashboard/Widget.tsx` to **internally** wrap `WidgetRenderer`
in `lazy()` + `Suspense` before swapping consumer imports. This is a
non-obvious but mandatory step: the current consumers use
`lazy(() => import('@/components/dashboard/widgets/WidgetRenderer'))` at the
top of each file. If we naively replace that with `import { Widget } from ...`
and stop the lazy import, **we lose the lazy chunk for widget content** —
every route that imports `Widget` will pull `WidgetRenderer` (and its heavy
widget registry + Three.js widget sub-trees) into the initial bundle.

Fix: Widget.tsx becomes the single lazy boundary:

```ts
// src/components/dashboard/Widget.tsx
import { Suspense, lazy, memo } from 'react';
import { Spin } from 'antd';
import type { WidgetConfig } from '@/types/dashboard';

// Preserve the lazy chunk that the consumers used to create manually.
const WidgetRenderer = lazy(
  () => import('@/components/dashboard/widgets/WidgetRenderer')
);

const WidgetImpl: React.FC<WidgetProps> = ({ widget, onEdit, onDelete }) => (
  <Suspense fallback={<Spin />}>
    <WidgetRenderer widget={widget} onEdit={onEdit} onDelete={onDelete} />
  </Suspense>
);

export const Widget = memo(WidgetImpl);
```

This keeps the chunk split intact: `Widget` is sync (small wrapper) and
`WidgetRenderer` stays in its own async chunk (loaded on first widget
mount). Memo benefit is preserved (the prop is `widget` which has stable
identity from the dashboard store).
