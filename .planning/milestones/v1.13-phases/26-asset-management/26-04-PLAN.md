```go
// 资产管理
assets := ops.Group("/asset")
assets.Use(middleware.RequirePermissions([]string{
	"ops:asset:list",
	"ops:asset:add",
	"ops:asset:edit",
	"ops:asset:delete",
}, core))
{
	assetService := opsServices.NewAssetService(core.DB.GetDB())
	assetHandler := operations.NewAssetHandler(assetService)

	assets.POST("", assetHandler.Create)
	assets.POST("/list", assetHandler.List)
	assets.POST("/:id", assetHandler.GetByID)
	assets.POST("/:id/update", assetHandler.Update)
	assets.POST("/:id/delete", assetHandler.Delete)
	assets.POST("/batch", assetHandler.BatchOperation)

	// Excel导入导出
	operations.SetupExcelRouter(assets, "asset", core)
}
```

Key implementation details:
1. `SetupExcelRouter` is already defined in excel_handler.go
2. It automatically registers template, import, and export endpoints
3. Uses the same permission middleware as parent group
4. No additional handler creation needed (Excel routes are generic)

## Threat Model

### Trust Boundaries
| Boundary | Description |
|----------|-------------|
| Excel Upload → API | Admin users upload asset Excel files |
| Excel Parser → Service | Parsed rows sent to service for validation and upsert |

### STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-04-01 | I | malicious Excel upload | mitigate | File size limits, MIME validation, excelize library sanitization |
| T-26-04-02 | I | Formula injection | mitigate | excelize library evaluates formulas safely, no code execution |
| T-26-04-03 | D | Bulk data disclosure via export | accept | Standard RBAC (ops:asset:list) controls export access |
