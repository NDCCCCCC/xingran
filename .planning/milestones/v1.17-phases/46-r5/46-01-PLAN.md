# 46-01-PLAN: 修复建议生成器 + 人工确认 UI

## 目标

实现 Phase 46 R5 半自动修复的前半段：高置信度 Type B 异常生成"修复建议" + 人工确认 UI（接受 / 拒绝）+ 状态机管理 + 完整 operlog 审计链。覆盖 ROADMAP SC1、SC2、SC5、SC6。

## 锁定的 18 项决策（D-A1~A4 / D-B1~B4 / D-C1~C5 / D-D1~D4）

本计划必须显式落实以下决策（详见 `.planning/phases/46-r5/46-CONTEXT.md`）：

- **D-A1**: 修复字段仅 `ops_asset.user_id`，不写 dept_id / NowUserName / DeptName
- **D-A2**: Type D 不进 R5（UI 提示"Type D 不适用 R5 自动修复"）
- **D-A3**: 置信度门槛可配置（`sys_config: asset.reconciliation.fix.confidence_threshold`，默认 0.9）
- **D-A4**: 触发条件 = `confidence_score >= threshold AND conflict_type='B' AND workorder_id IS NULL AND deleted_at IS NULL AND resolved_at IS NULL`
- **D-B1**: 独立表 `sys_reconciliation_fix_suggestion`，与 `sys_data_reconciliation` 1:N
- **D-B2**: 6 状态状态机 = `pending / accepted / rejected / applied / rolled_back / failed`
- **D-B3**: 1 对多版本化（`exception_id` 索引 FK，不设唯一约束）
- **D-B4**: 部分唯一索引 `uniq_fix_suggestion_pending_per_exception`
- **D-C1**: 回滚粒度仅恢复 user_id
- **D-C2**: 回滚窗口 7d（`rollback_window_until = applied_at + 7 day`）
- **D-C3**: 强 operlog 写入（Rollback 用 `OperTypeReset=11`）
- **D-C4**: 修复后 7d 静默期 + `invalidate_workstation_health(wsID)` 缓存失效
- **D-C5**: 误修复率监控（本计划生成 service + endpoint，Plan 46-02 接入 SysNotice 告警）
- **D-D1**: 独立页面 `/asset/reconciliation/fix-suggestion`
- **D-D2**: 紧凑行 + 点击展开详情 Drawer
- **D-D3**: 仅单条接受（不批量）
- **D-D4**: 默认排序 + 部门/状态筛选，复用 `BaseListRequest + ApplySort` 白名单
