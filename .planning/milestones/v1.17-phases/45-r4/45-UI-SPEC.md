## Spacing Scale

Declared values (multiples of 4, anchored on existing 8-pt token system):

| Token | Value | Usage in R4 |
|-------|-------|-------------|
| xs | 4px | HealthBadge dot margin-right; Tag gap |
| sm | 8px | Card body row gap (KPI inner spacing); Statistic subtitle margin-top |
| md | 16px | HealthCard outer padding; Drawer header→tabs gap; KPI cell padding |
| lg | 24px | Drawer body section spacing; Card-to-Card vertical gap |
| xl | 32px | Drawer body section break (between Tabs panels) |
| 2xl | 48px | HealthCard header→KPI grid vertical gap |
| 3xl | 64px | (not used in R4) |

**Exceptions (R4-specific):**
- **HealthBadge dot**: 8px diameter (24px touch target when in interactive list cell). The dot is decorative; the cell itself inherits 32px row height from antd `Table` density `middle`.
- **Drawer width**: 780px (constant for R4 — matches existing exception-rules Drawer).
- **Mini-chart height**: 56px (fixed, no padding around ECharts canvas).
- **Timeline item gap**: 12px vertical between successive `ReconciliationTimeline` entries (off-scale to allow 4-px dot + 8-px text baseline alignment).

## Typography

| Role | Size | Weight | Line Height | Token reference |
|------|------|--------|-------------|-----------------|
| Display (score) | 30px (`3xl`) | 700 (`bold`) | 1.25 (`tight`) | `typography.h1` token |
| Heading (Card title) | 18px (`lg`) | 600 (`semibold`) | 1.375 (`snug`) | `typography.h4` token |
| Subheading (Tab title) | 16px (`base`) | 600 (`semibold`) | 1.5 (`normal`) | `typography.h5` token |
| Body (default) | 14px (`sm`) | 400 (`normal`) | 1.5 (`normal`) | `typography.bodySmall` token |
| Label (KPI value) | 24px (`2xl`) | 600 (`semibold`) | 1.25 (`tight`) | `typography.h2` token |
| Label small (mini-chart axis) | 12px (`xs`) | 400 (`normal`) | 1.5 (`normal`) | `typography.caption` token |
| Mono (IP CIDR, exception rule name) | 13px (antd `code`) | 400 | 1.5 | `typography.code` token |

**Note:** R4 declares 6 type roles vs the template's recommended 3-4 max. R4 requires a `Display` (score 30px) and `Mono` (CIDR/code) on top of the 4 standard roles because the score is the dominant visual element in HealthCard and CIDR strings appear repeatedly in the Exception Rules tab. The two extra roles are scoped narrowly (Display = score only; Mono = code-like content only).

### New hooks (created in `src/components/reconciliation/hooks/`)

#### `useWorkstationHealth(workstationId: string)`

```typescript
useQuery({
  queryKey: queryKeys.reconciliation.workstationHealth(workstationId),
  queryFn: () => reconciliationApi.byWorkstation({ workstationId, window: "7d" }),
  staleTime: 5 * 60 * 1000,   // matches R1 MV refresh + R4 cache TTL
  gcTime: 10 * 60 * 1000,
  refetchOnWindowFocus: false,
  enabled: visible === true,    // D-A1-03 silent degradation
})
```

- **useEffect deps stability (CLAUDE.md hard rule):** `workstationId` is the only dep; `enabled` flag from parent boolean state. No inline-object deps.
- **Returns:** `{ data: ByWorkstationResponse | undefined, isLoading, isError, refetch }`.

#### `useAssetHealth(assetId: string, workstationId: string | null)`

- Returns the `AssetHealthItem` slice from `useWorkstationHealth(workstationId)` matching `assetId`.
- Used by `ReconciliationDrawer` Tab 1 to avoid a 2nd API call (single source of truth = workstation endpoint).

#### `useExceptionMatch(params: { ip: string; conflictType: string })`

```typescript
useQuery({
  queryKey: queryKeys.reconciliation.matchTest({ ip: params.ip, userId: undefined, deptId: undefined }),
  queryFn: () => reconciliationApi.exceptionRule.test({ ip: params.ip }),
  enabled: Boolean(params.ip),
  staleTime: 5 * 60 * 1000,
  gcTime: 10 * 60 * 1000,
  refetchOnWindowFocus: false,
})
```

- Reuses existing `reconciliationApi.exceptionRule.test()` (already wired in R3).

#### `useReconciliationVisibility()` (cross-module permission)

```typescript
function useReconciliationVisibility(): boolean {
  return useReconciliationPerm();  // useSyncExternalStore on authStore.perms has 'asset:reconciliation:list'
}
```

- Returns `true` when `authStore.perms` includes `asset:reconciliation:list`; `false` otherwise.
- All R4 components gate on this hook to satisfy D-A1-03 silent degradation.

## Interaction Contracts

### HealthCard interactions

| Trigger | Result |
|---------|--------|
| Page mount → expand workstation row | `useWorkstationHealth(id)` fires; card shows skeleton → KPI grid + chart within ≤200ms (cache hit) or ≤300ms (cache miss, R4 SC5) |
| Hover KPI label | (no tooltip — labels are static text) |
| Click `详情报告` link | Open `/asset/reconciliation/exceptions?workstationId={id}` in same tab (route to existing admin page) |
| Click `申请例外` link | Open `/asset/reconciliation/exception-rules/new?assetIp={primaryIp}&conflictType=B` in new tab; toast "已跳转到例外规则新建页，IP 与冲突类型已预填。" |
| Click score number | (no interaction — score is display-only) |
| Hover mini chart | (no tooltip — sparkline mode only) |
| API error | Card body replaced by `<Result status="error">` with retry button |

### HealthBadge interactions

| Trigger | Result |
|---------|--------|
| Render with `conflictType === null` | Solid green dot, no tooltip, no cursor pointer, no onClick handler |
| Render with `conflictType = "A"` | Solid green dot (Type A is healthy per list_class), tooltip "物理有/责任人有且一致…", cursor pointer, click opens drawer |
| Render with `conflictType = "B"`/`"C"`/`"D"`/`"E"`/`"F"` | Colored dot per mapping table, tooltip per COPYWRITING TABLE, cursor pointer, click opens drawer at Tab 1 |
| Click dot (Type A-F) | `DrawerState.open = true`, `selectedAssetId = assetId`, `activeTab = "summary"`, body skeleton → summary row within ≤200ms |
| Hover dot (Type B-F) | Tooltip appears after 1.0s mouseEnterDelay; disappears immediately on mouseLeave |

### ReconciliationDrawer interactions

| Trigger | Result |
|---------|--------|
| Drawer open (from badge click) | Drawer slides in from right, body shows Tab 1 (冲突摘要) skeleton → content within ≤200ms |
| Click Tab 2 (历史变更) | Tab content swaps to `<ReconciliationTimeline>` (skeleton during fetch, ≤200ms cache hit); antd `Tabs` default transition (200ms ease-out) |
| Click Tab 3 (例外规则) | Tab content swaps to `<ExceptionMatchList>` (skeleton during fetch); if `ip === ""` or `conflictType === null`, immediately renders empty state without API call |
| Click header `申请例外` button | Open `/asset/reconciliation/exception-rules/new?assetIp={ip}&conflictType={type}` in new tab; toast feedback same as HealthCard |

### Permission degradation (silent hide)

| Trigger | Result |
|---------|--------|
| User has `asset:reconciliation:list` | HealthCard renders in workstation expand; HealthBadge column renders in tables; drawer can open |
| User lacks `asset:reconciliation:list` | HealthCard renders nothing; HealthBadge column renders `-` per cell; drawer cannot open (parent guards); no 403, no toast, no console.error |
| API returns 5xx (not perm issue) | HealthCard shows `<Result status="error">` with retry; HealthBadge shows neutral gray dot + no tooltip (degraded gracefully — list still usable) |

### Caching behavior (D-A4-03 + D-A4-04)

| Trigger | Result |
|---------|--------|
| Open workstation detail page | React Query fires `useWorkstationHealth(id)` once; result cached for 5 minutes |
| Re-expand same workstation within 5min | No network call; cached data served |
| Expand different workstation | New query fires (cache key includes `workstationId`) |
| R2 `exceptionResolve` API success | Backend calls `invalidate_workstation_health(wsID)`; **frontend has no manual invalidation in this phase** (relies on next 5min refresh or window refetch) |
| R2 auto-workorder create | Same — backend invalidates cache; frontend relies on cache TTL |

## Cross-Module Permission Degradation (D-A1-03)

R4 must **never** trigger 403, console.error, or visible degradation noise when user lacks `asset:reconciliation:list`. Implementation contract:

1. **Frontend gate**: All R4 components call `useReconciliationVisibility()` first; if `false`, render `null` (HealthCard) or `-` (HealthBadge cell).
2. **Backend gate**: Backend handler sets `visible = false` in response (per D-A1-03, `WorkstationHandler.GetByID` injects `ReconciliationVisible` into `Workstation` struct). Frontend's `useReconciliationVisibility()` mirrors this — when backend reports `visible: false`, the hook returns `false` regardless of frontend perm cache.
3. **Defense in depth**: Both frontend perm check AND backend `visible` flag must agree. Mismatch → frontend trusts backend (defensive).

**Hidden-by-perm component checklist:**
- `<HealthCard>` — `null` (no skeleton, no placeholder, no height reservation)
- `<HealthBadge>` — `-` (single dash, equal column width as visible state)
- `<ReconciliationDrawer>` — never rendered; parent guards
- Mini-chart and timeline inside drawer — naturally never reached
