# Quick Task 260701-iface-sort: 接口名称列数值排序

## 目标

端口状态列表（`/network/port/list`）点击"接口名称"列头排序时，按**板卡号 + 接口号数值**排序，而非当前错误的字符串字典序。

**当前（错误）**：`GE0/1, GE0/10, GE0/11, GE0/2`（字典序）
**期望（正确）**：`GE0/1, GE0/2, GE0/10, GE0/11, GE1/1, GE1/2, GE1/10, GE1/11`

## 关键技术决策

### 决策 1：必须用 SQL ORDER BY，不能用 Go sort.Slice

`GetList` 是 **DB 层分页**（`Count` → `Offset().Limit().Find()`）。Go 层 `sort.Slice` 只能排序当前页，**跨页顺序仍乱**（第1页混入本应第2页的记录）。正确做法必须让 DB 层 ORDER BY 按数值，分页才正确。

### 决策 2：PostgreSQL 数组比较 = 元组比较

PG `regexp_matches(interface_name, '(\d+)', 'g')` 把数字段提取为 int 数组。PG 数组逐元素比较天然等价 `(板卡号, 子卡号, 接口号)` 元组比较：
- `GE0/1` → `{0,1}`、`GE0/2` → `{0,2}`、`GE0/10` → `{0,10}`、`GE1/1` → `{1,1}`
- 排序：`{0,1} < {0,2} < {0,10} < {1,1}` ✅

### 决策 3：dialect-aware（PG/SQLite 兼容）

`regexp_matches` 是 PG 专属。项目惯例（`reconciliation_service.go` 等多处）用 `db.Dialector.Name()` 分支：PG 走正则数组排序，SQLite 降级为字符串排序（端口采集主库为 PG，SQLite 仅开发/测试用）。

### 决策 4：避开 pkg/normalize 未提交重构

`pkg/normalize/` 是别人正在进行、未提交的重构（归一化下沉共享包）。本任务**不依赖、不修改**它，逻辑自包含在 `query.go`，避免与未完成工作耦合。

## 任务

### Task 1: query.go 实现
- `interfaceNameSortExpr(dialectName, direction string) string`
  - PG: `(SELECT COALESCE(array_agg(m[1]::int), ARRAY[]::int[]) FROM regexp_matches(interface_name, '(\d+)', 'g') AS m) <dir>, interface_name <dir>`
  - 其他: `interface_name <dir>`（降级）
- GetList：`OrderByColumn=="interfaceName"` 走特殊分支，其他字段仍走 `base.ApplySort`，空排序仍 `collected_at DESC`
