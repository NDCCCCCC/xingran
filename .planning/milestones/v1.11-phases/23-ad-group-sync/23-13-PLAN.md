# Plan 23-13: Register Periodic Group Sync Cron Task

## Objective
Register a periodic cron job in the ADSyncScheduler to automatically trigger group member synchronization at regular intervals (e.g., every 15 minutes), separate from the full AD data sync. This ensures department-group memberships stay in sync without requiring full sync overhead.

**Purpose**: Enable automated periodic group member synchronization to keep AD groups up-to-date with current department assignments.

**Output**: Cron-registered group sync task in ADSyncScheduler, separate from full sync cron.

   func (s *ADSyncScheduler) Start() {
   	s.mu.Lock()
   	defer s.mu.Unlock()

   	if s.started {
   		return
   	}

   	// 每5分钟检查一次需要同步的AD配置（全量数据同步）
   	_, err := s.cron.AddFunc("0 */5 * * * *", func() {
   		s.checkAndSyncADConfigs()
   	})
   	if err != nil {
   		applogger.Errorf("启动AD同步定时任务失败: %v", err)
   		return
   	}

   	// 每15分钟执行一次组同步（成员同步）
   	_, err = s.cron.AddFunc("0 */15 * * * *", func() {
   		s.checkAndSyncADGroups()
   	})
   	if err != nil {
   		applogger.Errorf("启动AD组同步定时任务失败: %v", err)
   		return
   	}

   	s.cron.Start()
   	s.started = true
   	applogger.Infof("AD同步定时任务已启动（全量同步: 每5分钟, 组同步: 每15分钟）")
   }

2. **Add checkAndSyncADGroups method** (add after checkAndSyncADConfigs method, around line 170):

   ```go
   // checkAndSyncADGroups 检查并同步需要同步的AD组
   func (s *ADSyncScheduler) checkAndSyncADGroups() {
   	// 查找所有启用了组映射的配置
   	var configs []models.ADConfig
   	err := s.db.Where("sync_enabled = ? AND status = ?", true, models.ADConfigStatusEnabled).Find(&configs).Error
   	if err != nil {
   		applogger.Errorf("查询AD配置失败: %v", err)
   		return
   	}

   	for _, config := range configs {
   		// 检查是否有启用的组映射
   		var mappingCount int64
   		err := s.db.Model(&models.DeptGroupMapping{}).
   			Where("ad_config_id = ? AND mapping_status = ? AND sync_enabled = ? AND deleted_at IS NULL",
   				config.ID, "active", true).
   			Count(&mappingCount).Error
   		if err != nil {
   			applogger.Errorf("查询组映射失败: %v", err)
   			continue
   		}

   		if mappingCount == 0 {
   			// 没有启用的组映射，跳过此配置
   			continue
   		}

   		// 异步执行组同步
   		go func(configID string, configName string) {
   			syncCtx, cancel := context.WithTimeout(context.Background(), 30*time.Minute)
   			defer cancel()

   			// 尝试获取信号量
   			if err := s.sem.Acquire(syncCtx, 1); err != nil {
   				if syncCtx.Err() == context.DeadlineExceeded {
   					applogger.Warnf("AD组同步启动超时: %s", configName)
   				} else {
   					applogger.Errorf("AD组同步启动失败: %s - %v", configName, err)
   				}
   				return
   			}
   			defer s.sem.Release(1)

   			s.syncADGroups(syncCtx, configID)
   		}(config.ID, config.ConfigName)
   	}
   }
   ```

3. **Modify syncADGroups method** (around line 285) to use MemberSyncService:

   ```go
   // syncADGroups syncs only groups (not full sync) for a given config
   func (s *ADSyncScheduler) syncADGroups(ctx context.Context, configID string) {
   	applogger.Infof("开始组同步: configID=%s", configID)

   	adService := addomain.NewADDomainService(s.db)
   	result, err := adService.MemberSync.SyncAllMembers(ctx, configID)
   	if err != nil {
   		applogger.Errorf("组同步失败: %v", err)
   		return
   	}

   	applogger.Infof("组同步完成: 部门=%d, 成功=%d, 失败=%d, 总成员=%d, 添加=%d, 移除=%d, 耗时=%dms",
   		result.TotalDepts, result.SuccessCount, result.FailedCount,
   		result.TotalMembers, result.TotalAdded, result.TotalRemoved, result.Duration)
   }
   ```

Changes design rationale:
1. **Separate cron job**: Group sync runs on 15-minute interval, independent of 5-minute full sync check
2. **Smart execution**: Only triggers group sync for configs that have active mappings
3. **Async execution**: Uses same semaphore-based concurrency control as full sync
4. **MemberSyncService**: Calls SyncAllMembers from the MemberSyncService (Plan 23-11) which provides core sync functionality
5. **Logging**: Enhanced logging shows sync statistics for monitoring

Wave rationale: Plan 23-13 depends on 23-11 (MemberSyncService.SyncAllMembers), placing it in wave 5.

   // executeADGroupMemberSyncTask 执行AD组成员同步任务（供Scheduler调用）
   func executeADGroupMemberSyncTask(ctx context.Context, params map[string]interface{}) error {
   	if globalADSyncScheduler == nil {
   		return fmt.Errorf("AD同步调度器未初始化")
   	}

   	configID, ok := params["configId"].(string)
   	if !ok || configID == "" {
   		return fmt.Errorf("配置ID参数无效")
   	}

   	adService := addomain.NewADDomainService(globalADSyncScheduler.db)

   	_, err := adService.MemberSync.SyncAllMembers(ctx, configID)
   	return err
   }
   ```

These changes allow the main Scheduler to trigger group sync on-demand via API calls, in addition to the periodic cron triggers.

Task registration rationale:
1. **Consistent interface**: Follows same pattern as ad_data_sync task
2. **On-demand execution**: Allows manual triggering via API or scheduled execution
3. **Parameter validation**: Ensures configId is provided
4. **Service integration**: Uses ADDomainService to access MemberSyncService
5. **Error handling**: Checks globalADSyncScheduler nil state before execution

// GetADSyncStatus 获取AD同步状态
func GetADSyncStatus() map[string]interface{} {
	status := map[string]interface{}{
		"started": false,
	}

	if globalADSyncScheduler != nil {
		status["started"] = globalADSyncScheduler.IsStarted()
		if globalADSyncScheduler.cron != nil {
			entries := globalADSyncScheduler.cron.Entries()
			if len(entries) >= 2 {
				// Entry 0: 全量同步 (每5分钟)
				// Entry 1: 组同步 (每15分钟)
				status["full_sync_next_run"] = getNextRunTime(globalADSyncScheduler.cron, entries[0])
				status["group_sync_next_run"] = getNextRunTime(globalADSyncScheduler.cron, entries[1])
			}
			status["next_run"] = getNextRunTime(globalADSyncScheduler.cron)
		}
	}

	return status
}

// getNextRunTime 获取下次运行时间（支持指定entry）
func getNextRunTime(cron *cron.Cron, entries ...*cron.Entry) string {
	if len(entries) == 0 {
		entries = cron.Entries()
		if len(entries) == 0 {
			return "未设置"
		}
		entry := entries[0]
		if !entry.Next.IsZero() {
			return entry.Next.Format("2006-01-02 15:04:05")
		}
	} else {
		entry := entries[0]
		if !entry.Next.IsZero() {
			return entry.Next.Format("2006-01-02 15:04:05")
		}
	}
	return "未设置"
}
```

This enhancement allows monitoring systems to track both full sync and group sync schedules separately.

Status reporting rationale:
1. **Dual schedule tracking**: Shows next run time for both sync types
2. **Backward compatible**: Still works if only one cron entry exists
3. **Monitoring ready**: Provides visibility into scheduler health
