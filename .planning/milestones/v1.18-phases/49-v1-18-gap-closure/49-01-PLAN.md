<objective>
修复 Gap 3 —— v1.18 组件采集链路的前置根因:`sys_network_device.serial_number` 在 ruijie/huawei 在线设备上 100% 为空,导致下游 Gap 2 的资产关联(`ops_asset.devicesn = sys_network_device.serial_number`)无匹配。

诊断结论(2026-07-05,见 49-CONTEXT.md §Gap 3):chassis SN 采集链路的根因不是"没采集",而是**现有的 `parseRuijieDeviceInfo` / `parseHuaweiDeviceInfo` 字符串关键字解析器过于脆弱**(硬编码 "System Serial" / "Serial Number" 关键字 + 位置 fields[i+1]/fields[i+2] 取值),无法匹配生产 `show version` 输出的实际格式。而项目里已有**经过单测验证、对真机 fixture(`ruijie_10_62_63_21_show_version.txt` / `huawei_10_62_25_253_display_device_esn.txt`)稳定的现成解析器** `ParseShowVersionModules` / `ParseDisplayDeviceEsn`,只是从未在采集链路被调用。

本计划:在 `parseDeviceInfo` 收到 vendor 对应命令的原始输出后,**复用** ParseShowVersionModules / ParseDisplayDeviceEsn 提取 chassis 行的 SN,回填到 `info.SerialNumber`,沿用现有 `updateDeviceInfo` 的 only-if-empty 写回逻辑。

Purpose: 解锁 Gap 2(资产关联)和 Gap 1(板卡组件写入),让 `parent_asset_id` 能通过已填的 `serial_number = devicesn` 匹配 chassis 资产。
Output: `internal/services/device_info_collection_service.go` 修改 + 单测补充。
</objective>
