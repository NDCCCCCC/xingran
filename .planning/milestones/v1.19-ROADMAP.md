## Milestone Goal

补全网络设备"读+写"闭环——Web 端通过 SSH 直接对目标设备下发端口配置命令（启停/描述/dot1x），成功后立即采集一次端口信息回填审计。

MVP 范围：
- 3 厂商 × 5 操作（shutdown / undo shutdown / description / dot1x enable / dot1x disable）
- 单端口 + 批量（serial fail-fast，max=50）
- 完整审计（operlog + `sys_port_write_audit` 真相表）
- 权限隔离（`network:port:write` vs `network:port:query`）
- 前端 Modal/Drawer + 审计跳转 + 进度反馈

---

## Key Decisions (locked)

| 决策 | 说明 |
|------|------|
| 厂商命令模板硬编码 | `vendor → action → command_sequence` Go map（落地为先，后续抽象到 DB） |
| 厂商支持 | Huawei / H3C / 锐捷（MVP），Cisco 后续 |
| 操作后采集 | 复用 v1.18 `DeviceInfoCollectionService.Enqueue(deviceID)`（1-2s 后台 fire-and-forget） |
| 权限隔离 | 新 `network:port:write` 与原 `network:port:query` 拆分；组级 2-arg `RequirePermissions` |
| Audit 双轨 | `sys_oper_log` 高层摘要 + OperType 映射 (status=10/update=2/batch=16) + `sys_port_write_audit` 未脱敏真相表（11 列含 before/after_value + command_sent + device_response） |
| Path C 关联 | handler 先 INSERT audit 拿 audit_id → `operlog.Record(..., WithOperParam(audit_ids))`；`audit.oper_log_id` 列保持 NULL（避免侵入 operlog 包） |
| Batch 上下文 | detached `context.WithTimeout(context.Background(), 30*time.Minute)` 规避 `Core.Close()` 30s 截止陷阱 |
| Batch fail-fast | 串行执行；首条失败立即停并回传失败点；data-check 类错误 `continue`（不 break） |
| Real-device UAT | 模拟 SSH (`scrapligo FileTransport`) e2e + 真机 UAT 推迟到下次现场访问（per v1.18 Phase 48 precedent） |

## Issues Resolved (mid-execution)

1. **parseConfigError priority inversion** (Phase 51) — plan D-16 step 4-5 said "scan transportMarkers first" but Pitfall #3 boundary test required rejectionMarkers first. Resolution: scan rejection first, transport second. Semantics: device rejection takes priority over coincidental substring matches.

2. **device.Response struct mismatch** (Phase 51) — plan D-16 expected `resp.Err != nil` but actual struct has `resp.Failed bool`. Adapted to `resp.Failed == true`.

3. **mockDeviceExecutor cannot invoke fn closure** (Phase 51) — if mock invokes fn → panic on nil pc; if mock skips fn → parseConfigError(nil) → TransportError. Two-part fix: mock simplification + service executeWrite nil-guard on `lastResp`. Documented as defensive behavior for empty response edge cases.

4. **seedPortAndDevice duplicate INSERT** (Phase 51) — multi-port batch tests seeded same device repeatedly, violating UNIQUE(ip_address). Added First-or-Create idempotency.

5. **var device shadowing** (Phase 51) — `var device models.NetworkDevice` shadowed `device` package import. Renamed local to `dev`.

6. **execSinglePort DRY consolidation** (Phase 52) — 5 single-port handlers inlined identical flow. Extracted `execSinglePort` helper. Operlog.Record count: 6 → 2 (no semantic regression).

7. **Source-grep router test** (Phase 52) — gin runtime nil deref with empty Core. Switched to `os.ReadFile + strings.Contains` source assertions.

8. **`response.Error(c, int, msg)` convention** (Phase 52) — int is business code, HTTPStatus fixed 400 (pkg/response/response.go:160-162). Tests assert body.code not w.Code.

9. **D-07 parent menu name typo** (Phase 52) — ROADMAP/REQUIREMENTS wrote "端口管理" but DB sys_menu.menu_name is "端口状态". All code uses "端口状态"; pen-paper comment explains the divergence.

10. **go/ast strip Go comments** (Phase 52) — `grep -q IsFrame` flagged doc-comment literal mention. Switched to `go/parser + ast.Inspect` skipping `*ast.Comment` nodes.

11. **JSX.Element namespace** (Phase 53) — `tsc -b` strict mode rejects `JSX.Element` return type (React 19 + tsconfig). Switched to type inference (4 occurrences removed).

12. **2-cmd fixture double prompt** (Phase 54) — `SendConfigs` with file transport needs current prompt per cmd's `AcquirePriv`. Fixture uses double prompt lines.

13. **device_rejected fixture text** (Phase 54) — `% Error: Unrecognized command` hits scrapligo `failed-when-contains` first → TransportError path. Use `% Error: too many parameters` instead → rejectionMarkers.

14. **Driver.Close hangs on FileTransport** (Phase 54) — `network-on-close` needs more bytes. E2e harness skips `defer d.Close()`; Go GC reaps on test exit.

15. **eslint-disable placement** (Phase 55) — IN-02 initial placement above `useEffect` opening line was no-op (rule fires on `}, [])`). Moved directive immediately before `}, []);` per codebase precedent (App.tsx, MatchTestPanel, templates, exceptions).
