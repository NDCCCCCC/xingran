# Requirements: v1.19 网络设备写命令 (Network Device Port Write Operations) — ✅ SHIPPED 2026-07-08

**Project:** XingRan-Next 网络运维管理系统
**Milestone:** v1.19 网络设备写命令 (Network Device Port Write Operations)
**Goal:** 补全网络设备"读+写"闭环——Web 端通过 SSH 直接对目标设备下发端口配置命令（启停/描述/dot1x），成功后立即采集一次端口信息回填审计。

## v1.19 Requirements — Final Status

### SSH — SSH 写命令基础设施

- [x] **SSH-01**: 系统能通过 `scrapli/scrapligo v1.3.3` 的 `SendConfig` 接口在配置模式下向 Huawei VRP / H3C Comware / Ruijie RGOS 设备下发命令 — ✅ Phase 50 50-01 (template+SendConfig contract)
- [x] **SSH-02**: 系统能解析 `SendConfig` 返回结果中的 `% Error:` / `Unrecognized command` / `Illegal` 标记，区分 `transport_error` 与 `device_rejected`，并把错误信息回传前端 — ✅ Phase 51 51-01 (parseConfigError 5-step priority scan)
- [x] **SSH-03**: 系统能复用 `PooledConnection.GetConnection` + `defer conn.ReleaseRef()` 模式管理 SSH 连接生命周期（per-port Acquire/Release，不 per-batch）— ✅ Phase 51 51-01 (per-port Acquire/ReleaseRef)
- [x] **SSH-04**: 系统能在批处理中使用脱离 HTTP 请求上下文的 30 分钟超时 context（避免 `Core.Close()` 30s 截止陷阱）— ✅ Phase 51 51-01 (detached 30min context, verified in TestBatchWritePorts_DetachedContext)
- [x] **SSH-05**: 系统能维护硬编码 `vendor → action → command_sequence` 映射（落地为先，后续 phase 抽象数据库）— ✅ Phase 50 50-01 (vendor→template map)
- [x] **SSH-06**: 系统能通过 `DeviceCredentialHelper` 解析 device_id → 凭据（默认 fallback 策略沿用 v1.18）— ✅ Phase 51 51-01 (DeviceCredentialHelper)

### PORT — 端口操作（单端口精确）

- [x] **PORT-01**: 运维能在 Web 端对单个端口执行 `shutdown` 操作（Huawei/H3C: `shutdown`；Ruijie: `shutdown`）— ✅ Phase 52 52-01 (shutdown handler + endpoint)
- [x] **PORT-02**: 运维能在 Web 端对单个端口执行 `undo shutdown` 操作（Huawei/H3C: `undo shutdown`；Ruijie: `no shutdown`）— ✅ Phase 52 52-01 (undo shutdown handler + endpoint)
- [x] **PORT-03**: 运维能在 Web 端对单个端口设置 `description`（端口描述，≤ 80 字符）— ✅ Phase 52 52-01 (description handler + endpoint, 80-char enforced)
- [x] **PORT-04**: 运维能在 Web 端对单个端口开启 `dot1x`（Huawei/H3C: `dot1x enable`；Ruijie: `dot1x port-control auto`）— ✅ Phase 52 52-01 (dot1x enable handler + endpoint)
- [x] **PORT-05**: 运维能在 Web 端对单个端口关闭 `dot1x`（Huawei/H3C: `undo dot1x enable`；Ruijie: `no dot1x port-control`）— ✅ Phase 52 52-01 (dot1x disable handler + endpoint)
- [x] **PORT-06**: 系统能在写命令执行前读取端口当前 `admin_status` / `dot1x_enabled`，对已处于目标状态的端口提示"无需操作" — ✅ Phase 51 51-01 (checkPreState NoOp detector, verified in TestBatchWritePorts_AllSkipped_PreStateMatch + Phase 54 TestE2E_NoOp_AlreadyDown)

### BATCH — 批量操作

- [x] **BATCH-01**: 运维能在 Web 端一次性选中多端口（同设备）并对所有端口执行同一操作 — ✅ Phase 52 52-01 (batch handler + endpoint, requires cross-device pre-validation)
- [x] **BATCH-02**: 系统能以串行 + 失败即停（fail-fast）方式执行批量操作，第一条失败立即停止并回传失败点 — ✅ Phase 51 51-01 (serial fail-fast, verified TestBatchWritePorts_FailFast_*)
- [x] **BATCH-03**: 系统能返回部分执行结果 `{succeeded: [...], failed: [...], skipped: [...]}`，明确每端口状态 + 失败原因 — ✅ Phase 51 51-01 (partial result struct, Phase 54 BatchResult struct verified)
- [x] **BATCH-04**: 系统能限制批量操作最大端口数为 50（硬上限），超过时前端警告 + 后端拒绝 — ✅ Phase 51 51-01 (maxBatchSize=50, verified TestBatchWritePorts_ExceedsMax)
- [x] **BATCH-05**: 系统能在批量操作执行期间为前端提供进度反馈（已完成 / 总数 / 当前操作端口）— ⚠️ PARTIAL — Phase 53 53-02 wrapper layer + indeterminate Spin (D-05 decision: honest progress without fake X/Y); real-time SSE/WS → v1.19.x follow-up

## Out of Scope (explicitly excluded from v1.19 — same as planned)

| Feature | Rationale |
|---------|-----------|
| **自动回滚 (Automatic Rollback)** | 反向命令规划失败模式过多；`sys_port_write_audit.before_value` 已支持人工回退 |
| **定时写操作 (Scheduled Writes)** | 夜间运维无响应；如需走工单系统 |
| **多用户并发写仲裁** | operlog 留时间戳，last-write-wins 对 MVP 可接受 |
| **写命令中转重试** | `shutdown` 重试是危险操作 |
| **跨厂商统一命令抽象** | 精度损失；vendor→template map 已锁定 |
| **Cisco 设备支持** | 后续 phase (v1.19.x+) 加入 |
| **端口绑定 / 速率 / 双工 / VLAN 切换** | 后续 phase (v1.19.x+) 加入 |
| **dry-run 模式** | 后续 phase 加入 |
| **命令预览 UI** | 后续 phase 加入 |
| **操作历史查看 UI** | 后续 phase 加入（operlog 后端已记录）|
| **批量冲突自动解决 (skipped array)** | 后续 phase 加入 |
| **设备不可达预检** | 后续 phase 加入 |
