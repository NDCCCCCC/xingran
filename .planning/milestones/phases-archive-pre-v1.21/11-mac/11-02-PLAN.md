# LLDP Neighbor Map Structure (from Plan 01)

**CRITICAL:** The LLDP service returns a map with **already normalized interface names as keys**. This means:

1. LLDP discovery normalizes interface names before building the map (in Plan 01, Task 5)
2. MAC collection must also normalize interface names before lookups
3. Both sides use the same normalization function, ensuring successful lookups

```go
// From Plan 01 Task 5 - DiscoverNeighbors return value
// Map keys are NORMALIZED interface names (e.g., "gi01", not "GigabitEthernet0/1")
lldpNeighbors := map[string]*models.LLDPNeighborInfo{
    "gi01": &LLDPNeighborInfo{LocalInterface: "GigabitEthernet0/1", ...},
    "gi02": &LLDPNeighborInfo{LocalInterface: "GigabitEthernet0/2", ...},
}

// In MAC collection filtering - lookup with normalized key
normalizedIface := normalizeInterfaceName(mac.InterfaceName)  // "GigabitEthernet0/1" → "gi01"
if neighbor, exists := lldpNeighbors[normalizedIface]; exists {
    // Found LLDP neighbor - this is an uplink port
}
```

**Why this matters:** Without normalization on both sides, lookups would fail:
- LLDP returns map with key "GigabitEthernet0/1"
- MAC table has interface "gi0/1" (from vendor output)
- Normalization ensures both become "gi01" for matching
