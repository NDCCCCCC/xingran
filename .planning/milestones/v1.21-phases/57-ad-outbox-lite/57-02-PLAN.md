# 语义红线

- **禁 JSON payload**（D-05）：行内容只有 entity_type/entity_id/action_type/状态；Phase 58 排水闭包重读 DB 取全量最新值
- **禁"先查后写"应用层合并**（D-06）：不得出现 `SELECT ... WHERE entity_id=?` 再决定 INSERT/UPDATE 的写法；合并只由 ON CONFLICT 夺锁
- **ON CONFLICT 谓词必须文本级复用部分索引谓词**，且必须放在 **`TargetWhere`** 字段、裸 SQL 用 **`clause.Expr`**：
  - `TargetWhere: clause.Where{Exprs: []clause.Expression{clause.Expr{SQL: "status IN ('pending', 'failed')"}}}` —— 正确写法
  - ❌ **不得用 `Where`**：gorm v1.30.5 `clause/on_conflict.go:35` 渲染 `onConflict.TargetWhere`（冲突目标推断谓词），`:49` 渲染 `onConflict.Where`（`DO UPDATE` 的**尾随** WHERE）。谓词放 `Where` → 部分唯一索引不被推断 → PG `42P10 "there is no unique or exclusion constraint matching the ON CONFLICT specification"` / sqlite `ON CONFLICT clause does not match any PRIMARY KEY or UNIQUE constraint` → QUEUE-02 合并语义彻底失效（第二次插入直接报错而非合并）
  - ❌ **不得用 `clause.Literal`**：gorm.io/gorm v1.30.5 的 `clause` 包中不存在该类型（裸 SQL 表达式类型是 `clause.Expr`），写了编译不过
  - ❌ **不得加 `ad_push_queue.` 表名限定**（sqlite 对 partial index 的冲突目标是结构化比较，加限定符会失配 → "no such index"；统一用不带限定的写法）
  - **项目内已验证的正确先例**：`internal/services/asset/reconciliation_detection.go:426`（`:415` 注释记录了不用 TargetWhere 时的失败症状）
- **入队函数必须接收 `tx *gorm.DB`**：禁接收 `s.db`、禁 goroutine、禁 defer 中入队
- **前置条件查询用同一个 tx**：保证与 INSERT 同事务同 snapshot（T-57-02）
