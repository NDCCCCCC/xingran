<objective>
修复 database.go 启动序列安全问题:共识 C3(多副本/滚动重启下 REFRESH CONCURRENTLY 与 CREATE OR REPLACE VIEW 竞态失败,需 advisory lock)、codex HIGH(createDatabaseIfNotExists 吞错,后续 gorm.Open 报误导性错误)、codex MEDIUM(NowFunc 用本地时区,与 DB NOW() 不一致)、opencode MEDIUM(Host 已设但 Port==0 时静默掉 SQLite,掩盖配置错误)。

Purpose: 这三处都是"启动期静默走错路"型缺陷——出了问题时表象错误与根因相距甚远;advisory lock 则是 HA 部署的硬前提。
Output: 错误真实上抛、并发安全、UTC 一致、配置错误可见的启动序列。

**Tradeoff 记录:**
- NowFunc 切 UTC:历史行的 created_at/updated_at 是服务器本地时区,新写入为 UTC;PG timestamptz 列会按会话时区规范化存储,混合期查询结果按 timestamptz 语义正确,仅 naive timestamp 列(若有)存在解释漂移。用户已锁定修复,接受该过渡期。
- 42P04 容忍:理论上一个真正失败的 CREATE DATABASE 若恰好报 42P04 会被 WARN 放过——但 42P04 语义就是"已存在",后续 gorm.Open 会真实验证连通性,风险可接受。
</objective>
