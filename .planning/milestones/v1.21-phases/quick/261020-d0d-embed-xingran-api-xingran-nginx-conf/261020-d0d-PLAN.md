```
# XingRan nginx 站点配置示例（后端 embed 二进制 + nginx 剥前缀部署）
#
# 安装:
#   cp deploy/xingran.nginx.conf /etc/nginx/conf.d/xingran.conf
#   nginx -t && systemctl reload nginx
#
# 语义:
#   浏览器访问 http://<host>/xingran/... → nginx 剥掉 /xingran 前缀 →
#   转发给后端 http://127.0.0.1:9000/...（后端看到的路径不含前缀）。
#   这与后端 internal/server/embed_frontend_prod.go 里 frontendSubPath 的约定一致。
#
# ⚠ X-Forwarded-Prefix 必须设置:nginx 剥前缀后,浏览器访问 /xingran/ 会让后端收到 "/";
#   后端据此判定"已在子路径下"并直接返回 index.html（不 302 到 /xingran/）,
#   否则浏览器会在 "/" 与 "/xingran/" 之间无限跳转。
#
# 不装 nginx 也能用:直接访问 http://<host>:9000/ 时后端会 302 到 /xingran/,
#   且后端自身会剥掉 /xingran/api/... 的前缀（后端兜底，见 internal/server/subpath.go）。

map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}

upstream xingran_backend {
    server 127.0.0.1:9000;
    keepalive 32;
}

server {
    listen 80;
    server_name _;

    client_max_body_size 50m;

    # 站点根 → 子路径入口
    location = / {
        return 302 /xingran/;
    }

    # 无尾斜杠的子路径 → 补斜杠
    location = /xingran {
        return 301 /xingran/;
    }

    location /xingran/ {
        # 末尾的 "/" 是剥前缀语义: /xingran/api/v1/x → 后端收到 /api/v1/x
        proxy_pass http://127.0.0.1:9000/;

        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Prefix /xingran;

        # WebSocket 透传（通知公告 /api/v1/ws/...）
        proxy_set_header Upgrade    $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        proxy_connect_timeout 10s;
        proxy_read_timeout    120s;
        proxy_send_timeout    120s;
    }
}
```

- 不得改动后端端口 9000 与子路径 `/xingran` 这两个字面量（它们是 `internal/server/subpath.go` 里 `frontendSubPath` 的同一事实源）。

## Trust Boundaries

| Boundary | Description |
|---|---|
| 浏览器 → 后端（直连 :9000） | 请求路径由客户端完全控制，中间件按路径前缀做重写 —— 重写规则若过宽，会把本该 404 的路径映射到真实路由上。 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-Q261020-01 | Tampering | `StripSubPathMiddleware` 重写范围过宽（把任意路径映射到已注册路由） | medium | mitigate | 白名单只含后端真实注册路由的前缀（`/api`、`/uploads`），且必须 `rest == pre \|\| HasPrefix(rest, pre+"/")`；`/xingranfoo` 这类相似前缀不匹配；`/assets` 刻意不纳入（已由 ServeSPA/ServeFrontend 处理）。用例 `TestSubPath_Middleware_LeavesOtherPathsUnchanged` 逐条锁死。 |
| T-Q261020-02 | Spoofing | 客户端自带 `X-Forwarded-Prefix: /xingran` 头 → 根路径不重定向，浏览器停在 `/`（basename 不匹配 → 白屏） | low | accept | 该头只影响**是否重定向**这一个表现，不放宽任何鉴权、不新增路由可达面；直连场景下用户显式带该头等于自选"我已在子路径下"，退化结果 = 改前行为（白屏），非新增风险。nginx 场景由运维在 conf 里设置该头（Task 2 已固化）。 |
