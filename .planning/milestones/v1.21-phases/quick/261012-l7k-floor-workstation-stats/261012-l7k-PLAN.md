# 楼层管理页每行显示工位统计（总数/已使用/未使用/维护）

**Mode**: quick
**Date**: 2026-10-12
**Slug**: 261012-l7k-floor-workstation-stats

## Context

楼层管理页面（`xingran-react-frontend/src/pages/operations/floors/index.tsx`）的表格目前每行只显示楼层名称/楼层号/楼宇/面积/状态/描述/创建时间，看不到该楼层下有多少工位、用了多少。用户需要在楼层列表中直接看到每个楼层的工位统计。

**已探明的语义（探索模型后确认，实现必须遵循）：**

- `sys_workstation`（`internal/models/workstation.go`）的 `Status` 字段是**独立枚举**（不受全局 0=正常/1=停用 惯例约束）：
  - `0` = WorkstationStatusAvailable 空闲 → **未使用**
  - `1` = WorkstationStatusOccupied 占用 → **已使用**
  - `2` = WorkstationStatusMaintain 维护
- 关联键：`sys_workstation.floor_id`（varchar(64)，存楼层 UUID 字符串）→ `ops_floors.id`。统计查询**不需要 JOIN**（按页内 floor_id 集合 IN 过滤 + GROUP BY），天然规避 PG uuid/varchar 类型转换问题。
- 软删除：`sys_workstation.deleted_at` 必须排除（用 `Model(&models.Workstation{})` 让 GORM 自动加）。
- 缓存安全：`floorCacheService.List` 直接委托不缓存（`floor_cache_impl.go:150`），在 `floorService.List` 内注入统计不会产生陈旧缓存。
- **operlog：不需要** —— 本任务是 list 只读端点的响应扩展，无写操作。

**方案：后端 List 响应内联统计（2 条 SQL，零 N+1）+ 前端新增一列。**

## Tasks

### Task 1: 后端 — OpsFloor 增加 WorkstationStats 虚拟字段 + List 批量聚合注入 + service 测试

**Files:**
- `internal/models/operations/floor.go`（修改）
- `internal/services/operations/floor_service.go`（修改）
- `internal/services/operations/floor_workstation_stats_test.go`（新建）

**Action:**

1. 在 `internal/models/operations/floor.go` 增加：

   - 新类型 `FloorWorkstationStats`，四个 `int64` 字段：`Total`/`Used`/`Unused`/`Maintenance`，json tag 分别为 `total`/`used`/`unused`/`maintenance`。
   - `OpsFloor` 增加字段 `WorkstationStats *FloorWorkstationStats`，tag `gorm:"-"` + `json:"workstationStats,omitempty"`。**必须用 `gorm:"-"`（完全忽略）而非 `gorm:"->;-:migration"`** —— List 的 joinScope 用 `Select("ops_floors.*, ...")` 显式选列，`->` 会让 GORM 尝试扫描不存在的列（见 workstation.go:74-88 注释里的同款教训）。现有 `MarshalJSON`（floor.go:42，嵌入 `*Alias`）会自动序列化新字段，无需改动。

2. 在 `internal/services/operations/floor_service.go` 的 `List` 方法末尾（拿到 `*PageResult` 之后、return 之前）注入统计：

   - 从 `result.List` 类型断言 `[]operations.OpsFloor`（注意该包内 model 包别名为 `operations`）；断言失败或空页直接返回原 result。
   - 收集页内非空 `FloorID` 去重成 `[]string`；空则直接返回。
   - **单条聚合查询**（参照同文件 `Statistics` 的 `fmt.Sprintf` + CASE WHEN 风格）：

     ```go
     s.db.WithContext(ctx).
         Model(&models.Workstation{}).  // 需新增 import "github.com/ruoyi-next/ruoyi-go-backend/internal/models"
         Select(
             "floor_id",
             "COUNT(*) AS total",
             fmt.Sprintf("COALESCE(SUM(CASE WHEN status = %d THEN 1 ELSE 0 END), 0) AS used", int(models.WorkstationStatusOccupied)),
             fmt.Sprintf("COALESCE(SUM(CASE WHEN status = %d THEN 1 ELSE 0 END), 0) AS unused", int(models.WorkstationStatusAvailable)),
             fmt.Sprintf("COALESCE(SUM(CASE WHEN status = %d THEN 1 ELSE 0 END), 0) AS maintenance", int(models.WorkstationStatusMaintain)),
         ).
         Where("floor_id IN ?", floorIDs).
         Group("floor_id").
         Scan(&rows)
     ```

     `rows` 是 `[]struct{ FloorID string; Total, Used, Unused, Maintenance int64 }` 局部类型。`Model(&models.Workstation{})` 自动附加 `deleted_at IS NULL` 软删过滤。状态值必须引用 `models.WorkstationStatus*` 常量（禁止魔法数字内联）。

   - 把 rows 构建 `map[floorID]*FloorWorkstationStats`，遍历页内楼层回填 `WorkstationStats` 字段；**无工位的楼层保持 nil**（前端渲染 "-"）。
   - 抽成私有方法 `attachWorkstationStats(ctx context.Context, floors []operations.OpsFloor)` 供 List 调用，保持 List 主体可读。

3. 新建 `floor_workstation_stats_test.go`（package operations），**复用 `floor_service_crud_test.go` 的 `newFloor91TestDB`**（已 AutoMigrate sys_workstation，零新增基建）：

   - **Test 1 基本聚合**：建 2 楼层；F1 挂 3 工位（status 0/1/1），F2 挂 2 工位（status 2/1）。`svc.List(ctx, map[string]interface{}{})` → 断言 F1 stats `{3,2,1,0}`、F2 stats `{2,1,0,1}`。
   - **Test 2 软删排除**：在 F1 下再建 1 个 status=1 工位后 `db.Delete` 软删它 → List 后 F1 total 仍为 3。
   - **Test 3 空楼层**：第 3 个楼层无任何工位 → 该行 `WorkstationStats == nil`，且序列化 JSON 中无 `workstationStats` 键（omitempty）。
   - **Test 4 分页隔离**：pageSize=1 只返回第一页时，聚合只覆盖页内 floor_id（断言 list 长度 1 + 首行 stats 正确）。
