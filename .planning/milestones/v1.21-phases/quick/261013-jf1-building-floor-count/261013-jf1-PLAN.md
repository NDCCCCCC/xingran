# 楼栋管理页每行显示该楼栋的楼层数（实时 COUNT）

**Mode**: quick
**Date**: 2026-10-13
**Slug**: 261013-jf1-building-floor-count

## Context

需求原文是"楼栋管理页每行添加显示楼层数"。探索后确认实际状态与需求假设有偏差，本任务的本质是**把已有的楼层数显示修正为实时准确值**：

- **"楼层数"列已存在**：`xingran-react-frontend/src/pages/operations/buildings/index.tsx:407-415`，`dataIndex: "totalFloors"`，render `v || 0`（无楼层显示 `0`，**不是 "-"**）。
- **数据源是持久化反范式列** `ops_buildings.total_floors`（`internal/models/operations/building.go:25`），由楼层增删事件驱动同步（`floor_service.go:137/145/220/468-487`）。
- **已确认的漂移路径（显示值不可信的根因）**：
  1. 楼层 `Update` **换楼**时全程不重算 total_floors（`floor_service.go:148-210` 无任何 `updateBuildingFloorCount` 调用）→ 旧楼计数虚高、新楼虚低；
  2. 楼宇 Excel 导入直接写用户上传的 totalFloors 值（`excel_service.go:1351` 数值解析分支）→ 与实际楼层行数无关。
- **需求语义（orchestrator 锁定）**：楼层数 = 该楼栋下 `ops_floors` 行数（软删 `deleted_at` 排除）；无楼层显示 "-"。

**方案（同构复刻 261012-l7k 楼层工位统计模式）**：OpsBuilding 新增 `FloorCount *int64` 虚拟字段（`gorm:"-"`），`buildingService.List` 末尾按页内 building_id **单条 GROUP BY 聚合**注入；前端把既有"楼层数"列切到实时字段，nil 渲染 "-"。**不改** `totalFloors` 持久化字段及其事件同步（Excel 导出 `excel_export_config.go:146` 仍映射 total_floors，行为不变）。

**与昨天任务的模型差异（实现必须知道）：**
- `OpsBuilding` **没有**自定义 `MarshalJSON`（不像 `OpsFloor` 的 `*Alias` 嵌入模式）→ 新字段带正常 json tag 即自动序列化，无需 Alias 处理。
- 关联键 `ops_floors.building_id`（varchar(64) 存楼栋 UUID 字符串）→ 页内 `building.ID`（Go string）`IN` 过滤，**无需 JOIN**，天然规避 uuid/varchar 转换。
- building List 走 `base.GORMRepository[OpsBuilding]`（`building_service.go:144-148` 直接 `return s.repo.List(...)`），`PageResult.List` 是 `interface{}`（`internal/services/base/service.go:30`）→ 需类型断言。
- 无 List 级缓存（仅 SearchBuildingOptions 下拉有 5min 缓存）→ service List 内注入统计无陈旧缓存风险。

## Constraints / Conventions

| 约束 | 来源 |
|------|------|
| 聚合必须单条 GROUP BY 批量查询，禁止 N+1（禁止 list 循环逐楼 COUNT，也禁止改用逐行关联子查询） | 本 quick 约束 |
| `gorm:"-"`（完全忽略）而非 `gorm:"->"`：selectScope 用 `Select("ops_buildings.*, ...")` 显式选列，`->` 会让 GORM 尝试扫描不存在的列 | `floor.go:42-46` 同款教训 |
| Handler-Service 模式；只改 service 层 + model，handler/router 零改动 | CLAUDE.md |
| operlog 不需要（只读 list 扩展，无写操作） | planning context |
| 状态惯例不涉及（本任务无 status 语义）；魔法数字禁令：聚合不引用 status | — |
| 改 Go 后必须 `go build ./...`；改前端后必须 `npm run type-check` | CLAUDE.md |
| 排序参数保持 `totalFloors`：后端白名单 `building_service.go:80` 只认 `"totalFloors": "total_floors"`，sort 请求发 `floorCount` 会落出白名单静默失效（regression） | `building_service.go:80` |
| 换楼不重算 total_floors 是**预先存在的独立缺陷**，本任务不修（scope constrainment；实时 COUNT 使显示层对该漂移免疫） | CLAUDE.md Debugging Scope Constrainment |

**Action:**

1. `internal/models/operations/building.go`：`OpsBuilding` struct 末尾（`OrderNum` 之后）增加字段 `FloorCount *int64`，tag `gorm:"-"` + `json:"floorCount,omitempty"`。附注释说明：楼层数实时统计（buildingService.List 按页内 building_id 批量 GROUP BY 注入，非表列）；必须 `gorm:"-"` 而非 `->`（selectScope 显式选列，`->` 会扫描不存在列）；nil = 聚合未覆盖/无楼层，配合 omitempty 序列化不出键。**不要**给 OpsBuilding 加 MarshalJSON（无既有自定义 MarshalJSON，普通 json tag 自动带出）。`TotalFloors` 字段原样保留不动。

2. `internal/services/operations/building_service.go`：
   - 新增私有方法 `attachFloorCount(ctx context.Context, buildings []operations.OpsBuilding)`，**逐字平移** `floor_service.go:312` `attachWorkstationStats` 的结构（同包直接参照）：
     - 收集页内非空 `ID` 去重成 `[]string`；空则 return。
     - 单条聚合查询（`Select("building_id", "COUNT(*) AS floor_count")` + `Where("building_id IN ?", ids)` + `Group("building_id")` + `Scan(&rows)`），`Model(&operations.OpsFloor{})` 起链让 GORM 自动附加 `deleted_at IS NULL` 软删过滤。`rows` 为局部类型 `[]struct{ BuildingID string; FloorCount int64 }`。
     - 查询失败：`logrus.WithError(err).Warn("[building] 楼层数聚合失败，按无统计降级")` 后 return（best-effort，失败行 FloorCount 保持 nil → 前端 "-"；需新增 `sirupsen/logrus` import）。
     - 构建 `map[buildingID]int64` 回填 `buildings[i].FloorCount`；无楼层的楼栋保持 nil。
   - `List` 方法（building_service.go:137-149）改为：先接住 `s.repo.List(...)` 的 `(*PageResult, error)`；err 非 nil 原样返回；`result.List.([]operations.OpsBuilding)` 断言失败或空页直接返回原 result；成功则调 `s.attachFloorCount(ctx, buildings)` 后返回 result。

3. 新建 `internal/services/operations/building_floor_count_test.go`（package operations），**复用** `floor_service_crud_test.go` 的 `newFloor91TestDB`（已 AutoMigrate OpsBuilding + OpsFloor）与 `seedFloor91Building` 帮助函数，零新增基建。楼层用 `db.Create(&operations.OpsFloor{Name:..., FloorNo:..., BuildingID: b.ID})` 直建（同楼宇 FloorNo 需互异）。测试用例：
   - **BasicAggregation**：B1 挂 2 层、B2 挂 1 层、B3 挂 0 层。`NewBuildingService(db).List(ctx, map[string]interface{}{})` → 断言 B1 `FloorCount` 值 2、B2 为 1、B3 为 nil；对 B3 行 `json.Marshal` 断言输出**不含** `floorCount` 键（omitempty）。
   - **SoftDeleteExcluded**：B1 挂 2 层后 `db.Delete` 软删其一 → List 后 B1 FloorCount 为 1。
   - **PaginationIsolation**：两栋楼各挂不同层数，`List(ctx, map[string]interface{}{"current": 1, "pageSize": 1})` → list 长度 1 且首行 FloorCount 正确（聚合只覆盖页内 building_id）。
