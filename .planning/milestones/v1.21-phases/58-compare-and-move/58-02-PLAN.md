### `NormalizeDN(dn string) string` —— 纯字符串轻量归一

注释必须写明（这是研究 F-C/D 的核心决策）：
```
// NormalizeDN DN 归一化，**仅用于比较**，绝不用于回写 AD 或生成 DN。
//
// 语义（纯字符串，永不失败、永不 panic、可单测）：
//  1. 整体 TrimSpace
//  2. 按 "," split，逐段 TrimSpace
//  3. 每段按首个 "=" 切分：attr 名 ToLower；值去首尾空格后**同样 ToLower**
//  4. 用 "," 无空格重新拼接
//
// ⚠ 为什么值也要 ToLower（Phase 58 revision 决策，取代早期"值原样保留"的注释）：
//   AD DN 的**属性名**（CN/OU/DC）与**属性值**（zhangsan / IT / corp）对 LDAP 匹配都是
//   大小写不敏感的（matchingRuleInCaseIgnoreMatch）。真实域控回写的 OU DN 大小写与本地
//   sys_dept_ou_mapping.ou_dn 经常不一致（`OU=IT,DC=corp,DC=com` vs `ou=it,dc=corp,dc=com`），
//   只归一 attr 名会让 compare-and-move 的幂等比较判为不等 → 重复 MoveUser → 第二次对已搬
//   移的源 DN 调 ModifyDN 直接 code 32（ldap_client.go:350-361，deleteOldRDN=true）。
//   ToLower 对转义序列是安全的：RFC4514 的转义字符（`\,` `\+` `\=` `\<` `\>` `\;` `\"`
//   `\` `#` 前导空格）与十六进制转义（`C`）都**不含大写字母以外的语义** —— 即 `C` 与
//   `c` 在 LDAP 语义下等价，ToLower 不破坏转义含义。
//
// ⚠ 刻意不用 ldap.ParseDN：存量 sys_dept_ou_mapping.ou_dn 是 dept_sync_service.go:115
// 写入的未转义值，ParseDN 遇未转义特殊字符会失败，只能退回字符串路径。
// ⚠ 与 utils.go:295 ParseOUDN 的分工：ParseOUDN 返回 DN 的层级切片供解析使用；
// NormalizeDN 返回可比较的规范化字符串。两者都不做大小写归一之外的处理，
// 但 NormalizeDN 额外把 attr 名小写化 —— AD 的 DN 属性名本身大小写不敏感。
```
实现按上述 4 步；空串返回空串；无 `=` 的段原样保留小写化后的整段。

### `BuildOUDN(deptName, parentOUDN string) string` —— 部门名 → OU DN

```
// BuildOUDN 部门名 → OU DN 拼接（HYGIENE-02）。全仓唯一拼接点的唯一出口。
//   - 转义一律走 ldap.EscapeDN（RFC4514），**禁手写转义表**（双重转义/漏字符）
//   - ⚠ ldap.EscapeDN 不转义 "="：以 "=" 开头的部门名是残留边界，
//     在 EscapeDN 之后再对前导 "=" 补一个 "\"（不补会产生非法 RDN）
//   - parentOUDN 为空时只返回 "OU=<escaped>"，不产生悬空逗号
```
即：`if parentOUDN == ""` → 返回 `"OU=" + escaped`；否则 `fmt.Sprintf("OU=%s,%s", escaped, parentOUDN)`。

### `MatchADConfigByDN(dn string, configs []models.ADConfig) (*models.ADConfig, error)` —— 纯函数（无 DB）

注释写死契约（D-02）：
```
// MatchADConfigByDN 按 sys_user.ad_dn 归属解析所属 AD 配置（Phase 58 D-02 契约）。
//
// 纯函数：无 DB、无副作用、可单测。调用方（排水器）负责把"无匹配/歧义"映射为队列行 dead。
//
// 算法：
//  1. 目标 DN 归一：NormalizeDN(dn)
//  2. 候选 = configs 中 status == models.ADConfigStatusEnabled 的配置（软删由调用方查库时过滤）
//  3. 命中判定**必须带逗号边界**：strings.HasSuffix(norm, ","+NormalizeDN(cfg.BaseDN))
//     —— 裸 HasSuffix 会让 "CN=a,DC=xcorp,DC=com" 被 "DC=corp,DC=com" 误命中（P6）
//  4. 取 base_dn **最长**者（最长后缀唯一匹配）
//  5. 最长长度并列 → 歧义 → error；无任何候选命中 → error
//  6. 跳过 BaseDN 为空的配置（配置未填 base_dn 时不能参与匹配，否则空串后缀恒命中）
```
错误文案必须可 grep：
- 歧义：`fmt.Errorf("AD 配置歧义: DN %s 同时匹配多个等长 base_dn (%s)", dn, strings.Join(tiedBaseDNs, " | "))`
- 无匹配：`fmt.Errorf("无匹配 AD 配置: DN %s 未命中任何启用配置的 base_dn", dn)`

⚠ 返回的指针指向 `configs` 切片的元素（调用方持有整个 slice，生命周期安全）；**不得**返回副本后再被调用方误当作独立对象修改。
