# Requirements: v1.20 网络设备 VLAN + 端口绑定 — PLANNING 2026-07-09

**Project:** XingRan-Next 网络运维管理系统
**Milestone:** v1.20 网络设备 VLAN + 端口绑定 (Network Device VLAN + Port Binding)
**Goal:** 在 v1.19 端口写命令 MVP 基础上扩展 2 个新写命令：① 修改 access VLAN ② IP+MAC+Port 静态绑定。复用 v1.19 vendor 模板 / operlog / 权限 / 批量 / e2e 全套基建。

---

## v1.20 Requirements — Draft

### VLAN — 修改 access VLAN

- [ ] **VLAN-01**: 运维能在 Web 端对单个端口执行 `set_access_vlan` 操作，指定 VLAN ID (1-4094)
- [ ] **VLAN-02**: 系统能通过 vendor-specific 命令下发 `set_access_vlan`（Huawei: `port default vlan <id>` / H3C: `port access vlan <id>` / Ruijie: `switchport mode access` + `switchport access vlan <id>`）
- [ ] **VLAN-03**: 系统能在下发前读取端口当前 PVID / Access VLAN（`dis port vlan` / `show int status`），与目标 VLAN ID 一致时 NoOp 短路
- [ ] **VLAN-04**: 运维能在 Web 端一次性对多端口（同设备）执行 `set_access_vlan` 批量操作，复用 v1.19 批量三态机
- [ ] **VLAN-05**: 系统能在 service 层校验 VLAN ID 范围 (1-4094)，越界返回参数错误
- [ ] **VLAN-06**: 系统能在 `sys_port_write_audit` 表记录 `set_access_vlan` 的 before_value (`{vlanId, linkType}`) / after_value (`{vlanId, linkType}`) JSON

### BIND — IP+MAC+Port 静态绑定

- [ ] **BIND-01**: 运维能在 Web 端对单个端口执行 `port_binding add` 操作，指定 IP Address (必填) + MAC Address (可选)
- [ ] **BIND-02**: 运维能在 Web 端对单个端口执行 `port_binding remove` 操作，指定 IP Address (必填) + MAC Address (可选)
- [ ] **BIND-03**: 系统能通过 vendor-specific 命令下发 `port_binding add`（Huawei: `user-bind static ip-address <IP> [mac-address <MAC>] interface <iface>` / H3C: 同 Huawei 结构 / Ruijie: `switchport port-security binding <IP>`）
- [ ] **BIND-04**: 系统能通过 vendor-specific 命令下发 `port_binding remove`（Huawei: `undo user-bind static ...` / Ruijie: `no switchport port-security binding <IP>`）
- [ ] **BIND-05**: 系统能在下发前读取端口当前绑定表（`dis user-bind static all` / `show port-security binding`），对已存在的 (ip, [mac], interface) tuple 短路（add → NoOp; remove → NoOp）
- [ ] **BIND-06**: 运维能在 Web 端一次性对多端口（同设备）执行 `port_binding` 批量操作，复用 v1.19 批量三态机
- [ ] **BIND-07**: 系统能在 service 层校验 IP Address (IPv4 regex) + MAC Address (MAC regex, optional)

### INFRA — 基础设施

- [ ] **INFRA-01**: 系统能在 `sys_port_write_audit` 表记录 `port_binding` 的 before_value (`{ipAddress, macAddress?}` 或 null) / after_value (对应对象或 null) JSON
- [ ] **INFRA-02**: 系统能新增 2 个 kebab HTTP 端点：`POST /network/ports/write/set-access-vlan` + `POST /network/ports/write/port-binding`（复用 v1.19 batch 端点 `POST /network/ports/write/batch`）
- [ ] **INFRA-03**: 系统能为 `set_access_vlan` 走 `operlog.OperTypeUpdate=2`，`port_binding add` 走 `operlog.OperTypeCreate=1`，`port_binding remove` 走 `operlog.OperTypeDelete=3`
- [ ] **INFRA-04**: 系统能复用 `network:port:write` 权限覆盖新 2 个 actions（不新增 perm 常量；复用 v1.19 端口配置 F 型按钮菜单）

### UI — 前端

- [ ] **UI-01**: 系统能在 `src/types/network.ts` 新增 `SetAccessVlanRequest` / `PortBindingRequest` TypeScript 类型（包含 reason 字段）
- [ ] **UI-02**: 系统能在 `src/lib/api/networkApi.ts` 新增 `writeSetAccessVlan` + `writePortBinding` 2 个 wrapper（kebab URL 对齐 + 0 try/catch + 0 Toast 重复）
- [ ] **UI-03**: 系统能在 `src/components/network/port-write/SetAccessVlanModal.tsx` 提供 VLAN ID InputNumber (1-4094) + reason 字段，复用 v1.19 `port-write/constants.ts` 的 REASON 校验
- [ ] **UI-04**: 系统能在 `src/components/network/port-write/PortBindingModal.tsx` 提供 op Radio (add/remove) + IP Input + MAC Input (optional) + reason 字段
- [ ] **UI-05**: 系统能在 `src/pages/network/ports/index.tsx` 的"端口操作"下拉新增"修改 access VLAN" + "端口绑定" 2 个菜单项，复用 v1.19 ActionButtons 模式
- [ ] **UI-06**: 系统能在 `src/components/network/port-write/BulkWriteDrawer.tsx` 复用 v1.19 三态机 + 审计跳转 Toast，零改动支持新 2 个 action

### TEST — 测试

- [ ] **TEST-01**: 系统能在 `internal/services/portcollection/vendor_port_template_test.go` 新增 12+ 测试用例覆盖 3 厂商 × 2 actions × 至少 2 变体（带/不带 MAC、add/remove）
- [ ] **TEST-02**: 系统能在 `internal/services/portwrite/pre_state_check_test.go` 新增 6+ 测试用例覆盖 VLAN (PVID match/mismatch) + binding (exists/not-exists) 各 3 厂商

  - TestE2E_PortBinding_Ruijie_Add_Success

- [ ] **TEST-05**: 系统能在 `.planning/phases/56-w1-v1.20.1-access-vlan-port-binding/56-HUMAN-UAT.md` 创建 UAT deferral 文档：
