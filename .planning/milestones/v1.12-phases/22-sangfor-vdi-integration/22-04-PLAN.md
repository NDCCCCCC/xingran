# Phase 22-04: VDI后端API层（完整VDI API集成）

## Objective

实现VDI虚拟机和服务器配置的HTTP API端点，包括路由注册、请求处理、响应包装和权限验证。所有操作都通过服务层调用真实的VDI API。

**Purpose**: 提供标准的RESTful API接口，支持前端调用和VDI管理操作，每个操作都调用VDI API

**Output**: 完整的后端API层，所有虚拟机操作都成功调用VDI API

### Handler-Router模式参考

从`building_handler.go`和`building_router.go`提取的关键模式：
1. Handler结构体包含Service依赖
2. 构造函数接收Service实例
3. Handler方法使用`handleJSONBinding`和`handleServiceError`辅助函数
4. Router配置使用`SetupXxxRouter`函数
5. 路由模式：`POST /list`, `POST /`, `POST /:id`, `POST /:id/update`, `POST /:id/delete`

### API响应规范

```go
// 成功响应
response.Success(c, data)

// 错误响应
response.Error(c, httpCode, message)
```

### VDI API端点设计

所有虚拟机操作端点必须通过服务层调用VDI API：

| 功能 | 端点 | HTTP方法 | 服务层方法 | VDI API |
|------|------|----------|-----------|---------|
| 创建VM | POST /vdi/vm | POST | CreateVM | POST /v1/vm |
| 删除VM | POST /vdi/vm/:id/delete | POST | DeleteVM | DELETE /v1/vm |
| 开关机 | POST /vdi/vm/operate | POST | OperateVM | POST /v1/vm/operate |
| 配置IP | POST /vdi/vm/config_ip | POST | BatchConfigIP | POST /v1/vm/config_ip |
| 重命名 | POST /vdi/vm/:id/rename | POST | RenameVM | PUT /v1/vm/:id/name |
| 绑定用户 | POST /vdi/vm/:id/bind_user | POST | BindUser | POST /v1/vm/:id/bind_user |
| 解绑用户 | POST /vdi/vm/:id/unbind_user | POST | UnbindUser | （本地操作） |
| 同步状态 | POST /vdi/vm/:id/sync | POST | SyncVMFromVDI | GET /v1/vm/:id |

3. **实现Create方法（调用VDI API创建虚拟机）**：
   ```go
   // Create 创建虚拟机
   // @Summary 创建虚拟机
   // @Description 创建新的虚拟机，调用VDI API
   // @Tags VDI管理
   // @Accept json
   // @Produce json
   // @Param request body vdiServices.CreateVMRequest true "虚拟机信息"
   // @Success 200 {object} response.Response{data=vdiServices.VDIVMDTO}
   // @Failure 400 {object} response.Response
   // @Failure 500 {object} response.Response
   // @Router /vdi/vm [post]
   func (h *VMHandler) Create(c *gin.Context) {
       var req vdiServices.CreateVMRequest
       if !handleJSONBinding(c, &req) {
           return
       }

       vm, err := h.vmService.CreateVM(c.Request.Context(), &req)
       if !handleServiceError(c, err, "创建") {
           return
       }

       response.Success(c, vm)
   }
   ```
4. **实现Delete方法（调用VDI API删除虚拟机）**：
   ```go
   // Delete 删除虚拟机
   // @Summary 删除虚拟机
   // @Description 删除指定的虚拟机，调用VDI API
   // @Tags VDI管理
   // @Accept json
   // @Produce json
   // @Param id path string true "虚拟机ID"
   // @Success 200 {object} response.Response
   // @Failure 400 {object} response.Response
   // @Failure 500 {object} response.Response
   // @Router /vdi/vm/{id}/delete [post]
   func (h *VMHandler) Delete(c *gin.Context) {
       id := c.Param("id")
       if id == "" {
           response.Error(c, http.StatusBadRequest, "虚拟机ID不能为空")
           return
       }

       if !handleServiceError(c, h.vmService.DeleteVM(c.Request.Context(), []string{id}), "删除") {
           return

       response.Success(c, nil)
   }
   ```

   func handleJSONBinding(c *gin.Context, obj interface{}) bool {
       if err := c.ShouldBindJSON(obj); err != nil {
           response.Error(c, http.StatusBadRequest, "请求参数错误")
           return false
       }
       return true
   }

   func handleServiceError(c *gin.Context, err error, operation string) bool {
       if err != nil {
           // 判断错误类型
           if errors.Is(err, apperrors.ErrNotFound) {
               response.Error(c, http.StatusNotFound, fmt.Sprintf("%s失败，记录不存在", operation))
           } else {
               response.Error(c, http.StatusInternalServerError, fmt.Sprintf("%s失败: %s", operation, err.Error()))
           }
           return false
       }
       return true
   }

### Task 2: 创建虚拟机Router

**Files**: `internal/api/v1/vdi/vm_router.go`

**Action**:
1. 创建 `vm_router.go` 文件
2. 实现路由配置：
   ```go
   package vdi

   import (
       "github.com/gin-gonic/gin"
       "github.com/xingran-next/xingran-go-backend/internal/core"
       vdiServices "github.com/xingran-next/xingran-go-backend/internal/services/vdi"
   )

   func SetupVMRouter(r *gin.RouterGroup, core *core.Core) {
       // 创建VDI客户端（使用第一个服务器配置）
       if len(core.Config.VDI.Servers) == 0 {
           return // 没有配置VDI服务器，跳过路由注册
       }

       serverCfg := core.Config.VDI.Servers[0]
       vdiClient := vdiServices.NewVDIClient(
           core.GetDB(),
           "", // serverID将在运行时确定
           serverCfg,
       )

       // 创建服务实例
       vmService := vdiServices.NewVMService(core.GetDB(), core.Cache, vdiClient)
       vmHandler := NewVMHandler(vmService)

       // 注册路由
       r.POST("/list", vmHandler.List)
       r.POST("", vmHandler.Create)
       r.POST("/:id", vmHandler.GetByID)
       r.POST("/:id/update", vmHandler.Update)
       r.POST("/:id/delete", vmHandler.Delete)

       // VDI特定操作（调用VDI API）
       r.POST("/operate", vmHandler.Operate)
       r.POST("/config_ip", vmHandler.ConfigIP)
       r.POST("/:id/rename", vmHandler.Rename)
       r.POST("/:id/bind_user", vmHandler.BindUser)
       r.POST("/:id/unbind_user", vmHandler.UnbindUser)
       r.POST("/:id/sync", vmHandler.SyncFromVDI)
   }
   ```

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP Request → Handler | 未信任的HTTP请求输入 |
| Handler → Service | 业务逻辑调用 |
| Service → VDI API | VDI服务器通信 |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-14 | Spoofing | API认证 | mitigate | 使用Auth中间件验证JWT token |
| T-22-15 | Tampering | 请求参数 | mitigate | 使用ShouldBindJSON验证请求格式，参数验证标签 |
| T-22-16 | Elevation of Privilege | 权限验证 | mitigate | 使用Permission中间件检查用户权限 |
| T-22-17 | Information Disclosure | 错误信息 | mitigate | 统一错误响应，不暴露内部实现细节，VDI API错误脱敏处理 |
| T-22-18 | Tampering | VDI操作 | mitigate | 所有VDI操作通过服务层调用，失败时回滚本地数据库状态 |
