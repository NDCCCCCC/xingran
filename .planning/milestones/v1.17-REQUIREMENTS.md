# Requirements: v1.17 资产对账 (Asset Reconciliation) — SHIPPED

**Project:** XingRan-Next 网络运维管理系统

## Milestone v1.17 Requirements — All Shipped

### RECON — 对账引擎核心

- [x] **RECON-01**: 系统能建立三路对账（物理链路 vs 系统责任人 vs AD managed_by），并按 Type A-F 分类（A 健康 / B 无主 / C 不一致 / D 未上线 / E 幽灵 / F AD 不一致）
- [x] **RECON-02**: 系统能基于 `ops_asset.mac1/mac2` + `sys_port_mac` + `sys_info_point` + `sys_workstation.user_id` 反向推导物理链路 user_id
- [x] **RECON-03**: 系统能计算置信度评分（physical +0.5 / declared +0.3 / ad +0.2），低于阈值进异常池
- [x] **RECON-04**: 系统能维护 `reconciliation_normalized` 物化视图，5 分钟增量刷新
- [x] **RECON-05**: 系统能在冲突检出时立即写入 `sys_data_reconciliation`，包含 raw_snapshot (JSONB) 完整快照
- [x] **RECON-06**: 系统能在修复回写后保留 7 天静默期（避免循环触发）
- [x] **RECON-07**: 系统能基于 `sys_config` 的 `asset.reconciliation.score.*` 与 `view.refresh_interval` 参数化运行行为

### EXCEPTION — 例外规则

- [x] **EXCEPTION-01**: 系统能按 CIDR 格式（如 `192.168.0.0/16`）配置 IP 段级别例外规则
- [x] **EXCEPTION-02**: 系统能配置 5 种 actions 组合（no_alert / no_notice / no_workorder / skip_severity / silence），多条规则取并集
- [x] **EXCEPTION-03**: 系统能在例外规则中设定有效期（expires_at），到期自动停用
- [x] **EXCEPTION-04**: 系统能提供"命中测试"工具，输入 IP/CIDR 实时返回命中规则与合并效果

### WORKORDER — 工单闭环

- [x] **WORKORDER-01**: 系统能在 critical / high 异常出现时，自动调用 `workorder.BaseService.Create()` 生成工单（带 6 类冲突分类）
- [x] **WORKORDER-02**: 系统能在工单状态变更时通过 `operlog.Record()` 写入审计日志

### MONITOR — 看板 + 告警

- [x] **MONITOR-01**: 系统能提供 6 个 Statistics 专用 COUNT 端点（Summary / ByConflictType / BySeverity / HealthTrend / TopUnresolved / ExceptionRuleStats），不依赖 `list.length` 防 MaxPageSize 钳制
- [x] **MONITOR-02**: 系统能通过 WebSocket 实时推送 critical 异常到前端
- [x] **MONITOR-03**: 系统能将高危异常写入 `sys_notice` 系统通知

### INTEGRATE — 前端整合

- [x] **INTEGRATE-01**: 系统能在工位详情页（`/ops/workstation/:id`）顶部显示健康度卡片（5 KPI + 趋势 mini chart），无权限时静默隐藏
- [x] **INTEGRATE-02**: 系统能在工位详情页的资产设备子表 + 域控设备子表中加入"对账健康"列（行内徽标）
- [x] **INTEGRATE-03**: 系统能在点击徽标时打开 `ReconciliationDrawer`（冲突摘要 / 历史变更 / 例外规则三 Tab）

### AUDIT — 审计 + 血缘

- [x] **AUDIT-01**: 系统能在所有对账相关写操作（标记已解决 / 例外 CRUD / 自动转工单）中调用 `operlog.Record()` 或 `operlog.RecordWithBody()`
- [x] **AUDIT-02**: 系统能在 `raw_snapshot` JSONB 中冻结触发时刻的三路原始值，支持事后溯源

### INFRA — 基础设施复用

- [x] **INFRA-01**: 系统能在 `sys_dict_type` / `sys_dict_data` 中 seed 4 个字典（`asset_reconciliation_conflict_type` / `asset_reconciliation_severity` / `asset_reconciliation_exception_action` / `asset_reconciliation_status`）
- [x] **INFRA-02**: 系统能在 `sys_config` 中 seed 8 个 config 项（refresh_interval / score.physical / score.declared / score.ad / default_expiry_days / critical_threshold / silence_after_resolved_hours / health.score_weights）
- [x] **INFRA-03**: 系统能在 `sys_workorder_category` 中 seed 6 个对账冲突分类（A-F）
- [x] **INFRA-04**: 系统能在 `internal/services/asset/cache_keys.go` 定义 8 个 cache key 常量与 helper 函数
- [x] **INFRA-05**: 系统能在 `src/lib/queryKeys.ts` 注册 9 个 reconciliation queryKey

### R5 — 半自动修复（可选）

- [x] **SC1**: 高置信度异常生成"修复建议"（含建议的 responsible_user_id + 理由）
- [x] **SC2**: 人工确认 UI（一键接受 / 拒绝 / 修改建议）
- [x] **SC3**: 一键回滚机制（所有修复可回滚到修复前状态）
- [x] **SC4**: 误修复率 < 1%（监控 + 告警）
- [x] **SC5**: 修复回写完整 operlog + raw_snapshot 留痕
- [x] **SC6**: 状态机：建议 → 待确认 → 已接受 / 已拒绝 → 已应用
- [x] **SC7**: R5 完成后 v1.17 milestone close
