# Plan 02 — RBAC-04：system 域 4 组严格化 + 新码 TS 提前声明

## Context

roles / menus / departments / posts 4 组（`internal/api/router.go:231-241 / 247-257 / 260-276 / 279-289`）仍是 ANY-of 组级语义：持组级任一码（含 list！）即可写。拆分范式完全照抄 `/system/users`（router.go:166-221 + user_router.go）：**读组保留组级 ANY-of（含 WithQuery），写组升为 authorized 兄弟组逐动作 `RequireStrictPermissions([单一码])`**。

⚠️ **兄弟分离是硬约束**（v124 fixture note §3.4.1 实施方修正）：gin `Group()` 继承父组中间件链——写组若是读组的子组，读组 ANY-of 仍先放行，病灶①不修。写组必须是 `authorized` 的兄弟组（`strictUserRouteGroup`，router.go:215-219 引用，可直接复用）。

## ⚠️ 窗口期显式声明（预期行为，非缺陷）

85 拆分后、87 播种前：**`xtgl` 等现有角色在 system 4 组的全部写操作会 fail-closed（HTTP 403）**。原因：`system:{role,menu,dept,post}` 4 模块 F 型码全为 0（tmp_ftype.json 实证，85-RESEARCH §B4）→ 新动作码无法授予任何角色 → Strict 精确匹配必拒。这是**预期行为**（无授予渠道的权限本就不该放行），85 不做任何数据补授（生产库零写入 + 播种归 87，`GrantNewMenuToRolesHavingParent` 届时补授）。本影响须同步登记进 phase STATE（85-04 收口）。
