# Plan 01 — RBAC-03：死表重建 + CI 校验接线（验收底座）

## Context

`GetRoutePermissions()`（`pkg/permission/config.go:224-290`，49 条）全仓唯一消费点是 `GetPermissionByPath` 自身定义处，**零调用点 = 死表**。且死表已与现行路由**漂移**（85-RESEARCH §A3，HIGH）：

| 死表登记 | 实际路由 | 漂移 |
|---|---|---|
| `POST /system/roles/batch-delete` | `POST /system/roles/batch`（`internal/api/v1/system/role_router.go:33`） | 路径不同 |
| `POST /system/depts/*`（前缀） | 组前缀实为 `/departments`（`internal/api/router.go:260`）；批量删除 `POST /departments/batch`（`department_router.go:53`） | 前缀+路径双漂移 |
| （缺登记） | `POST /system/posts/batch-delete`（`post_router.go:35`） | 缺登记 |

**接线选型 = CI 校验**（Lead 裁决，否决运行时查表：双轨判定 / matchPath 与 gin 匹配语义不一致 / 热路径查表开销）。`matchPath`/`GetPermissionByPath` 保留为纯数据 + 单测；真实守卫 = **写路由清单从路由注册代码扫描得出**（不是手抄表），与死表登记比对，未登记 → exit≠0。

**口径裁决（执行必须遵守）**：
- 事实源 = **源码重扫**。`tmp_routes.json` 有 system 4 组 0 条的系统性缺口（85-RESEARCH §0），只作盘点参考，**不作事实源**。扫描脚本须补内联中间件形态解析（`r.POST("...", middleware.X(...), core.Handler)`，85-RESEARCH §0 末段）。
- 规模口径 = **33 组 / ~110 条写路由**；ROADMAP 的「133 处」是含读的挂载口径，验收时不混用。
