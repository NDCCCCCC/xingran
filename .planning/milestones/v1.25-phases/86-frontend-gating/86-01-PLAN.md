# Plan 01 — W1：system 域有码页三态门控铺开（7 页）

W0（86-00）已把口径钉死：**76 页 = 2 页已接入 + 25 页有码待铺开 + 51 页带理由 N/A 豁免**。W1 铺开 **system 域 7 个有码页**，作为「铺开范式」的批量验证场。

### 为什么先做 system 域（三个理由）

1. **码最齐**：`systemUser` / `systemRole` / `systemMenu` / `systemDept` / `systemPost` 五个区块在 `src/constants/permissionCodes.ts:22-66` 全部声明完毕，**不需要任何新码**；
2. **窗口期无碍**：这 5 组码在 87 播种前无 F 型授权来源（`85-STATE.md:10`），前端「ready 且无码 → `visible:false` → 不渲染」与后端 fail-closed **同向**（`useActionPermission.ts:100-109`）——不渲染入口，用户根本点不到 403 的按钮，窗口期行为自洽，无需 feature flag；
3. **入口形态覆盖最全**：工具栏按钮 / 行操作（列在 `columns/`）/ 批量删除 / `<Switch>` / Excel 导入导出 五种形态在 system 域全部出现（ops 域的 Excel 入口密度更高，放 W2）。

### 实现模式（Lead 裁定 5：**每页 1 行 hook + 每入口 1 个 `permission:` 传参/条件渲染**）

> **⚠️ 门控点必须落在「用户可点的触发按钮」上（Excel 类入口铁律）**：`ExcelImportLazy` / `ExcelExport` / `BatchExportModal` / `NetworkExport` 的 **modal 容器**（dept 页的 `:314` / `:323`）只是弹窗壳子 —— 门控点若标在容器上，工具栏的**导入/导出触发按钮仍在 DOM 且可点**（点开的是被无条件渲染的 modal），与本 plan 的 acceptance_criteria「导入/导出按钮在 ready 无权限时**不渲染**」**直接冲突**。因此 Excel 类入口一律门控**触发按钮**（dept：导入 `:268-270` / 导出 `:271-273`）；modal 容器**可保留渲染**（其 `visible` 由按钮状态驱动 —— 按钮不渲染 ⇒ 弹窗永远打不开），也可一并条件渲染，**二者择一**，但**必须**保证触发按钮被门控。
>
> **裁定 #4「归最接近码」的落地口径**：某个码组缺少精确动作键时（如 `opsManagerOrg` / `opsManagerRule` 只有 `list/edit/delete`，**无 `add`**），把该写动作归到**语义最近的既有键**并在**源码注释写明归码理由**（如「新增机构 → `opsManagerOrg.edit`（该码组无 add 键，按最近码归属）」），**不自造新键**（86 零新增码，裁定 4）。

```tsx
// ① 页面顶部：1 行 hook
import { PERMISSION_CODES } from "@/constants/permissionCodes";
import { useActionPermission } from "@/components/shared";
const permGate = useActionPermission();

// ② ActionButtons 行操作：加 permission 字段（组件内已内建逐按钮门控）
{ key: "edit", label: "编辑", onClick: …, permission: PERMISSION_CODES.systemRole.edit }

// ③ 工具栏按钮 / Excel / 批量：条件渲染（visible=false 时不渲染；未就绪时 disabled+提示）
const permAdd = permGate.decide(PERMISSION_CODES.systemRole.add);
{permAdd.visible && <Button disabled={permAdd.disabled} title={permAdd.hint} …>新增</Button>}

// ④ 独立 Switch（两行）
const permToggle = permGate.decide(PERMISSION_CODES.systemMenu.edit);
<Switch disabled={permToggle.disabled} checked={…} />
```

**禁用形态**：不做 PageTable 级 hook；不做路由→码映射表；不改 `useActionPermission` / `ActionButtons` / `PageTable` / `FormModal` / `ConfirmDelete` 的契约语义（只消费）。`PageTable` 的 `batchDelete` prop 契约是 `{ onDelete, target }`（`src/components/shared/PageTable.tsx:60`，**无 permission 位**），因此批量删除在**页面层条件传参**：`batchDelete={permRemove.visible ? { onDelete: handleBatchDelete, target: "角色" } : undefined}`。

**⚠️ 三态陷阱（务必逐页自查）**：门控组件内部对「未就绪」返回 `visible:true, disabled:true`（`useActionPermission.ts:104`），因此**条件渲染用 `visible` 不会在未就绪时把入口藏掉**（未就绪 → visible=true → 仍渲染 → 但要显式把 `disabled` 传给按钮）。反之，**只写 `disabled` 不写 `visible` 判断**会导致 ready 无权限时按钮仍渲染 —— 这是本 plan 最常见的失败模式。
