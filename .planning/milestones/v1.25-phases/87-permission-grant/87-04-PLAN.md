# Plan 04 — RBAC-05：授权闭环组件测试 + 三层证据 + 决定性对照实验

## Context

### 前端零改造（研究已推翻 Lead 的最初假设）

`internal/services/system/menu_service.go:181-190` 的 `GetTree` 是 `Find(&menus)`，**无 `menu_type` / `visible` / `status` 过滤**；前端 `src/pages/system/role/hooks/useRoleData.ts:103-111` 的 `processTreeData` 也不按 `menuType` 过滤 ⇒ **F 型按钮在角色页本来就可见可勾选**。87 播种后 F 行进入树 ⇒ 角色页**无需任何前端改造**即可勾选。

⇒ 本 plan **不改授权组件**（`src/pages/system/role/index.tsx` 及其 hooks 零 diff），只**新建一个组件测试**证明闭环。

### 角色页授权链路（C 段实证）

antd **`Tree`（不是 `TreeSelect`）**，`Form.Item name="menuIds"`；`treeData` 来自 `POST /system/menus/tree-select`；勾选 → `onCheck` → `editForm.setFieldsValue({ menuIds: keyArray })`（`index.tsx:442-446`）→ 提交走 `POST /system/roles/:id/update`（`useRoleActions.ts:190-198`）→ 后端 `internal/services/system/role_service.go:384-452` 写 **`sys_role_menu`**。

### 后端放行的那一行（RBAC-05 的机制）

`pkg/middleware/permission.go:451-457` 的 `m.perms = ?`（`checkUserPermissionStrict` 精确匹配）—— F 行 + `sys_role_menu` 关联行齐了就立即放行。Step 2 继承在 `:214-256`（F → 父页面，**方向不可反**）。admin bypass 在 `:281-302`，键是 **`role_key='admin'`** ⇒ 夹具 `role_key` 必须用 `p87_*` 前缀且**只挂这一个角色**。权限缓存 **30s**（`pkg/middleware/permission.go:33`）⇒ 决定性对照实验必须**等 31s 或重启后端**。`InvalidateMiddlewarePermCache` **未接线**。

### 本机环境约束（决定哪些证据可自动产出）

| 事实 | 后果 |
|---|---|
| 本机**无 PG**（远程 `10.62.10.34:5432` 需口令，安全网拦截） | 迁移验证走 sqlite；生产侧只能**只读 SQL 判据** |
| **无 API-Key 认证路径**（`pkg/middleware/` grep `X-API-Key|api_key|apikey` 零命中；`apikey_router.go` 是业务端点不是认证通道） | HTTP 实测只能自签 JWT 或纯 SQL 判据 |
| 登录被 **AD + 滑块验证码**阻断（生产 `sys.auth.default.mode=ad`） | UI 实机不可代做 ⇒ 组件测试承担前端证据 |
| **生产后端进程当前未运行**（nginx 502；9000 端口是 MinIO） | 生产 HTTP 复测暂不可行 ⇒ 决定性对照走只读 SQL 口径 |
| 前端缓存叠加（后端 30s + 前端 5min 内存 + 30min sessionStorage，`MENU_CACHE_VERSION=1` 未变不会自动失效） | UI 实机验收必须清 sessionStorage `menu:cache` 或重新登录 |

### 三层证据**不可互相替代**（必须写进验收报告）

| 层 | 能证明 | **不能**证明 |
|---|---|---|
| DB 层（只读 SQL 等价判据） | 权限集是否含目标码 ⇒ 403/200 的判定依据 | HTTP 状态码本身 |
| HTTP 层（自签 JWT + curl） | 端点真的 403 / 200 且真生效 | 前端入口可见性 |
| 组件层（vitest） | F 节点可见 / 可勾选 / `menuIds` 携带 F id | 后端真的放行、库里真有 F 行 |
