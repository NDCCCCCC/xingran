## 新增章节 1：type-check gate 空转缺陷全程（发现 → 处置）

**定性**：「gate 语义 ≠ gate 结果」的实证案例——`npm run type-check` 为裸 `tsc --noEmit`，而根 tsconfig.json 为 solution-style（`files: []` 仅作 references 容器），实际检查 **0 文件恒 exit 0**（探针实测 0.09s / Files: 0）。CI 的 type-check 步骤同样受影响，全程未报警。

**发现**：Phase 94（API 工厂化）verifier 以真实配置探针（`tsc --noEmit -p tsconfig.app.json --diagnostics`）验证交付文件时暴露——真实检查面 3701 文件 / 12.97s，全仓恰好 **1 处存量错误**：`src/pages/network/backups/hooks/useRestoreTask.ts:47` TS2345（Phase 93 commit a4bfc71 引入，不在 94 改动清单）。94-VERIFICATION 判 human_needed 并登记 94-HUMAN-UAT，转本相裁决。

**处置（D-03 修复线，授权边界内）**：95-02 Task 1 落地——
1. `package.json` scripts.type-check：`tsc --noEmit` → `tsc --noEmit -p tsconfig.app.json`（探针实证选型；「根 config 补 references」方案已证伪——裸 tsc 不遍历 references；`tsc -b` 备选因 build-mode 语义混淆否决）
2. `useRestoreTask.ts:47`：`setTask(result.data)` → `setTask(result.data ?? null)`（TS2345 根因 = BaseResponse data 可选属性不可赋 null 联合；单 token 级修复）
