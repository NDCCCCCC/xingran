<action>
  1. **不新增 macInput state(option b 决定)**:
     - 明确不新增 `useState<string>("")` 行;AntD Form 作为 MAC 字段唯一源。
     - 依据:option a(新增 macInput + value={macInput})会让 Input 由 Form 与本地 state 共同管理,任一路径遗漏会导致漂移;option b(纯 Form)单一源彻底避免此问题。
  2. **Input onChange 改写**(行 213-219):
     - 当前(反模式):
       ```tsx
       onChange={(e) => {
         const formatted = normalizeMACAddress(e.target.value);
         if (formatted) {
           e.target.value = formatted;  // 🛑 BLOCKER:直接 DOM 写入
         }
       }}
       ```
     - 改为(纯 Form 驱动):
       ```tsx
       onChange={(e) => {
         const formatted = normalizeMACAddress(e.target.value);
         if (formatted) {
           form.setFieldValue("mac", formatted);
         }
       }}
       ```
     - 关键差异:删除 `e.target.value = formatted`;删除任何 setState/setMacInput 调用;仅保留 form.setFieldValue。
     - 行为对比:
       * 原:仅规范化(移除非法字符 + 格式化为 AA:BB:CC:DD:EE:FF)才更新;非法中间态时,form state 不变
       * 新:同样仅在规范化成功时同步 form state(行为等价,但走 React 状态路径而非直接 DOM 写入)
       * 用户输入 12 个合法字符:中间态可能含非法字符(如 "AA-BB-CC"),但 normalizeMACAddress 仅在输入完整 12 位十六进制时返回有效结果,因此 form state 仍按规范化结果更新(行为不变)
     - 注意:Form.Item 的 valuePropName="value" 由 AntD Form 管理,无需显式设置 `value` prop;Input 默认由 Form 接管。
  3. **Input value prop 不设置**(行 210-212):
     - 保留 `<Input placeholder="AA:BB:CC:DD:EE:FF" style={{ width: 200 }} ... />`,不显式添加 `value` 或 `defaultValue`(交给 Form.Item 管理)。
  4. **onBlur 保持不变**(行 220-226):
     - 失焦时 `form.setFieldValue("mac", formatted)` 仍生效,与 onChange 内 setFieldValue 形成"先实时同步 + 失焦再确认"的双重保险。
