## Locked Decisions from CONTEXT.md

**D-05**: 使用月度分区优化查询和清理性能
- 按 `first_seen` 字段按月分区
- 应用层自动创建分区（启动时检查未来 1-2 个月）
- 使用 BRIN 索引优化时间序列查询

**D-08**: 使用 DROP PARTITION 删除过期分区
- 保留期设为 120 天（90天 + 30天缓冲）
- 确保默认 90 天数据全部保留，避免分区边界问题
- 直接删除整个过期分区，瞬间释放空间

**D-09**: 使用定时任务（Cron）自动清理
- 复用现有 scheduler（internal/scheduler）
- 每天凌晨 2 点执行清理任务
- 检查并删除超过 120 天的完整月度分区

**D-10**: 使用数据库配置表存储保留期配置
- 配置键：`network.mac.history.retention_days`
- 默认值：120
- 支持运行时修改，无需重启应用
- 管理员可通过 UI 修改

   ```go
       CreateMonthlyPartition(ctx context.Context, year int, month int) error
       EnsurePartitionsExist(ctx context.Context, monthsAhead int) error
       DropExpiredPartitions(ctx context.Context) error
       GetRetentionDays(ctx context.Context) int
   }
   ```

2. **实现私有结构体** (`partitionServiceImpl`):

   - 构造函数: `NewPartitionService(db *gorm.DB) PartitionService`

3. **实现 CreateMonthlyPartition 方法** (按 D-05 决策):
   - 输入: year (年), month (月)
   - 生成分区名称: `sys_device_mac_history_YYYY_MM` (如 `sys_device_mac_history_2025_01`)
   - 生成 SQL DDL:
     ```sql
     CREATE TABLE IF NOT EXISTS sys_device_mac_history_2025_01
     PARTITION OF sys_device_mac_history
     FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');
     ```
   - 使用 `db.Exec()` 执行 SQL
   - 返回 error（失败时记录日志）

4. **实现 EnsurePartitionsExist 方法** (按 D-05 决策):
   - 输入: monthsAhead (未来月数，默认 2)
   - 计算当前年月和未来 N 个月
   - 对每个月调用 `CreateMonthlyPartition`
   - 忽略已存在的分区错误（`IF NOT EXISTS` 已处理）
   - 记录创建日志（`applogger.Infof`）

5. **实现 GetRetentionDays 方法** (按 D-10 决策):
   - 从 `sys_config` 表读取配置
   - 配置键: `network.mac.history.retention_days`
   - 默认值: 120
   - 查询逻辑:
     ```go
     var config models.Config
     err := s.db.WithContext(ctx).
         Where("config_key = ?", "network.mac.history.retention_days").
         First(&config).Error
     if err == nil && config.ConfigValue != "" {
         if days, parseErr := strconv.Atoi(config.ConfigValue); parseErr == nil && days > 0 {
             return days
         }
     }
     return 120 // 默认值
     ```

6. **实现 DropExpiredPartitions 方法** (按 D-08, D-09 决策):
   - 调用 `GetRetentionDays` 获取保留期
   - 计算截止日期: `now.AddDate(0, 0, -retentionDays)`
   - 查询现有分区: `SELECT tablename FROM pg_catalog.pg_inherits WHERE inhparent = 'sys_device_mac_history'::regclass`
   - 解析分区名称提取年月（`YYYY_MM` 格式）
   - 对比分区日期与截止日期
   - 删除过期分区: `DROP TABLE IF EXISTS sys_device_mac_history_YYYY_MM`
   - 记录删除日志（`applogger.Infof`）
   - 返回删除的分区数量和 error

7. **安全验证**:
   - 分区名称格式验证（`^\d{4}_\d{2}$`）
   - 年份范围检查（2020-2100）
   - 月份范围检查（1-12）
   - 防止 SQL 注入（使用参数化或严格验证）

8. **错误处理**:
   - 使用 `applogger.Errorf` 记录错误
   - 返回 error 供调用方处理

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config table → partition service | 配置值可能被恶意修改 |
| partition name → SQL DDL | 分区名称拼接风险 |
| scheduler → cleanup task | 定时任务参数注入 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-04 | Tampering | 配置表 `network.mac.history.retention_days` 被修改为极小值 | mitigate | 添加最小值检查（retention >= 30），拒绝无效配置 |
| T-12-05 | Injection | DROP PARTITION 分区名称未验证 | mitigate | 严格验证分区名称格式（`^\d{4}_\d{2}$），使用白名单 |
| T-12-06 | Denial of Service | 清理任务删除正在使用的分区 | mitigate | 仅删除完整过期的月度分区，检查分区边界 |

**Disposition Rationale:**
- T-12-04: 保留期配置过小会导致数据丢失，必须设置最小值（30天）
- T-12-05: DROP PARTITION 是危险操作，分区名称必须严格验证格式
- T-12-06: 清理任务应删除完整月度分区，避免删除当前使用的分区
</threat_model>
