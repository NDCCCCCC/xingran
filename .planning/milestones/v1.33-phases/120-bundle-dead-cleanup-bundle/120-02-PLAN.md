@xingran-react-frontend/src/utils/iconUtils.tsx

**Problem (iconUtils.tsx:546-550):**
```typescript
const DynamicIcon = lazy(() =>
  import(`@ant-design/icons/${iconName}`)  // bare template literal — Vite cannot analyze at build time
    .then((m) => ({ default: m.default ?? m[iconName] }))
    .catch(() => ({ default: () => null }))  // silently swallows all errors
);
```
Bare template literal in dynamic import: Vite/Rollup cannot determine the module at build time, so it cannot be code-split correctly. The `.catch(() => null)` silently swallows ALL errors — icons that fail to load appear as nothing.

**Solution:** The static registry (STATIC_ICON_REGISTRY, lines 116-214) already contains ALL icons from iconCategories. The dynamic path (lines 535-556) is unreachable for any icon in iconCategories because line 515 already returns from static registry first. The only case the dynamic path handles is icons added by backend but not registered here — which was always failing silently anyway.

**Action:** Delete lines 535-556 (dynamic import cache + lazy fallback). Keep only static registry path (lines 511-533, the two lookup steps). The dynamic cache at line 217 (`const dynamicIconCache = new Map()`) can also be removed since it will be unused.
</context>
