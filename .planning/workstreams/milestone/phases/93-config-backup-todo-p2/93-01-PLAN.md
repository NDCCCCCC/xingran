1. 在 config_backup_service.go 末尾（calculateHash 之前）新增三个包内私有成员：常量 `maxDecompressedConfigBytes = 64 << 20`；函数 `gzipCompress(config string) ([]byte, error)`（gzip.NewWriter(&buf) → Write → 显式 Close → 返回 buf.Bytes()；Close 必须在取字节之前）；函数 `gzipDecompress(data []byte) (string, error)`（gzip.NewReader 错误包装为 "备份文件损坏: %w"；io.ReadAll 改为 `io.LimitReader(gr, maxDecompressedConfigBytes+1)` 后 ReadAll，len(out) > maxDecompressedConfigBytes 时返回错误 "解压后内容超过大小上限"，ReadAll 错误包装为 "备份文件解压失败: %w"）。
2. 新增 `sanitizeBackupFileName(name string) string`：将 `\/:*?"<>|` 与控制字符替换为 "_"，去除首尾的点和空格，结果为空时返回 "device"（Windows/POSIX 双侧安全，防 DeviceName 夹带路径分隔符逃逸备份目录）。
3. 改造 CreateBackup 的 `req.CompressLarge` 分支（现 :156-162）：删除 `// TODO: 实现压缩` 注释与 `content := config` 中转变量；CompressLarge=true 时调用 gzipCompress，错误返回 `fmt.Errorf("压缩备份内容失败: %w", err)`；fileName 构造先用 sanitizeBackupFileName(req.DeviceName) 清洗，再在 `.conf` 后条件追加 ".gz"（仅当 CompressLarge）；`backup.Compressed = req.CompressLarge`；`backup.BackupSize = configSize` 保持原始字节口径不变；os.WriteFile 写压缩后字节。
4. 改造 GetBackupContent（现 :205-208）：删除 `// TODO: 解压` 注释；`isGz := strings.HasSuffix(backup.FilePath, ".gz")`；`backup.Compressed && isGz` 时 gzipDecompress 后返回；`backup.Compressed != isGz`（矛盾状态）返回错误 `fmt.Errorf("备份压缩状态不一致: compressed=%v, file=%s", backup.Compressed, backup.FilePath)`；均否保持现有明文返回。
5. 改造 createNewAutoBackup 的文件分支（现 :385-394）：与 CreateBackup 同构——fileName 用 sanitizeBackupFileName(device.DeviceName) 清洗 + ".gz" 追加、gzipCompress 压缩后写入、`backup.Compressed = true`、BackupSize 保持 len(config)；错误返回 "压缩备份内容失败: %w"。
6. import 补 "bytes"（如 helper 用 bytes.Buffer）与 "io"、"compress/gzip"。
</action>
