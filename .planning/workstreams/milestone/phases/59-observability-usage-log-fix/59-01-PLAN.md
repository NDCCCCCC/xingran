<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP 客户端 → MultiAuth middleware | untrusted X-API-Key header / 请求 ctx 跨越此边界；pre-auth 失败在此 abort |
| MultiAuth → 下游 handler / RequireScope | c.Next() 跨越；statusCode 经 c.Writer.Status() 回流 |
| logUsageAsync goroutine → DB | fire-and-forget 异步跨越请求生命周期； detached context 在此边界生效 |
| logUsageAsync → applogger → stderr/log file | DB 写入失败信息跨越；仅 apiKeyID UUID + path + err，无敏感字段 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-59-01 | Information Disclosure | usage_logger.go logUsageAsync 失败日志 | mitigate | `applogger.Errorf` 仅记录 apiKeyID（UUID，非 key 明文）+ Path（gin 已规范化 URL）+ err；LogUsageRequest 结构体本身无 key/secret/password/token 字段，无法泄露凭据 |
| T-59-02 | Denial of Service | usage_logger.go logUsageAsync goroutine 泄漏 | mitigate | `context.WithTimeout(context.Background(), 10*time.Second)` 兜底超时；DB 写失败仅 applogger 记录，不 panic、不阻塞业务、不重试；fire-and-forget 语义保持 |
| T-59-03 | Tampering | apikey.go Success 字段计算 | accept | Success 由 `c.Writer.Status()`（gin 内部管理的 int）派生，无外部输入污染路径；statusCode 不可被客户端操纵 |
| T-59-04 | Repudiation | apikey.go 记录点后移 | mitigate（本 phase 反而**提升**审计性） | 记录点移到 c.Next() 之后使 Success/StatusCode 真实反映请求结果，消除 P1-2「全零 → successRate ≈ 0%」的审计失真；D-04 进一步让写入失败可见 |
| T-59-SC | Tampering | go mod 依赖（package legitimacy gate） | accept | 零新增依赖（仅 import 既有 `pkg/logger`），无 npm/pip/cargo install 操作；gate 不适用 |

**Phase 安全态势净影响:** 正向——本 phase 修复后 API Key 使用日志真实可信（消除审计失真），写入失败可见（观测系统自身可观测），不引入新攻击面。ASVS V7 Error Handling & Logging 适用且满足。
