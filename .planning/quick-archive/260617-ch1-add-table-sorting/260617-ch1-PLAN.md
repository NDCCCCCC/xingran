  Extend `xingran-react-frontend/src/utils/tableHelpers.tsx` with a small set of generic sorter helpers. The design must follow the existing factory pattern (named exports that return partial `ColumnType` props, then spread via `{...config}`). Constraints from CLAUDE.md and the existing code:
  - `createStatusColumn` and `createDateTimeColumn` already use `...config` last, so they will accept `sorter` via the `config` arg automatically — DO NOT change their existing signature.
  - `createActionColumn` is action-only and must NEVER be sortable.
  - `createIndexColumn` is computed from page index and must NEVER be sortable.
  - Ant Design's `sorter` accepts a function `(a, b) => number`. For client-side sort, a plain comparator is enough.

  Concretely add:
  1. A `createSorter<T>(key: keyof T & string, opts?: { multiple?: number })` helper that returns `{ sorter: (a, b) => compareValues(a[key], b[key]) }`. `multiple` (priority) is optional; default to 1 so it composes with other sorters. Do NOT pass `sortDirections` — Ant Design's default is `['ascend', 'descend']`, matching the user's "点击切换升降序" requirement.
  2. A small `compareValues(a, b)` helper that handles `null`/`undefined`/numbers/strings/dates (use `dayjs(...).valueOf()` if either side is an ISO string and `dayjs(...).isValid()` is true, else fall back to `String(a).localeCompare(String(b))` for `b - a` style ordering only when both are numeric).
  3. Keep the helper types aligned with the existing `ColumnConfig` / `TableColumn<T>` types. Add `sorter` to `ColumnConfig` so that `Partial<ColumnConfig>` already supports it (TS-side, no runtime change).
  4. Do NOT introduce a runtime dependency. `dayjs` is already a project dep — use it.
  5. Add a short jsdoc block to `createSorter` explaining client-side only behavior (one paragraph).

  Do not refactor the rest of the file. Do not rename existing exports. The new exports are additive.
