    3. 新增 resolveLeaderByAncestors(ctx, dept *models.Department) (string, error) 方法：
       - 返回值是 leader 的 user.id（非 ad_dn，由 caller 再查 ad_dn）。
       - 流程：
         a. 当前部门 leader 非空 → 返回 *dept.Leader。
         b. 解析 dept.Ancestors（用 strings.Split(",", 去空格)），过滤掉 "0" 根占位符和当前 dept.ID，得到祖先 ID 列表（已按层级从近到远排序）。
         c. 一次性 SELECT id, leader FROM sys_dept WHERE id IN (?) AND leader IS NOT NULL AND leader != ''，构造 leaderMap[deptID]leader。
         d. 遍历祖先列表（顺序即层级），第一个出现在 leaderMap 的 → 返回其 leader。
         e. 都没有 → 返回 ("", nil)。
       - 额外保护：若 dept.Ancestors 中包含 dept.ID 自身（异常数据），跳过自身；递归深度自然受 ancestors 长度限制（通常 <20），但显式用计数器 i < maxLeaderDepth 兜底。

    4. 新增 SyncManagersToAD(ctx context.Context, userIDs []string) (*ManagerSyncResult, error) 方法：
       - 步骤 1：查 ADConfig（sync_enabled=true AND status=0），复用 SyncUserUpdateToAD 第 47 行的查询模式；未找到配置 → 直接返回 &ManagerSyncResult{}, nil（降级，不阻塞，记 WARN）。

       - 步骤 4：批量预加载所有涉及部门 + 其祖先部门到内存（避免 N+1）：
         * 收集所有用户 dept_id。
         * SELECT id, parent_id, ancestors, leader FROM sys_dept WHERE id IN (?) → 当前部门。
         * 调 resolveLeaderByAncestors 时传入完整 dept 对象（ancestors 已含祖先链）。
         * 优化：可一次性 SELECT 所有 dept_id + ancestors 展开后的所有祖先 ID 的 (id, leader) 构建全局 leaderMap，避免每个用户重复查（性能关键点，用户提到 ~1195 用户）。
       - 步骤 5：批量预加载所有 leader 用户 ID 对应的 (id, ad_dn)，构造 leaderAdDnMap[leaderUserID]adDn。
       - 步骤 6：创建 LDAPClient（NewLDAPClient(&adConfig)）+ Connect()，defer Close()。失败 → 返回 nil, fmt.Errorf("连接AD失败: %w", err)。

         * leaderID == "" → Skipped++（WARN: 无可用 leader）。
         * leaderID == user.ID → Skipped++（自指跳过，不覆盖原值）。
         * leaderAdDnMap[leaderID] == "" → Skipped++（WARN: leader 无 ad_dn）。
         * 否则 ldapClient.UpdateUserAttribute(*user.AdDn, {"manager": leaderAdDn}) → 成功：Synced++，更新该用户 ad_synced_at（复用 updateSyncTimestamp）；失败：Failed++，Errors 追加 "userID: <err>"，WARN 日志，不中断。
