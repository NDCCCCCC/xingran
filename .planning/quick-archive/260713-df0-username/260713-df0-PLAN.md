# 工位导入扩展 - 部门/用户/主设备序列号

**Mode**: quick
**Date**: 2026-07-13
**Slug**: 260713-df0-username

## Context

工位管理页面的 Excel 导入当前仅支持工位本体字段 + `deptName`/`userName` 两列（按名称匹配），没有主设备序列号入口，也没有"按部门代码导入"的便捷方式。用户痛点：

1. 批量导入工位时，必须先在 UI 里翻部门列表查到 dept_id，效率低
2. 跨表写入"主设备"目前只能在前端 `WorkstationDevice` 表手动添加，无法 Excel 批量
3. 已有 260614-dpz-workstation-main-device-merge 提供的 `SetPrimaryAndSave` 合并逻辑（AD/Asset 实时拉取 + 字段优先级合并）已封装好，导入场景只差一个"以 SN 为键调用"的入口

本 quick 的目标：

- ExcelConfig 增加 `deptCode`（按 `sys_dept.dept_code` 解析）和 `deviceSerial`（跨表特殊处理）两列
- 在 ExcelService.ImportData 事务提交后，新增 post-import hook，遍历含 `deviceSerial` 的行调用新增的 `SetPrimaryAndSaveBySerial`，失败计入 `result.Errors` 不阻断
- 新增独立端点 `GET /ops/dept/mapping-template` 下载部门名称↔代码映射表（xlsx）
- 前端导入 Modal 旁加"下载部门映射表"按钮

**复用而非重写**：

- `workstation_device_service.go:1065-1251` 的合并实现是本 quick 的"事实唯一源"，新方法 `SetPrimaryAndSaveBySerial` 必须共用同一段合并代码（不要复制粘贴）
- `excel_handler.go:163-180` `downloadTemplate` handler 模式可直接复用做映射表下载
- `excelApi.downloadTemplate` 已有完整下载链路（fetch → blob → triggerBrowserDownload），只缺一个 helper

## Task 1: 后端 - ExcelConfig 加列 + WorkstationDeviceService 新方法 + ExcelService post-import hook

**Files**:
- `internal/services/operations/excel_config.go:142-151` (`WorkstationExcelConfig.Columns`)
- `internal/services/operations/workstation_device_service.go:17-77`（接口 + Request）+ 新增 `SetPrimaryAndSaveBySerial` 实现
- `internal/services/operations/excel_service.go:417-490`（ImportData 事务段）

**Action**:

1. **ExcelConfig 新增两列**

   在 `WorkstationExcelConfig.Columns` 末尾（`remark` 前）插入：
   - `{Field: "deptCode", Header: "部门代码", MaxLength: 100, Reference: "sys_dept.dept_code", DBField: "dept_id"}` — 优先按 `dept_code` 匹配 `sys_dept.id`，匹配失败回退到既有的 `deptName` 名称匹配（解析器层在导入时若两列都有值，以 deptCode 为准；若 deptCode 为空且 deptName 非空，按 deptName 走）
   - `{Field: "deviceSerial", Header: "主设备序列号", MaxLength: 200, DBField: ""}` — **无 DBField**，不写 sys_workstation，靠 post-import hook 跨表处理（参考 `[[xingran-excel-import-upsertkey-needs-dbfield]]` "无 DBField 字段 continue 跳过不写库"行为天然契合）

   保留现有 `deptName` / `userName` 不变，向后兼容。

2. **`SetPrimaryAndSaveBySerial` 新增接口方法**

   在 `WorkstationDeviceService` 接口（`workstation_device_service.go:17-65`）中 `SetPrimaryAndSave` 之后新增：

   ```
   SetPrimaryAndSaveBySerial(ctx context.Context, workstationID string, serial string, req *SetPrimaryAndSaveRequest) error
   ```

   实现要点：
   - **不复制合并逻辑**。抽出一个 unexported helper `mergeBySerial(ctx, workstationID, serial) (*models.WorkstationDevice, error)`，返回 AD/Asset 合并后的字段值（`DeviceName`, `DeviceModel`, `DeviceType`, `MACAddress`, `IPAddress`, `ResponsibleUser`, `AssetID`, `ADComputerID`）。
   - 重构现有 `SetPrimaryAndSave(ctx, deviceID, req)`：调用 `mergeBySerial`（`deviceID` 入参保留签名兼容，但内部忽略 — 记录 warn 提醒上游 deviceID 已废弃），其余事务内清理/取消主设备/写入 manual 记录逻辑保持不变。
   - 新增 `SetPrimaryAndSaveBySerial(ctx, workstationID, serial, req)`：调用 `mergeBySerial`，事务逻辑与现有保持一致，但**不需要 `deviceID` 入参**（req 内允许 `DeviceName/Model/Type/MAC/IP/ResponsibleUser` 为空，全部靠 AD/Asset 实时数据）。
   - `mergeBySerial` 返回 AD/Asset 拉取失败时仅 `logger.Warnf` 降级继续，不返回 error（与现有 `SetPrimaryAndSave:1106-1116` 行为一致）。

3. **ExcelService.ImportData post-import hook**

   在 `excel_service.go:484` cache invalidation 之前（即事务 commit 后）新增：

   ```
   if entityType == "workstation" {
       s.postImportWorkstationPrimaryDevice(ctx, validRecords, result)
   }
   ```

   实现 `postImportWorkstationPrimaryDevice(ctx, validRecords, *ImportResult)` 私有方法：
   - 遍历 `validRecords`，过滤出含 `deviceSerial`（非空 string）的行
   - 对每行：根据 `(floor_id, workstation_name)` 查 `sys_workstation.id`（用 `SELECT id FROM sys_workstation WHERE floor_id = ? AND workstation_name = ? AND deleted_at IS NULL LIMIT 1`）
   - 调 `WorkstationDeviceService.SetPrimaryAndSaveBySerial(ctx, workstationID, serial, &SetPrimaryAndSaveRequest{WorkstationID: workstationID, DeviceSerial: serial})` —— `DeviceName/Model/...` 全部靠合并逻辑自动填充
   - 失败时 `logger.Warnf` 记录，`result.Failed++`，追加 `ImportError{Row: <excel row index>, Error: err.Error()}` 到 `result.Errors`，**不阻断循环**（继续处理下一行）
   - 该方法走 service 层不写 operlog（约定：仅 HTTP handler 入口必记）

4. **依赖接线**

   - `ExcelService` 构造时需要 `WorkstationDeviceService` 依赖。检查 `excel_service.go` 中 `ExcelService` struct 和 `NewExcelService` 构造函数（参照已有 `pwdManager`, `cacheProvider`, `geocodingService` 模式），新增 `deviceService *WorkstationDeviceService` 字段；`getExcelService` in `excel_handler.go:52-` 构造时一并注入 `core.WorkstationDeviceService`（如果 core 还没暴露，就用 `opsServices.NewWorkstationDeviceService(core.DB.GetDB(), ...)` 自行 new）
   - 若 `WorkstationDeviceService` 接口与 `ExcelService` 之间形成 import cycle（operations 包内互引），把 post-import 逻辑下沉到 `internal/api/v1/operations/excel_handler.go` 的 `importData` handler 末尾更安全 —— 优先尝试 service 层方案，若 import cycle 则退化为 handler 层调用（决策点写在本 task 的"决策记录"段）

**Verify**:

- 启动后端，用现有工作站模板（在 ExcelConfig 自动生成的）下载后能看到新列"部门代码"和"主设备序列号"
- 跑一次最小回归：导入 3 行（1 行无 deviceSerial、1 行 deviceSerial 命中 AD、1 行 deviceSerial 命中 Asset），确认 `result.Inserted/Updated/Failed` 与 `result.Errors` 符合预期

**Done**:
- `WorkstationExcelConfig.Columns` 含 `deptCode` 与 `deviceSerial` 两列

## Task 2: 后端 - 部门映射表下载端点

**Files**:
- `internal/api/v1/operations/excel_handler.go:163-180`（参考 `downloadTemplate` handler 模式）+ 新增 `downloadDeptMappingTemplate` handler + 新增路由注册函数
- `internal/api/router.go:583-617`（workstations router 注册块）

**Action**:

1. **新增 handler**

   在 `excel_handler.go` 末尾新增 `downloadDeptMappingTemplate(core *core.Core) gin.HandlerFunc`：
   - 用 `excelize.NewFile()` 创建 xlsx
   - sheet 名 `部门映射`，表头 `dept_name` | `dept_code`
   - 查询 `SELECT dept_name, dept_code FROM sys_dept WHERE deleted_at IS NULL AND status = 0 ORDER BY dept_code`（按代码排序，方便用户检索）
   - 写入数据行
   - `c.Header("Content-Disposition", "attachment; filename=dept_mapping_<timestamp>.xlsx")` + `c.Data(http.StatusOK, ...)` 返回 blob
   - 记录 operlog：`operlog.Record(c, core.OperLogService, core.GetDB(), "部门管理", operlog.OperTypeDownload)`（独立于工位导入，与 `downloadTemplate` 模式一致）

2. **注册路由**

   在 `internal/api/router.go:583-617` 的 workstations block 内、`SetupExcelRouter(workstations, "workstation", core)` 之前一行注册：
   ```
   workstations.GET("/dept-mapping-template", operations.DownloadDeptMappingTemplate(core))
   ```

   在 `excel_handler.go` 暴露 `DownloadDeptMappingTemplate(core)` 导出函数（与 `SetupExcelRouter` 同样的导出风格），方便 router.go 直接调用。

3. **operlog 与权限**

   - 端点放在 `workstations` group 下，自动继承 `ops:workstation:*` 权限链（与 `/import`/`/export`/`/template` 一致）
   - 若未来要开放给其他模块用，可考虑移到独立的 dept router，但本次不重蹈 Excel 路由冲突（`[[xingran-excel-import-route-conflict]]`），保持独立端点

**Verify**:
- `go build ./...` 通过
- `curl -X GET http://localhost:9000/api/v1/ops/workstation/dept-mapping-template -H "Authorization: Bearer <token>"` 返回 200 + xlsx blob，文件可被 Excel/WPS 打开
- 文件第一行是表头 `dept_name | dept_code`，数据行数 = `sys_dept WHERE deleted_at IS NULL AND status = 0` 行数

**Done**:
- `GET /api/v1/ops/workstation/dept-mapping-template` 返回部门映射 xlsx
- 下载文件名含时间戳
- operlog 记录 1 条 Download 类型日志

## Out of Scope

明确**不做**的事，避免 scope creep：

1. **不改 `sys_workstation` 表结构**：`PrimaryDeviceSerial` 是虚拟字段（`gorm:"->;-:migration"`），deviceSerial 跨表写入走 `ops_workstation_device` 子表，不在工位表加列
2. **不改 `ExcelImport.tsx` props 接口**：所有改动都在调用方（workstations/index.tsx）
3. **不修改既有 `SetPrimaryAndSave` 签名**：通过 `mergeBySerial` helper 共用合并逻辑，签名/行为兼容
4. **不做前端新组件/新路由**：复用 `Button` + `deptApi.exportMapping()` 一行调用
5. **不写 DB trigger**：按 `[[user-prefers-code-fixes-no-db-triggers]]`，主设备同步逻辑全在 Go service 层 + BeforeCreate hook
6. **不重构既有 `deptName`/`userName` 逻辑**：保留按名称匹配作为 deptCode 缺失时的回退，向后兼容老模板
7. **operlog 只记映射表下载一次**：post-import 主设备同步是 service 层内部动作，不重复记 operlog
8. **不开放映射表端点给非工位模块**：本次仅工位导入使用，避免路由冲突
