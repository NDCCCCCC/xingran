# Quick Task 260626-n71: 工位选择所属人员后自动改成占用状态 — Summary

## 1. 任务概述

为 XingRan-Next 工位（sys_workstation）模块添加 `user_id` ↔ `status` 自动联动规则：

- 写入 `user_id`（所属人员）→ 自动联动 `status = 1`（占用）
- 清空 `user_id` → 自动联动 `status = 0`（空闲）
- `Maintain = 2`（维护）保留独立语义，**不受**人员分配影响
- Excel 导入路径：忽略 Excel 中填写的 `status` 列，**以 `user_id` 为准**
- 历史数据迁移：修复 `user_id IS NOT NULL AND status = 0` 的不一致工位
- 前端 EditModal：`userId` 改变时立即联动 `status`（UI 兜底）；后端 Service 为最终兜底

**约束遵守**:
- 不新增枚举值（`Available=0 / Occupied=1 / Maintain=2` 已存在）
- 不引入新 OperType（复用 `OperTypeUpdate`）
- 不破坏现有 Excel 导入流程
- 不引入缓存失效逻辑（sys_workstation 无缓存）
- 不破坏 Maintain 状态的语义

## 4. 与原计划的偏差

### 偏差 1：Excel 导入路径限定到 sys_workstation
- **原计划**：直接无条件覆盖 `status`
- **实际**：增加 `if config.TableName == "sys_workstation"` 守卫
- **原因**：`prepareRecordsForUpsert` 是公共入口，被多表复用（building、floor、workstation、infopoint 等）。其他表的 `status` 字段语义不同（如 building.status=0/1 表示启用/停用），不应被本任务的联动规则污染。守卫确保仅 workstation 表受影响。
- **影响**：无负面影响，反而提升安全性

### 偏差 2：单测覆盖 5 个场景而非 4 个
- **原计划**：4 个测试（with/empty/nil/preserve）
- **实际**：5 个测试（增加 `PreserveMaintainOnClear`）
- **原因**：发现用户清空 user_id 时（Maintain 状态下）也需要测试保护
- **影响**：测试覆盖更全面

### 偏差 3：PreserveMaintain 测试使用 sentinel 值
- **原计划**：`expected status=Maintain(2) preserved`
- **实际**：使用 sentinel 值 `99` 验证 helper 早 return（w.Status 维持原样）
- **原因**：helper 实现是 `if currentStatus == Maintain { return }`，**不会触碰** w.Status。所以测试不能用 `Maintain(2)` 断言（因为 w.Status 默认零值是 0，会失败）
- **影响**：测试逻辑更准确地反映 helper 行为

## 5. 关键设计实现说明

### helper 函数签名
```go
applyWorkstationOccupancyLink(w *models.Workstation, currentStatus models.WorkstationStatus)
```
- `w`：要写入的目标工位（Save 前修改 w.Status）
- `currentStatus`：当前 DB 中的 status，用于判断是否 Maintain

### Maintain 保留的实现
helper 通过 `currentStatus == Maintain` 时**早 return** 实现保护：
```go
if currentStatus == models.WorkstationStatusMaintain {
    return // 不修改 w.Status
}
```
调用方（Update）传入 `existing.Status`（DB 中读到的状态），保证 Maintain 工位不会被覆盖。

### 前端 + 后端双重兜底
- 前端：UI 体验一致性（用户改 userId 立即看到 status 变化）
- 后端：Service 层 helper 在 Save 前覆盖，前端被绕过无效

### Excel 导入 status 列处理
- Excel 模板仍保留 `status` 列（仅作展示）
- 实际写入由 `user_id` 决定（`preparedRecord["status"] = int(...)` 覆盖）
- 这样 Excel 用户填什么 status 都不影响数据一致性
