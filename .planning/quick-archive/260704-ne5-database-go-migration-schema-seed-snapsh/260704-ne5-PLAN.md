### Task 2: 写 snapshot.sh 脚本

**新文件**：`scripts/db/snapshot.sh`

**功能**：从运行中的 PostgreSQL 数据库导出 schema + seed snapshot。

**实现要点**：
1. 读取环境变量 `PGHOST` / `PGPORT` / `PGUSER` / `PGPASSWORD` / `PGDATABASE`（默认 `localhost:5432/xingran_next`，密码从 `.env` 读）
2. 输出目录：`docs/deployment/snapshots/`
3. 文件名：`schema-{YYYY-MM-DD}.sql` + `seed-{YYYY-MM-DD}.sql`
4. Schema dump：
   ```bash
   pg_dump --schema-only --no-owner --no-acl \
       -t 'sys_*' -t 'ops_*' \
       "$PGDATABASE" > "schema-${DATE}.sql"
   ```
5. Seed dump：
   ```bash
   pg_dump --data-only --inserts --no-owner --no-acl \
       -t sys_menu -t sys_role -t sys_role_menu -t sys_user \
       -t sys_config -t sys_dict_type -t sys_dict_data \
       -t sys_ad_service_accounts -t sys_post \
       "$PGDATABASE" > "seed-${DATE}.sql"
   ```
6. 脚本头部输出 README 注释（说明这是 dev tool，新部署流程）
7. 末尾打印两个文件的行数 + 大小

**验证**：
- `bash scripts/db/snapshot.sh --help` 输出用法
- 检查输出文件存在且非空

**完成标志**：脚本可独立运行，输出格式正确。

## 风险评估

| 风险 | 缓解 |
|------|------|
| 删错调用导致启动 panic | 保留 GORM AutoMigrate(model) + cleanupOldConstraints()；删的全是已 idempotent 的 migration |
| 删了某个 service 依赖的函数 | service 层不用 migration 函数，只用 db 连接；不影响 |
| snapshot.sh 在生产 DB 跑锁表 | `pg_dump` 用 `--no-owner --no-acl` 不锁；schema-only 本身就是只读事务 |
| 新部署流程变了没文档 | docs/deployment.md 由用户手动更新（不在本任务范围） |
