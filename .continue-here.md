### 3. Fix redundant MAC history writes (Plan B + redundant-write fix per user request)

- `467df3fc` — `RecordMACChange` 2-layer dedup:
  - **L1 (norm set)**: Replace `(mac, interface, vlan)` tuple comparison with normalized MAC set. Prevents collector-miss-1-cycle from producing disappeared + reappeared pair.
  - **L2 (history re-check)**: Before writing, query `sys_device_mac_history` for the most recent record of this MAC. If the interface matches the current one, skip the write (re-detection / brief miss).
  - Result: stable MAC 7 days → 1 event (first appeared) instead of 366. Real changes (move, VLAN change, true appearance/disappearance) still write 1 event each.
  - Known trade-off: A MAC that truly leaves the device for an extended period may miss its `disappeared` write (L2 re-check matches the last appeared on the same port). Future enhancement: add time threshold.
  - **7/7 regression tests pass** in `mac_history_record_change_test.go` (sqlite in-memory):
    - Same-port miss → 0 events
    - First appearance → 1 appeared
    - A→B port move → 1 moved (no appeared/disappeared)
    - MAC disappears → 1 disappeared
    - Same-port VLAN change → 1 vlan_changed
    - 7-day stable MAC (10% simulated miss) → 1 event total

## Anti-Patterns Discovered This Session

- **Reading only half a function** misled me into thinking `NormalizeMACAddress` returns no-separator format (it actually re-inserts colons at the end). Always read the WHOLE function before reasoning about its behavior.
- **Single-call subtests sharing a DB** — first test pass failed because records accumulated across subtests. Each subtest needs its own fresh DB (in-memory sqlite).
- **Default-fixed test expectations** — moved records use the NEW interface name (semantic "where it is now"), not the OLD one ("where it came from"). Counterintuitive but documented in test.
- **For trajectory-page consolidation**: The user's intent of "load more" (Plan B) overlapped with the deeper issue of "data is too much in the first place" — both fixes shipped together, but the bigger impact is the backend dedup (`RecordMACChange` 2-layer). UI load-more is now mostly defensive (since busy MACs become 1 event after the fix).
